**1.** (a) Convert the decimal number 203 into 8-bit binary. (1)

(b) Convert the binary number 1011 0110 into hexadecimal. (1)

(c) Convert the hexadecimal number 7E into decimal. Show your working. (2)

(d) Give one reason why hexadecimal is often used in computer science instead of binary. (1)

(5)
---
(a) 1100 1011 (1).

(b) B6 (1). 1011 is B and 0110 is 6.

(c) 7 × 16 = 112 and E = 14 (1); 112 + 14 = 126 (1). A correct answer with no working gets 2.

(d) Any one: it is shorter, so easier for people to read and remember; people make fewer mistakes copying it than long strings of 0s and 1s; each hex digit maps exactly onto four bits, so it converts to binary easily (1). Do not accept "it takes less memory" or "computers process it faster": computers still store binary.

::: q 4-5 3.3.5
**3.** In ASCII the character code for 'A' is 65.

(a) State the character code for 'G'. (1)

(b) Explain why Unicode was developed when ASCII already existed. (2)

(3)
---
(a) 71. The capital letters run in sequence, and G is six places after A (1).

(b) 7-bit ASCII has only 128 codes, which is enough for English letters, digits and symbols but not for other alphabets (1). Unicode uses more bits per character, so it can represent many more characters: the world's alphabets, plus symbols such as emoji (1). Accept "its first 128 codes match ASCII, so it is backwards compatible" as a creditworthy extra point.
:::

::: q 4-5 3.4.5a
**5.** (a) Describe the role of each of these CPU components: the arithmetic logic unit, the control unit and the clock. (3)

(b) The fetch-execute cycle has three stages. Describe the fetch stage and the decode stage. (2)

(5)
---
(a) ALU: carries out arithmetic calculations and logical operations such as comparisons (1). Control unit: decodes instructions and sends control signals to coordinate the other components and the flow of data (1). Clock: sends regular pulses that keep the components in step; each pulse lets an operation happen (1).

(b) Fetch: the next instruction is copied from main memory into the CPU (1). Decode: the control unit works out what the instruction is and what it needs to do (1).

**6.** (a) A bitmap image is 400 pixels wide and 300 pixels high, with a colour depth of 8 bits. Calculate its file size in kilobytes. Show your working. (3)

(b) The colour depth is increased to 24 bits. State the effect on the image and on its file size. (1)

**7.** The word NEEDLESS is compressed with Huffman coding using this tree. Each left branch is 0 and each right branch is 1.

```
        (8)
       /   \
     E(3)  (5)
          /   \
        S(2)  (3)
             /   \
           N(1)  (2)
                /   \
              L(1)  D(1)
```

(a) State the Huffman code for S. (1)

(b) Calculate the number of bits needed to store NEEDLESS using this Huffman code. Show your working. (2)

(c) Calculate the number of bits needed to store NEEDLESS in 7-bit ASCII, and the number of bits saved by the Huffman code. (2)

(d) One row of a black and white image is `1110000000110000`. Represent it using run length encoding as frequency/data pairs. (2)

(7)
---
(a) 10 (1).

(b) E = 0, S = 10, N = 110, L = 1110, D = 1111. E: 3 × 1 = 3; S: 2 × 2 = 4; N: 3; L: 4; D: 4 (1); total 18 bits (1).

(c) 8 × 7 = 56 bits (1); 56 − 18 = 38 bits saved (1). Follow through from an incorrect (b).

(d) 3 1 7 0 2 1 4 0. Three or four pairs correct (1); all correct, in order, with frequency before value (2).

- C is the input to a NOT gate.

::: q 6-7 3.4.4
**9.** (a) State one difference between machine code and assembly language. (1)

(b) Explain why most programs are written in high-level languages. (2)

(c) Give two differences between the way a compiler and an interpreter translate a high-level program. (2)

(5)
---
(a) Any one: machine code is binary, while assembly uses short mnemonics such as ADD; assembly must be translated by an assembler, while machine code runs directly (1).

(b) Any two: they use English-like keywords, so code is quicker to write, read and debug (1); one statement can do the work of many machine instructions (1); they are not tied to one processor, so programs are portable (1); they have built-in structures such as loops and subroutines (1). Max 2.

(c) Any two (2):

- A compiler translates the whole program before it runs; an interpreter translates and runs it one statement at a time.
- A compiler produces machine code, an executable file that runs without the compiler; an interpreter produces no machine code of its own, and is needed every time the program runs.
- A compiled program usually runs faster.
- A compiler reports errors after translating the whole program; an interpreter stops at the first error it reaches.
:::

::: q 6-7 3.4.5b
**10.** (a) Give two differences between RAM and ROM. (2)

(b) A student's new laptop has a solid state drive (SSD) rather than a magnetic hard disk. Give one advantage and one disadvantage of the SSD for this student. (2)

(c) Explain how an embedded system differs from a non-embedded system, using an example. (2)

(6)
---
(a) Any two: RAM is volatile and loses its contents when the power is off, while ROM is non-volatile (1); RAM can be read and written, while ROM can normally only be read (1); RAM holds the programs and data currently in use, while ROM holds the start-up (boot) instructions (1). Max 2.

(b) Advantage, any one: no moving parts, so it is more robust if the laptop is dropped; faster access; uses less power, so the battery lasts longer; lighter and silent (1). Disadvantage, any one: higher cost per gigabyte, so less capacity for the same price; a limited number of write cycles (1).

(c) An embedded system is a computer built into a larger device to do one dedicated task, while a general-purpose computer can run many different programs (1). Example: the controller in a washing machine, microwave or car engine management system, contrasted with a laptop or PC (1).
:::

**13.** A gym uses a relational database with two tables.

`Member`

| MemberID | FirstName | LastName | Town |
|---|---|---|---|
| M01 | Priya | Shah | Leeds |
| M02 | Tom | Hughes | York |
| M03 | Ola | Nowak | Leeds |

`Booking`

| BookingID | MemberID | ClassName | Fee |
|---|---|---|---|
| B101 | M01 | Spin | 6.50 |
| B102 | M03 | Yoga | 5.00 |
| B103 | M01 | Yoga | 5.00 |
| B104 | M02 | Boxing | 7.00 |

(a) State the field that is a foreign key in the `Booking` table. (1)

(b) Write an SQL query that lists every booking made by a member who lives in Leeds. It must return only the member's last name, the class name and the fee, in descending order of fee. (6)

(c) The fee for every Yoga booking rises to 5.50. Write an SQL statement that makes this change. (2)

(9)

(b) Example:

```
SELECT Member.LastName, Booking.ClassName, Booking.Fee
FROM Member, Booking
WHERE Member.MemberID = Booking.MemberID
AND Member.Town = 'Leeds'

```

::: q 8-9 3.6.2 3.6.2.1 3.6.3 3.5a
**14.** A small accountancy firm keeps its clients' financial records on its own network. Staff work from the office and from home on company laptops. The firm has been warned that it is a likely target for criminals.

Discuss the threats the firm faces from:

- social engineering;
- weak and default passwords;
- removable media.

In your answer, explain how each threat could be exploited and how the firm could protect itself. (9)
---
Levels of response.

- **Level 3 (7–9):** All three threats discussed, each with how it could be exploited and at least one relevant, explained protection. The answer applies them to an accountancy firm with home workers, and shows how measures work together. Detailed and well organised.
- **Level 2 (4–6):** At least two threats discussed, with some exploitation and protection explained, or three covered more briefly. Some links to the context. Mostly accurate.
- **Level 1 (1–3):** One or more threats or protections stated or described, with little explanation or context.
- **0:** Nothing creditworthy.

Indicative content:

- **Social engineering.** Phishing emails pretending to come from HMRC or a client could trick staff into revealing logins or opening malicious attachments. Blagging: a caller poses as IT support or a client to get passwords or account details. Shouldering at home or on a train as staff type passwords. Protection: staff training to spot phishing; a policy never to give out passwords by phone; checking callers' identity; email confirmation to verify identities; privacy screens on laptops.
- **Weak and default passwords.** Easily guessed or default router and admin passwords let attackers log in, or brute-force them. Protection: a password system that enforces length and complexity, lockouts after failed attempts, and changing default passwords; biometrics on laptops; CAPTCHA on online client portals to stop automated guessing.
- **Removable media.** USB sticks can carry malware onto the network, or be lost with unencrypted client data on them. Protection: disable USB ports or restrict which devices are allowed; scan removable media with anti-malware; encrypt data; keep automatic software updates on so known vulnerabilities are patched.
- **Combined measures.** A firewall and MAC address filtering control what can reach the office network, and penetration testing finds weaknesses before criminals do. Laws on protecting personal data make a breach serious for a firm holding clients' financial records.
:::

::: q 8-9 3.8
**15.** A city council plans to introduce self-driving (autonomous) delivery vehicles on its roads. The vehicles use cameras and sensors and share their location over mobile networks.

Discuss the ethical, legal and environmental impacts of this plan, including issues of privacy. (9)
---
Levels of response.

- **Level 3 (7–9):** A well-developed, balanced discussion covering ethical, legal and environmental impacts, with privacy addressed. The points are applied to autonomous delivery vehicles in a city, and both benefits and risks are weighed.
- **Level 2 (4–6):** Covers at least two of the areas with some explanation, or all three superficially. Some application to the scenario; may be one-sided.
- **Level 1 (1–3):** A few relevant points, mostly stated rather than explained. Little application.
- **0:** Nothing creditworthy.

Indicative content:

- **Ethical.** Fewer accidents caused by human error, tiredness or distraction, but the vehicle must be programmed to choose in an unavoidable crash, and someone decides those priorities. Delivery drivers lose jobs, though new jobs appear in maintenance and monitoring. Questions of trust and fairness, for example whether the sensors work equally well for all pedestrians.
- **Legal.** Who is responsible after a crash: the manufacturer, the software developer, the council or the operator? Laws and insurance written for human drivers need updating. A hacked vehicle raises questions of unauthorised access and of whether the firm took reasonable security steps.
- **Environmental.** Electric vehicles with efficient routing may cut emissions and congestion. But manufacturing, batteries and the data centres processing the data use energy and raw materials, and the vehicles become e-waste when replaced.
- **Privacy.** Cameras record pedestrians and number plates, and location data shows customers' addresses and routines. Who stores it, for how long, and who can see it? Citizens may object to constant recording, while police and security services may argue access to the footage keeps people safe.
- **Cyber security.** Vehicles connected over mobile networks could be hacked and taken over or stopped. They need encryption, authentication and automatic software updates.
:::
