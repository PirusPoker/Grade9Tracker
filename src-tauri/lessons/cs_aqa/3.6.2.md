## What it is

A **cyber security threat** is anything that could exploit a weakness to gain unauthorised access to a system, or to damage it or its data. The spec lists seven threats. Two of them have their own lessons, and this lesson covers the other five plus **penetration testing**.

For every threat, learn three things: **what it is**, **how an attacker exploits it**, and **how to protect against it**. Questions often ask for all three.

### Pharming

**Pharming** is a cyber attack that **redirects a website's traffic to a fake website**. The user types the correct address, or clicks a genuine bookmark, but ends up on a copy of the site built by the attacker. Anything they enter there, such as a username, password or card number, goes to the attacker.

How the redirection happens (at GCSE level):
- **malware on the user's computer** changes the settings that turn a web address into an IP address, so the computer goes to the attacker's server instead of the real one;
- or the attacker tampers with a **DNS server** (3.5b), so that everyone using that server is sent to the wrong IP address for the site.

**Why it is dangerous:** the user did nothing obviously wrong. There is no suspicious email or link to spot, and the address bar can show the right name.

**Protection:**
- **anti-malware software** to detect and remove malware that changes the redirection settings;
- checking for **HTTPS** and a valid security certificate before entering details (a fake site often cannot show a valid certificate for the real domain);
- organisations using **secure, trusted DNS servers** and keeping them patched;
- users being suspicious of a familiar site that looks slightly different or asks for unusual information.

**Pharming vs phishing.** **Phishing** (3.6.2.1) uses a **fake message**, such as an email or text, to trick the user into clicking a link or giving information. **Pharming** **redirects** traffic for the real address to a fake site, so no message is needed. Mixing them up is the most common error on this topic.

### Weak and default passwords

A **weak password** is easy to guess or crack: short, a dictionary word, a name or date of birth, a common sequence like `123456`, or a password reused across many sites.

A **default password** is the one a device or account is set up with by the manufacturer, such as on a router, a webcam or an admin account. These are often printed in manuals or listed online, so if they are never changed, an attacker can simply look them up.

**How they are exploited:**
- **guessing** using personal information found on social media;
- **brute force**: an automated program tries huge numbers of combinations very quickly; short passwords fall fastest;
- trying a **list of common passwords** against many accounts;
- using passwords stolen from one site to log in to others, which works when people reuse passwords;
- logging in to devices still using their **default** credentials.

**Protection:** password systems that **enforce rules** (minimum length, a mix of character types, not a common password); **forcing a change** of default passwords at set-up; **locking an account** after several failed attempts; **two-factor authentication**; **biometrics** (3.6.3).

### Misconfigured access rights

**Access rights** (permissions) control **which users can read, change or delete which files, folders and programs**. They are **misconfigured** when they are set wrongly, usually giving users more access than they need.

Examples:
- every member of staff can open the payroll folder;
- pupils can reach a shared drive containing exam papers;
- a former employee's account was never removed;
- an ordinary account has administrator rights, so malware running under it can change the whole system.

**How they are exploited:** an attacker who gets into **any** account, perhaps through phishing, can reach far more data than that account should allow. A malicious insider can see or change data they have no reason to touch. Mistakes by ordinary users can delete or change important data.

**Protection:** give each user **only the access they need for their job** (often called the principle of least privilege); set rights by **role or group**; **review** rights regularly; **remove accounts** when people leave; keep **administrator** accounts few and separate.

### Removable media

**Removable media** are storage devices that can be plugged in and taken away: **USB flash drives**, external hard drives, memory cards.

**How they are a threat:**
- **bringing malware in**: an infected USB stick is plugged in and malware copies itself onto the computer and possibly the network. Attackers have been known to leave infected sticks lying around, relying on curiosity;
- **taking data out**: an employee can copy large amounts of data onto a small device and walk out with it;
- **loss or theft**: a stick holding unencrypted personal data is left on a train.

**Protection:** **disable or block USB ports** or allow only approved devices; **automatically scan** removable media with anti-malware; **encrypt** any data that must be carried on removable media; staff training and policies (never plug in an unknown device).

### Unpatched and/or outdated software

All large programs contain bugs, and some bugs are **security vulnerabilities**. When the developer finds one, it releases a **patch** (an update that fixes it).

- **Unpatched software** has a fix available that has not been installed.
- **Outdated software** is no longer supported, so the developer has **stopped producing patches** at all, and any new vulnerabilities stay open for ever.

**How it is exploited:** once a patch is released, the vulnerability is public knowledge, so attackers write tools to exploit it and scan the Internet for systems that have not installed the fix. Malware can then get in without the user doing anything.

**Protection:** **automatic software updates** (3.6.3) so patches are installed promptly; replacing software and operating systems that are no longer supported; keeping a record of all software in use.

### Penetration testing

**Penetration testing** is when an organisation **authorises** a person or team to **try to gain access to its systems** using the methods an attacker would use, without being given the normal means of access such as usernames and passwords. The aim is to **find weaknesses before real attackers do**, so they can be fixed. The testers report what they found; they do not cause real damage.

It is legal because it is done with the **owner's permission**. The same actions without permission would be unauthorised access.

The spec names two types:

| | **Insider (malicious insider) test** | **External attack test** |
|---|---|---|
| **Tester knows** | **some knowledge** of the system and possibly **basic credentials**, like an ordinary employee | **no credentials** and no inside knowledge |
| **Simulates** | an attack from **inside**: a dishonest or disgruntled employee, or an attacker who has stolen a staff login | an attack from **outside**: a hacker on the Internet |
| **Finds** | how far a user can get **beyond their permitted access**, e.g. misconfigured access rights | weaknesses visible from outside, e.g. unpatched servers, weak passwords on public logins, open ports |

**What penetration testing is used for:** identifying vulnerabilities; checking that existing security measures (firewall, access rights, passwords) actually work; testing staff responses, for example with a fake phishing email; and giving the organisation a list of fixes in priority order.

**Limits:** a test only shows weaknesses at that moment; new software or new attacks may create new ones, so tests should be repeated.

::: terms
- **Pharming**: a cyber attack that redirects a website's traffic to a fake website, so users who enter the correct address reach the attacker's copy.
- **Weak password**: a password that is easy to guess or crack, such as a short word, a name or a common sequence.
- **Default password**: the password a device or account is given by its manufacturer, which is often publicly known if not changed.
- **Brute force attack**: using a program to try very large numbers of possible passwords until the right one is found.
- **Access rights**: permissions that control which users can read, change or delete particular files, folders and programs.
- **Misconfigured access rights**: permissions set wrongly so that users can reach data or functions they should not.
- **Removable media**: storage devices that can be plugged in and taken away, such as USB flash drives and memory cards.
- **Patch**: an update released by a developer to fix a bug or security vulnerability in software.
- **Outdated software**: software no longer supported by its developer, so security patches are no longer produced for it.
- **Penetration testing**: authorised attempts to gain access to a system without the normal means of access, to find weaknesses before attackers do.
:::

::: method
1. **Describe the threat** in one precise sentence (use the definitions above).
2. **Explain how it is exploited**: what the attacker does and what they gain.
3. **Give the protection** and explain **how** it reduces that particular threat.
4. **Pharming vs phishing**: pharming **redirects traffic** to a fake site; phishing uses a **fake message**.
5. **Penetration testing**: authorised, tries to gain access without normal credentials, finds weaknesses to fix. For the types, state **what the tester knows** and **what attack it simulates**.
6. **9-mark Discuss**: for each bullet, pair threats with protections, apply to the scenario, weigh up, conclude.
:::

::: example Pharming
Describe what is meant by pharming. (2)

A cyber attack that redirects traffic intended for a genuine website (1) to a fake website, where the user's login or payment details can be captured by the attacker (1).
:::

::: example Default passwords
A family has just installed a new wireless router. Explain why they should change its default password. (2)

Default passwords for a model of router are often published in manuals or online (1), so anyone could look it up and log in to the router to change its settings or access the network (1).
:::

::: example Access rights
Explain how misconfigured access rights could lead to a data breach in a company. (2)

If staff have more access than they need, e.g. everyone can open the HR folder (1), then an attacker who compromises any one account, or a dishonest employee, can read or steal confidential data they should never have reached (1).
:::

::: example Unpatched software
Explain why using an operating system that is no longer supported is a security risk. (2)

The developer no longer releases patches (1), so newly discovered vulnerabilities are never fixed and attackers can exploit them to get into the computer (1).
:::

::: example Two types of penetration test
Describe the two types of penetration testing. (4)

In one type, the tester has knowledge of the system and possibly basic login credentials (1); this simulates an attack by a malicious insider, such as a dishonest employee (1).

In the other type, the tester has no credentials or knowledge of the system (1); this simulates an external attack by a hacker from outside the organisation (1).
:::

::: q
State what is meant by a default password. (1)
---
The password set by the manufacturer/supplier when a device or account is first made, which the user has not changed (1).
:::

::: q
Give two features of a password system that make weak passwords less of a threat. (2)
---
Any two of: minimum length; requiring a mix of upper case, lower case, digits and symbols; rejecting common/dictionary passwords; locking the account after several failed attempts; forcing default passwords to be changed; two-factor authentication (1 each).
:::

::: q
Explain two ways that removable media can be a threat to an organisation. (4)
---
Malware on an infected USB stick (1) can be copied onto the computer and spread across the network when it is plugged in (1). An employee can copy large amounts of confidential data onto a small device (1) and take it out of the building / lose it, causing a data breach (1).
:::

::: q
Explain the difference between pharming and phishing. (2)
---
Phishing uses fake messages such as emails or texts to trick a user into giving information or clicking a link (1), whereas pharming redirects the traffic for a genuine website address to a fake site, so the user is fooled even when entering the correct address (1).
:::

::: q
Explain what penetration testing is used for. (2)
---
To find weaknesses/vulnerabilities in a system by attempting to gain access as an attacker would (1), so that they can be fixed before a real attacker exploits them (1).
:::

::: q
Explain why a penetration test that simulates a malicious insider would be given basic credentials. (2)
---
An insider such as an employee already has a login and some knowledge of the system (1), so the test checks how far someone with ordinary access could get beyond their permitted rights, e.g. exposing misconfigured access rights (1).
:::

::: watch
- **Pharming** redirects **traffic** to a fake **website**. Do not describe it as an email; that is phishing.
- Default passwords are a threat because they are **publicly known**, not just because they are "weak".
- **Unpatched** = a fix exists but has not been installed. **Outdated** = no fixes are made any more.
- Removable media is a threat in **both directions**: malware in, data out.
- Misconfigured access rights usually means **too much** access. Explain what an attacker or insider could then reach.
- Penetration testing is **authorised**, and its purpose is to **find and fix** weaknesses. "Hacking a system" alone does not earn the mark.
- For the two test types, give **what the tester knows** and **who they simulate**.
:::

::: test
A school gives every member of staff administrator rights on their laptop so that they can install software. Explain why this is a security risk. (3)
---
Administrator rights give more access than staff need for their jobs, so the rights are misconfigured (1). Malware run by a member of staff, e.g. from an email, would also run with administrator rights and could change system settings/spread (1). An attacker who obtains one staff login would have full control of that laptop and possibly access to more of the network (1).
:::

::: test
Explain why default passwords are a particular risk for devices connected to the Internet, such as webcams and routers. (2)
---
The default passwords for each model are published/easy to find (1), and attackers can scan the Internet for such devices and log in automatically, taking control of them or spying through them (1).
:::

---

Level 2 (4–6): at least two threats explained with some protections; some application.
Level 1 (1–3): some threats or protections named with little explanation; may cover only one bullet.
