## What it is

This topic covers five measures for **detecting and preventing** cyber security threats. For each one you need to know **how it works**, **which threat it reduces**, and its **advantages and limitations**.

| Measure | Main threats it reduces |
|---|---|
| **Biometric measures** | weak passwords, shouldering, stolen or guessed passwords, a lost or stolen phone |
| **Password systems** | weak and default passwords, brute force guessing |
| **CAPTCHA** | automated attacks by bots: mass fake accounts, automated password guessing, spam |
| **Email confirmations** | fake accounts, people signing up or resetting passwords with someone else's email address |
| **Automatic software updates** | unpatched and outdated software; malware that exploits known vulnerabilities |

### Biometric measures

**Biometrics** identify a person by a **unique physical (or behavioural) characteristic**: **fingerprint**, **face**, **iris** or retina, **voice**, or even typing pattern.

**How it works:** when set up, the device scans the characteristic and stores a **template** of its key features. At login, a new scan is compared with the template; if they match closely enough, access is granted.

**Mobile devices** are the spec's focus. Most smartphones have a **fingerprint sensor** or **facial recognition** built in. These are used to unlock the phone and to approve payments and banking app logins.

**Why biometrics suit mobile devices:**
- phones are unlocked many times a day, and biometrics are **fast and convenient**, so users are less tempted to use a weak PIN or no lock at all;
- phones are easily **lost or stolen**, and a biometric lock stops a thief using the phone or its apps;
- in public places a PIN can be watched (**shouldering**); a fingerprint cannot be "seen";
- a biometric **cannot be forgotten**, guessed or **shared** like a password, and is hard to steal by phishing.

**Limitations:**
- **false rejections** (the right person is refused, e.g. wet or cut fingers, poor lighting) and, more seriously, **false acceptances** (someone similar is let in);
- some systems can be **fooled**, e.g. basic face recognition by a photograph;
- a biometric **cannot be changed** if the stored data is ever stolen, unlike a password;
- **privacy**: biometric data is highly personal, so how and where it is stored matters (on modern phones it is normally kept on the device);
- needs suitable hardware, so costs more to add;
- devices keep a **PIN or password as a backup**, so that becomes the weak point if it is poor.

### Password systems

A **password system** is the set of rules and features that control how passwords are created, used and stored. A good system makes weak passwords **impossible to choose** and guessing **impractical**.

Features of a strong password system:
- **minimum length**: every extra character multiplies the number of possible passwords, so brute force takes far longer;
- **complexity rules**: a mix of upper case, lower case, digits and symbols;
- **rejecting common passwords** and dictionary words, and the user's own name;
- **forcing default passwords to be changed** on first use;
- **limiting failed attempts**: locking the account or adding a delay after a few wrong tries, which stops automated guessing;
- **masking** the password on screen (dots), which reduces shouldering;
- **not reusing** recent passwords;
- **two-factor authentication**: a second check, such as a code sent to the user's phone or a biometric, so a stolen password is not enough on its own;
- storing passwords securely (in scrambled form) so a stolen database doesn't reveal them directly.

**Limitations:** very strict rules can lead users to **write passwords down** or reuse them; passwords can still be phished, blagged or watched.

### CAPTCHA

A **CAPTCHA** is a test that is **easy for a human but difficult for a computer program** to pass, used to check that a **real person**, not an automated **bot**, is using a website. Examples include typing distorted letters, picking the images that contain a particular object, or simply ticking a box while the site analyses how the mouse moves.

**What it prevents:** **automated** attacks, where a program can make thousands of attempts a minute:
- **brute force** password guessing on a login page;
- creating **large numbers of fake accounts**;
- posting **spam** in comments and forms;
- bots buying up limited tickets or stock.

**What it does not prevent:** a **person** logging in with a stolen password, phishing, or malware. CAPTCHA stops **bots**, not human attackers.

**Limitations:** can be **annoying** and slow for users; some are hard for people with visual impairments (audio alternatives are often offered); advanced software can solve some types.

### Email confirmations to confirm identity

The website **sends an email to the address the user has given**, containing a **link or a code**. The user must click the link or enter the code to complete an action. Only someone with access to that **email inbox** can do it.

Uses:
- **confirming a new account**: proves the email address is real and belongs to the person signing up, which stops people registering with someone else's address and makes **fake accounts** harder;
- **resetting a forgotten password**: the reset link goes to the registered email, so a stranger cannot reset it;
- **confirming important actions**, such as a change of address, a new device logging in, or a large order; the user is alerted if it wasn't them.

**Limitations:** relies on the **email account itself being secure**: if an attacker controls the email, they can confirm anything; confirmation emails can be **imitated** in phishing; it adds a step for users.

### Automatic software updates

Developers release **updates (patches)** that fix bugs and close **security vulnerabilities**. With **automatic updates**, the operating system and apps **download and install these without the user having to remember or act**.

**Why it is a security measure:**
- once a vulnerability is publicly known, attackers target systems that have not been patched; automatic updates **shorten the time** a device is exposed;
- many users ignore update reminders, so leaving it to them leaves devices **unpatched**;
- anti-malware updates also add **new malware signatures**, so new threats can be detected;
- in an organisation, updates can be pushed to every computer at once, so none are missed.

**Limitations:** an update can occasionally cause a **compatibility problem** or a fault; installing may need a **restart** at an inconvenient time; it uses data and storage; it does nothing for software that is **no longer supported** (no updates are produced).

### Matching measures to threats

Exam questions often give a threat and ask for a suitable measure, or ask which threat a measure protects against. Use the table at the top. Remember the network security methods from 3.5 (firewall, encryption, MAC address filtering) are also valid measures where relevant.

::: terms
- **Biometrics**: identifying a person by a unique physical or behavioural characteristic, such as a fingerprint, face or iris.
- **Biometric template**: the stored record of the key features of a person's biometric, compared with each new scan.
- **False rejection**: when a biometric system wrongly refuses access to the genuine authorised user.
- **False acceptance**: when a biometric system wrongly allows access to someone who is not the authorised user.
- **Password system**: the rules and features controlling how passwords are created, used and checked, such as length rules and lockouts.
- **Account lockout**: blocking further login attempts after a set number of wrong passwords, to stop automated guessing.
- **CAPTCHA**: a test that is easy for a human but hard for a computer program, used to stop automated bots using a website.
- **Bot**: a program that carries out automated tasks, such as repeated login attempts, much faster than a person.
- **Email confirmation**: a link or code sent to a user's email address that must be used to complete an action, proving access to that inbox.
- **Automatic software update**: patches downloaded and installed by the system without the user having to act, closing vulnerabilities quickly.
:::

::: method
1. **Name the measure** and explain **how it works** in one or two steps.
2. **Name the threat** it reduces, and explain **why** it reduces that threat (e.g. CAPTCHA stops **bots**, so automated guessing fails).
3. For **advantages/disadvantages** questions, give two-sided points, each with a reason.
4. For **biometrics**, link to **mobile devices**: lost/stolen phones, shouldering, convenience, can't be forgotten or shared.
5. For **password systems**, give **specific rules** (minimum length, mix of characters, lockout), not "make it strong".
6. **9-mark Discuss**: cover every bullet, match measures to threats, weigh security against convenience, and reach a judgement.
:::

::: example CAPTCHA
Explain the purpose of a CAPTCHA on a website's login page. (2)

It checks that the user is a human rather than an automated program/bot (1), which stops bots making thousands of automated password guesses (brute force) against accounts (1).
:::

::: example Biometrics on a phone
Explain two advantages of using fingerprint recognition rather than a PIN to unlock a mobile phone. (4)

A fingerprint cannot be watched over the user's shoulder in a public place (1), unlike a PIN typed on screen, so shouldering is not possible (1).

It is quick and convenient (1), so users are more likely to keep the phone locked rather than choosing a weak PIN or no lock (1).
:::

::: example Email confirmation
Explain how an email confirmation helps confirm a user's identity when they create an account. (2)

The website sends a link or code to the email address the user entered (1); the account is only activated when it is used, proving the person has access to that inbox and hasn't used someone else's address (1).
:::

::: example Automatic updates
Explain why automatic software updates help protect a computer from malware. (2)

Updates include patches that close known security vulnerabilities (1); installing them automatically means the computer is protected quickly, rather than staying exposed if the user ignores update messages (1).
:::

::: example Password rules
Describe two rules a password system could enforce to make passwords harder to crack. (2)

A minimum length, e.g. at least 12 characters (1). It must include a mixture of upper case, lower case, digits and symbols (1).
:::

---

:::

::: watch
- **CAPTCHA** stops **bots / automated programs**, not "hackers" in general. Say "automated".
- For **biometrics**, explain **why it suits mobile devices**: lost or stolen, used in public, unlocked often.
- Password systems: give **specific rules**. "Use a strong password" earns nothing.
- **Email confirmation** works because only the owner can access the **inbox**; it is only as secure as that email account.
- **Automatic** updates matter because users **forget or ignore** updates. Say what the update **fixes** (security vulnerabilities).
- Don't claim any measure makes a system completely secure. Mention limitations where the question asks for evaluation.
:::

::: test
A bank is launching a mobile banking app that lets customers check balances, make payments and change their details.
Discuss how the bank could keep customers' accounts secure. In your answer you should discuss:
- how customers should prove their identity when they use the app;
- how the bank could protect against automated attacks and fake or hijacked accounts;
- how the app and phone software should be kept secure, and any drawbacks of these measures for customers. (9)
---
Level 3 (7–9): detailed discussion of all three bullets; measures are explained, matched to specific threats and applied to a mobile banking app; drawbacks weighed against benefits; a reasoned conclusion.
Level 2 (4–6): relevant measures explained for at least two bullets, with some application; some drawbacks.
Level 1 (1–3): measures named with little explanation or application.
0: nothing worthy of credit.
Indicative content:
- Proving identity: biometric login (fingerprint/face) is fast and suits frequent use on a phone; protects against shouldering in public and if the phone is lost/stolen; cannot be forgotten or shared; a password/PIN system as backup with rules on length, rejection of common choices, lockout after failed attempts; two-factor authentication for payments or new devices.
- Automated and fake/hijacked accounts: CAPTCHA on registration and web login stops bots creating accounts or brute forcing passwords; account lockout; email confirmation when registering, resetting a password, adding a new payee or changing details proves access to the registered inbox and alerts the real customer.
- Keeping software secure: automatic updates for the app and the phone's operating system patch vulnerabilities quickly; the bank could refuse to run on outdated, unsupported operating systems; encryption of data sent between app and bank.
- Drawbacks: biometric false rejections and privacy concerns; CAPTCHA is annoying and can be hard for some users; strict password rules lead to written-down passwords; email confirmation depends on the email account's security; updates may need restarts or cause problems; extra steps may frustrate customers.
- Judgement: e.g. layered measures are needed because each covers different threats; biometrics plus two-factor checks for payments balance convenience and security.
:::
