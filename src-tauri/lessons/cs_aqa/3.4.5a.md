## What it is

The **central processing unit (CPU)**, or processor, is the part of a computer that **carries out the instructions of programs**. It does not hold whole programs itself: programs and their data sit in **main memory**, and the CPU continually fetches instructions from there and executes them.

### The components and their roles

| Component | Role |
|---|---|
| **Main memory** | Holds the **instructions and data of programs currently running**. It is **directly accessible** by the CPU: the CPU fetches each instruction from main memory, and may **read data from** or **write results to** main memory while executing it. (Main memory is mostly RAM; see 3.4.5b.) |
| **Arithmetic logic unit (ALU)** | Carries out **arithmetic** operations (such as addition and subtraction) and **logical** operations (such as AND, OR and NOT, and comparisons like "is A greater than B?"). It is where calculations and decisions actually happen. |
| **Control unit (CU)** | **Decodes** each instruction and sends out **control signals** that coordinate the rest of the computer: telling the ALU which operation to do, telling memory whether to read or write, and directing the flow of data between components. It manages the fetch-execute cycle. |
| **Clock** | Sends out a steady stream of **electrical pulses** that keep every component **synchronised**. Each step of the processor's work happens in time with the clock's ticks. |
| **Registers** | Very **small, very fast** memory locations **inside** the CPU. They hold the instruction being processed, addresses, and the data and results the CPU is working on right now. (You do not need to know the names of specific registers.) |
| **Bus** | A **collection of wires** through which **data and signals** are transmitted from one component to another, for example between the CPU and main memory. Separate groups of wires carry data, memory addresses and control signals. |

### The fetch-execute cycle

From the moment it is switched on, the CPU repeats the same cycle billions of times per second: it **reads instructions stored in main memory and executes them**.

| Stage | What happens |
|---|---|
| **Fetch** | The **next instruction** is copied from **main memory** into the CPU, travelling along the bus. The CPU keeps track of the address of the next instruction, and moves that on so that it is ready for the following cycle. |
| **Decode** | The **control unit** works out **what the instruction is**: what operation is needed and what data it uses. |
| **Execute** | The instruction is **carried out**. This might use the **ALU** for a calculation or comparison, move data between registers, or **read data from or write data to main memory**. |

Then the cycle **repeats** with the next instruction. A useful picture: fetch is reading the next line of a recipe, decode is understanding it, execute is doing it.

**Main memory's role in the cycle**: it supplies the instruction in the **fetch** stage, and during the **execute** stage it may supply data (for example, load a value) or receive a result (for example, store a total).

### What affects CPU performance

**Performance** means how many instructions the CPU can process in a given time. The spec names three factors.

**Clock speed.** The number of clock cycles per second, measured in **hertz**; a 3.5 GHz clock ticks 3.5 billion times a second. A **higher clock speed** means the fetch-execute cycle is carried out **more times per second**, so **more instructions are processed per second**. Limits: faster clocks use more power and produce more **heat**, which must be removed, so speeds cannot be raised indefinitely.

**Number of processor cores.** A **core** is a complete processing unit able to fetch, decode and execute instructions **on its own**. A quad-core CPU can, in principle, process four instructions at the same moment.
- More cores help when **several programs** run at once, or when a program is **written to split its work** into parts that can run in parallel (video encoding, 3D rendering, many games).
- More cores do **not** always help: if a task is a single sequence of steps where each step depends on the one before, it can only use **one core**. The cores also have to **coordinate** and share data, which takes time. So **doubling the cores does not double the speed**.

**Cache size.** **Cache** is a small amount of **very fast memory on or very near the CPU**, holding **copies of frequently used instructions and data** taken from main memory. Reading from cache is much **faster** than reading from main memory.
- With a **larger cache**, more of the instructions and data the CPU needs can be kept close by, so the CPU has to wait for slower main memory **less often**.
- Benefits depend on the program: if the data it uses is already in cache, extra cache adds little. Cache is also expensive, which is why it is small.

Real performance depends on **all three together**, plus the software. A CPU with a slightly lower clock speed but more cores and more cache may well be faster for a heavily multi-threaded task such as video editing.

::: terms
- **Central processing unit (CPU)**: the component that processes data by fetching, decoding and executing program instructions.
- **Main memory**: memory directly accessible by the CPU that holds the instructions and data of programs currently running.
- **Arithmetic logic unit (ALU)**: the part of the CPU that carries out arithmetic and logical operations, including comparisons.
- **Control unit**: the part of the CPU that decodes instructions and sends control signals to coordinate the other components.
- **Clock**: a component that generates regular electrical pulses to synchronise the operation of the CPU.
- **Register**: a very small, very fast storage location inside the CPU holding data or instructions currently being used.
- **Bus**: a collection of wires through which data and signals are transmitted from one component to another.
- **Fetch-execute cycle**: the continuous process in which the CPU fetches an instruction from main memory, decodes it and executes it.
- **Clock speed**: the number of clock cycles per second, measured in hertz (e.g. 3.5 GHz).
- **Core**: an independent processing unit within a CPU that can fetch, decode and execute instructions by itself.
- **Cache**: a small amount of very fast memory on or near the CPU that holds frequently used instructions and data.
:::

::: method
1. **Component roles**: name the component **and** say what it does (e.g. "the ALU performs calculations and comparisons"). One clear sentence per mark.
2. **Fetch-execute**: three stages in order. Say **where from** (main memory), **who decodes** (control unit) and **what execute may involve** (ALU, reading/writing main memory).
3. **Performance factors**: say what the factor is, then the **effect** ("so more instructions are processed per second").
4. **Cores**: always add the caveat that the software must be able to **split the work**.
5. **Cache**: link larger cache to **fewer slow accesses to main memory**.
6. **9-mark discuss**: cover every bullet, apply to the scenario (the user's software), and finish with a justified judgement.
:::

::: example Role of the ALU and CU
Describe the roles of the arithmetic logic unit and the control unit. (3)

The ALU carries out arithmetic operations, such as addition (1), and logical operations/comparisons, such as checking whether one value is greater than another (1).

The control unit decodes instructions and sends control signals to coordinate the other components, such as the ALU and memory (1).
:::

::: example Fetch-execute cycle
Describe what happens during the fetch and decode stages of the fetch-execute cycle. (3)

Fetch: the next instruction is copied from main memory into the CPU (1), travelling along the bus (1).

Decode: the control unit works out what the instruction is / what it needs to do (1).
:::

::: example Main memory during execute
Explain the role of main memory in the execute stage. (2)

An instruction may need data that is stored in main memory, so it is read from memory into the CPU (1), or it may produce a result that is written back to main memory, for example to store a variable's new value (1).
:::

::: example Clock speed
A CPU is upgraded from 2.4 GHz to 3.6 GHz. Explain the likely effect on performance. (2)

The clock produces more cycles per second (1), so the fetch-execute cycle is carried out more times per second and more instructions are processed each second, making programs run faster (1).
:::

::: example Cores do not always help
Explain why a computer with eight cores may not run a particular program twice as fast as one with four cores. (2)

The program may not be written to split its work into parallel tasks, so it can only use one or a few cores (1). Also, cores must coordinate and share data, which takes time, so adding cores does not increase speed in proportion (1).
:::

::: watch
- **Cores**: "four cores = four times faster" is marked wrong. Say performance improves **only if the work can be split**.
- **Cache** is on or near the CPU and is **faster than main memory**; don't confuse it with secondary storage.
- **Fetch** is from **main memory**, not from the hard disk or SSD.
- The **control unit decodes**; the **ALU calculates and compares**. Don't swap them.
- Performance answers need the **effect**: "more instructions processed per second", not just "it is faster".
- You don't need specific register names, and the von Neumann architecture is not in this spec.
:::
