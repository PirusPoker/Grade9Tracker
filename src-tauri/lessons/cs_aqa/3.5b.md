## What it is

For two computers to communicate, they must agree on **exactly** how to do it: how data is formatted, how it is addressed, how errors are handled, who speaks first. These agreements are **protocols**.

A **network protocol** is a **set of rules** that govern **how data is transmitted** and communicated between devices on a network. Because protocols are **standards**, devices and software made by **different manufacturers** can communicate: a phone from one company can load a web page from a server built by another, because both follow the same protocols.

### The protocols you need

| Protocol | Full name | Purpose | Layer |
|---|---|---|---|
| **TCP** | Transmission Control Protocol | sets up a **connection** between the two hosts; **splits data into packets** and **numbers** them; checks that every packet **arrives**, asking for **lost or damaged packets to be resent**; **reassembles** packets in the **correct order** at the destination | transport |
| **IP** | Internet Protocol | gives each packet the **source and destination IP addresses**; the packets are **routed** across networks, hop by hop through routers, to the right destination | internet |
| **HTTP** | Hypertext Transfer Protocol | used by a **web browser** to **request** web pages and other resources from a **web server**, and by the server to send them back | application |
| **HTTPS** | Hypertext Transfer Protocol Secure | an **encrypted** version of HTTP, so data passing between browser and server cannot be read if intercepted; used for **secure transactions** such as logins, online banking and shopping | application |
| **SMTP** | Simple Mail Transfer Protocol | used to **send** email: from the sender's email program to their mail server, and **between mail servers** towards the recipient's server | application |
| **IMAP** | Internet Message Access Protocol | used to **retrieve / access** email held on a **mail server**. Messages **stay on the server**, so the same mailbox (read, deleted, folders) can be seen from several devices | application |

**Memory hook:** **S**MTP **S**ends; IMAP is how you get mail **I**n to your inbox from the server.

### The four-layer TCP/IP model

Networking is split into **layers**. Each layer has its own job and its own protocols; it **uses the services of the layer below** and **provides services to the layer above**.

| Layer | Main function | Protocols / parts |
|---|---|---|
| **Application** (top) | where **network applications** such as **web browsers** and **email programs** operate. It decides **what** data is being sent and in what format. | **HTTP, HTTPS, SMTP, IMAP** |
| **Transport** | **sets up communication between the two hosts**, which agree settings such as the **size of packets**; splits data into numbered packets; makes sure they all arrive, resending any that are lost, and puts them back in order. | **TCP** |
| **Internet** | **addresses and packages** the data for transmission, adding the source and destination **IP addresses**; **routes** the packets across the network(s). | **IP** |
| **Link** (bottom) | where the **network hardware** is, such as the **NIC** (network interface card); **operating system device drivers** also operate here. It sends and receives the actual signals over the cable or radio link. | NIC, device drivers |

**Sending and receiving.** On the **sending** computer, data passes **down** the layers: each one adds the information it needs. On the **receiving** computer it passes **up** the layers, each one dealing with its own information, until the application gets the data.

**Sending an email, layer by layer:**
1. **Application:** the email program uses **SMTP** to send the message to the sender's mail server.
2. **Transport:** **TCP** sets up a connection with the mail server, splits the message into **numbered packets**, and later checks they all arrived.
3. **Internet:** **IP** adds the **source and destination IP addresses** to each packet, and the packets are **routed** across the networks.
4. **Link:** the **NIC** and its **driver** send the packets as signals over the physical connection (cable or wireless).

At the mail server, the packets go back **up** the layers: TCP puts them in order and requests any missing ones, then the server software receives the email. Later, the recipient's email program uses **IMAP** to fetch it from their mail server.

**Why use layers?**
- Each layer is **self-contained** and deals with **one part** of the problem, so networking is easier to understand, design and **troubleshoot**.
- A layer can be **changed or improved without affecting the others**: for example, the same web browser works whether the link is a cable or wireless, because only the link layer differs.
- Manufacturers and programmers can **specialise** in one layer, and products from different companies **work together** because each layer follows **standard protocols**.

::: terms
- **Network protocol**: a set of rules that govern how data is transmitted and communicated between devices on a network.
- **TCP**: Transmission Control Protocol; splits data into numbered packets, checks they all arrive, resends lost ones and reassembles them in order.
- **IP**: Internet Protocol; adds source and destination IP addresses to packets so they can be routed across networks.
- **HTTP**: Hypertext Transfer Protocol; used by browsers and web servers to request and send web pages.
- **HTTPS**: Hypertext Transfer Protocol Secure; an encrypted version of HTTP for secure web transactions.
- **SMTP**: Simple Mail Transfer Protocol; used to send email to and between mail servers.
- **IMAP**: Internet Message Access Protocol; used to retrieve and manage email stored on a mail server.
- **Packet**: a small unit of data sent across a network, carrying addressing information as well as part of the data.
- **TCP/IP model**: a four-layer model of networking: application, transport, internet and link.
- **NIC**: network interface card; the hardware at the link layer that connects a device to a network.
:::

::: method
1. **Define protocol**: a **set of rules** for how data is **transmitted/communicated** between devices.
2. **Purpose of a protocol**: say **what it is used for** (send email, retrieve email, request web pages, secure web pages, packets, addressing).
3. **Layers in order, top to bottom**: **A**pplication, **T**ransport, **I**nternet, **L**ink ("All Turtles Is Lazy" or any hook that works).
4. **Protocol → layer**: HTTP, HTTPS, SMTP, IMAP = application; TCP = transport; IP = internet; NIC and drivers = link.
5. **Describe a layer**: give its main function, not just its protocols.
6. **"What happens at each layer"**: go down the layers in order, one clear action per layer, applied to the example.
7. **Why layers**: self-contained, change one without the others, interoperability/standards.
:::

::: example HTTP and HTTPS
Explain why an online shop uses HTTPS rather than HTTP for its checkout pages. (2)

HTTPS encrypts the data sent between the customer's browser and the shop's web server (1), so card details and passwords cannot be read if the data is intercepted (1).
:::

::: example SMTP and IMAP
Explain the purposes of SMTP and IMAP when Priya sends an email to Ben. (3)

Priya's email program uses SMTP to send the email to her mail server (1), and SMTP is used again to pass it from her mail server to Ben's mail server (1). Ben's email program uses IMAP to retrieve the email from his mail server, where it stays stored (1).
:::

::: example Purpose of TCP
Describe the purpose of TCP. (3)

It sets up communication between the sending and receiving hosts (1). It splits the data into numbered packets (1). It checks all packets have arrived, requests any lost ones to be resent, and reassembles them in the correct order (1).
:::
