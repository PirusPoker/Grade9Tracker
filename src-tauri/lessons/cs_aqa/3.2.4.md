## What it is

A **relational operator** compares two values and gives a **Boolean** result: **True** or **False**. Every `IF`, every `WHILE` and every `UNTIL` depends on one. Choosing the wrong operator by one symbol (`<` instead of `≤`) is enough to make a program reject valid data, and examiners build questions around exactly that kind of mistake.

The six relational operators, and how different languages write them:

| Meaning | AQA pseudo-code | Python | C# | VB.NET | Example (x is 7) |
|---|---|---|---|---|---|
| equal to | `=` | `==` | `==` | `=` | `x = 7` is True |
| not equal to | `≠` | `!=` | `!=` | `<>` | `x ≠ 7` is False |
| less than | `<` | `<` | `<` | `<` | `x < 7` is False |
| greater than | `>` | `>` | `>` | `>` | `x > 5` is True |
| less than or equal to | `≤` | `<=` | `<=` | `<=` | `x ≤ 7` is True |
| greater than or equal to | `≥` | `>=` | `>=` | `>=` | `x ≥ 8` is False |

In AQA pseudo-code, `=` **compares** and `←` **assigns**, so there is no confusion between them. In Python and C#, a single `=` **assigns** and a double `==` **compares**. Writing `if x = 7:` in Python is a syntax error. When you write pseudo-code answers, either style is accepted as long as your meaning is clear.

**Using them.** A comparison can go anywhere a True/False value is needed:
1. `IF age ≥ 18 THEN`
2. `    OUTPUT 'You can vote'`
3. `ENDIF`
4. `WHILE guess ≠ secret`
5. `    guess ← USERINPUT`
6. `ENDWHILE`

The result of a comparison can also be stored in a Boolean variable: `passed ← mark ≥ 40` sets passed to True or False.

**Turning words into operators.** Exam briefs are written in English, and the boundary is decided by one word:

| The brief says | Operator | 18 included? |
|---|---|---|
| "18 or over", "at least 18", "18 and above", "a minimum of 18" | `age ≥ 18` | yes |
| "over 18", "more than 18", "older than 18" | `age > 18` | no |
| "under 18", "less than 18", "younger than 18" | `age < 18` | no |
| "18 or under", "up to 18", "at most 18", "a maximum of 18" | `age ≤ 18` | yes |
| "not 18", "anything except 18" | `age ≠ 18` | no |

Each condition has an **opposite**. The opposite of `x < 5` is `x ≥ 5`, not `x > 5`, because the value 5 itself must go somewhere. The same pattern gives: `>` and `≤`, `=` and `≠`. You need this when you turn a WHILE condition into an UNTIL condition. `WHILE count < 10` keeps going until `count ≥ 10`, so the REPEAT version is `UNTIL count ≥ 10`.

**Range checks** use two comparisons joined by `AND` (Boolean operators are covered in 3.2.5). A score must be from 1 to 10 inclusive:
1. `IF score ≥ 1 AND score ≤ 10 THEN`
2. `    OUTPUT 'Valid'`
3. `ELSE`
4. `    OUTPUT 'Out of range'`
5. `ENDIF`

Writing `score > 1 AND score < 10` instead would reject 1 and 10, the **boundary values**, even though they are allowed. This is a **logic error**: the program runs, but gives the wrong result for some inputs. Testing with boundary data (3.2.11b) is how such errors are found.

**Comparing strings.** Relational operators work on strings too:
- **Equality** compares every character exactly, and it is **case-sensitive**: `'Yes' = 'yes'` is **False**. A program that checks `answer = 'Y'` will reject a user who types `'y'`.
- **Ordering** (`<`, `>`) compares strings **alphabetically**, character by character, using their **character codes**. `'apple' < 'banana'` is True because 'a' comes before 'b'. If the first characters match, the next ones are compared: `'cab' < 'cat'` is True because 'b' comes before 't'. A shorter string that matches the start of a longer one comes first: `'cat' < 'catch'` is True.
- Because the codes for **upper-case letters are lower** than the codes for lower-case letters ('A' is 65, 'a' is 97), `'Zebra' < 'apple'` is True. Programs usually convert both strings to the same case before comparing.
- **Digits stored as strings** compare character by character, not by value. `'10' < '9'` is **True**, because '1' comes before '9'. Convert numbers from input to integers before comparing them.

Python, C# and VB.NET all allow `==`, `!=` (or `<>`) on strings. Python also allows `<` and `>` on strings directly. AQA pseudo-code allows `'A' < 'B'`.

::: terms
- **Relational operator**: an operator that compares two values and gives a Boolean result, such as <, ≥ or ≠.
- **Equal to**: an operator that is True when two values are the same, written = in AQA pseudo-code and == in Python.
- **Not equal to**: an operator that is True when two values differ, written ≠ in AQA pseudo-code and != in Python.
- **Less than or equal to**: an operator that is True when the first value is smaller than or the same as the second, written ≤ or <=.
- **Greater than or equal to**: an operator that is True when the first value is larger than or the same as the second, written ≥ or >=.
- **Condition**: an expression that evaluates to True or False, used in selection and iteration.
- **Boundary value**: a value at the edge of an allowed range, such as 1 or 10 for the range 1 to 10.
- **Case-sensitive**: treating upper-case and lower-case letters as different, so 'Yes' is not equal to 'yes'.
:::

::: method
1. **Evaluating a condition:** substitute the values, then ask the question literally: "is 7 ≤ 7?" Yes, so True.
2. **Translating a brief:** underline the boundary word: "at least", "over", "under", "up to". Then decide whether the boundary value is **included** (≤, ≥) or **excluded** (<, >).
3. **Range check:** lower limit with `≥`, upper limit with `≤`, joined by `AND`, when both ends are allowed.
4. **"Correct this condition and explain the error":** name the value that is handled wrongly ("10 is rejected although it is valid"), say why (`<` excludes 10), and give the corrected condition (`≤ 10`).
5. **Opposites:** `<` ↔ `≥`, `>` ↔ `≤`, `=` ↔ `≠`. Use this when converting between WHILE and REPEAT … UNTIL.
6. **Strings:** equality is exact and case-sensitive; ordering is alphabetical by character code; digits in strings compare as text.
:::

::: example Evaluate conditions
`a ← 12` and `b ← 15`. State whether each condition is True or False: (a) `a ≥ 12`; (b) `b < a`; (c) `a + 3 = b`; (d) `a ≠ b - 3`. (4)

(a) True: 12 is equal to 12, and ≥ includes equal (1).

(b) False: 15 is not less than 12 (1).

(c) True: 12 + 3 is 15 (1).

(d) False: b - 3 is 12, which is equal to a (1).
:::

::: example Fix a boundary error
A cinema shows a film rated 15. A program checks `IF age > 15 THEN OUTPUT 'Allowed' ENDIF`. Explain the error and correct the condition. (3)

Someone aged exactly 15 is allowed to see the film (1).

`age > 15` is False when age is 15, so they would be wrongly refused (1).

The condition should be `age ≥ 15` (1).
:::

::: example Write a range check
Write an algorithm that asks for the number of guests at a party, which must be from 2 to 30 inclusive, and outputs 'OK' or 'Not allowed'. (4)

Input the number (1):
1. `guests ← STRING_TO_INT(USERINPUT)`

Check both limits, including the boundaries, joined with AND (2):
- `IF guests ≥ 2 AND guests ≤ 30 THEN`
- `    OUTPUT 'OK'`

Output the other message in the ELSE branch (1):
- `ELSE`
- `    OUTPUT 'Not allowed'`
- `ENDIF`
:::

::: example Comparing strings
State whether each condition is True or False, and explain why: (a) `'Mia' = 'mia'`; (b) `'bat' < 'bed'`; (c) `'100' < '25'`. (3)

(a) False: the comparison is case-sensitive, and 'M' is not the same character as 'm' (1).

(b) True: the first letters match, and 'a' comes before 'e' (1).

(c) True: these are strings, so they compare character by character, and '1' comes before '2' (1).
:::

::: watch
- **Boundaries decide the mark.** "At least", "or more" and "up to" **include** the value (≥, ≤). "Over" and "under" **exclude** it.
- The opposite of `<` is `≥`, not `>`. The boundary value must land on one side.
- In Python and C#, compare with `==`. A single `=` assigns.
- A range check needs **two complete comparisons**: `x ≥ 1 AND x ≤ 10`, never `1 ≤ x ≤ 10` in AQA pseudo-code, and never `x ≥ 1 AND ≤ 10`.
- String comparison is **case-sensitive** and **character by character**: '10' < '9' is True.
- When asked to explain an error, **name the value that goes wrong** and say what happens to it.
:::

::: test
Explain why boundary values should be used when testing a condition that uses a relational operator. (2)
---
Errors in conditions most often happen at the boundaries, e.g. using < instead of ≤ (1); testing values on and either side of the boundary shows whether each is accepted or rejected correctly (1).
:::

::: test
Write a program, in pseudo-code or program code, that:
- asks the user for the maximum temperature on each of 7 days;
- counts how many days were 25 °C or above;
- finds the lowest of the 7 temperatures;
- outputs the count and the lowest temperature. (6)
---
Example answer (Python):
1. `hot_days = 0`
2. `lowest = float(input("Day 1: "))`
3. `if lowest >= 25:`
4. `    hot_days = hot_days + 1`
5. `for day in range(2, 8):`
6. `    temp = float(input("Day " + str(day) + ": "))`
7. `    if temp >= 25:`
8. `        hot_days = hot_days + 1`
9. `    if temp < lowest:`
10. `        lowest = temp`
11. `print(hot_days, lowest)`
Mark points:
- A. Count-controlled loop that takes exactly 7 temperatures (1).
- B. Each temperature converted to a number (1).
- C. Counter initialised and increased for each temperature ≥ 25, including 25 itself (1).
- D. Lowest initialised to the first temperature (or a suitably large value) (1).
- E. Lowest updated when a smaller temperature is found, using < (1).
- F. Count and lowest output after all 7 have been entered (1).
Accept AQA pseudo-code, C# or VB.NET equivalents.
:::
