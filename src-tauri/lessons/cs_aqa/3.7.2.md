## What it is

**SQL** (Structured Query Language) is the language used to work with a relational database. You need four kinds of statement:

| Statement | What it does |
|---|---|
| `SELECT … FROM … WHERE … ORDER BY …` | **retrieves** (searches for) data, from one or two tables |
| `INSERT INTO … VALUES …` | **adds** a new record |
| `UPDATE … SET … WHERE …` | **changes** data in existing records |
| `DELETE FROM … WHERE …` | **removes** records |

Paper 2 almost always has a **6-mark SELECT** that pulls data from **two tables**, marked one mark per correct clause, plus a 2–3 mark INSERT, UPDATE or DELETE. Exam queries never use more than **two tables** at once.

All the examples use this gym database (from 3.7.1).

**Member**

| MemberID | FirstName | LastName | Plan | Age |
|---|---|---|---|---|
| M001 | Asha | Patel | Gold | 34 |
| M002 | Tom | Reid | Basic | 19 |
| M003 | Grace | Okoye | Gold | 52 |
| M004 | Dev | Shah | Basic | 27 |

**Booking**

| BookingID | MemberID | ClassName | Day | Cost |
|---|---|---|---|---|
| B501 | M001 | Spin | Monday | 6.50 |
| B502 | M003 | Spin | Monday | 6.50 |
| B503 | M001 | Yoga | Tuesday | 5.00 |
| B504 | M002 | Boxfit | Monday | 7.00 |
| B505 | M004 | Yoga | Tuesday | 5.00 |

MemberID is the primary key of Member and a foreign key in Booking.

### SELECT, FROM, WHERE

A query to list the first and last names of all Gold members:
1. `SELECT FirstName, LastName`
2. `FROM Member`
3. `WHERE Plan = "Gold"`

- **SELECT** lists the **fields** (columns) to show, separated by **commas**, in the order you want them. `SELECT *` means every field; only use it if the question asks for all the fields.
- **FROM** names the **table** the data comes from.
- **WHERE** gives the **condition** a record must meet to be included. Leave it out and every record is returned.

Result:

| FirstName | LastName |
|---|---|
| Asha | Patel |
| Grace | Okoye |

**Writing conditions**
- Comparison operators: `=`, `<>` (not equal; `!=` is also accepted), `<`, `>`, `<=`, `>=`. Use a single `=`. Writing `==` is rejected in AQA mark schemes.
- **Text values go in quotation marks**: `Plan = "Gold"`. Single quotes are fine too. Field names never go in quotes.
- **Numbers do not need quotes**: `Age > 30`, `Cost <= 6.50`.
- Booleans are written `True` or `False`.
- Combine conditions with **AND** (both must be true) and **OR** (either can be true). Each side must be a full condition: write `Age >= 18 AND Age <= 30`, not `Age >= 18 AND <= 30`.

Example: Basic members aged under 25.
1. `SELECT MemberID, FirstName`
2. `FROM Member`
3. `WHERE Plan = "Basic" AND Age < 25`

Only Tom Reid (M002, Tom) meets both conditions; Dev Shah is Basic but 27.

### ORDER BY … ASC | DESC

**ORDER BY** sorts the results on a field. **ASC** is ascending (A to Z, smallest first) and **DESC** is descending (Z to A, largest first). If you leave out ASC, ascending is assumed, and mark schemes ignore a missing ASC, but always write DESC when you need it.

All members, oldest first:
1. `SELECT FirstName, LastName, Age`
2. `FROM Member`
3. `ORDER BY Age DESC`

ORDER BY always comes **last**, after WHERE. The field you sort on does not have to be one of the SELECT fields.

### Queries on two tables

Often the data you need is split between tables: the names are in Member, but the classes are in Booking. You list **both tables** in FROM, then **link them** in WHERE by saying that the **foreign key equals the primary key**:
1. `SELECT FirstName, LastName, ClassName`
2. `FROM Member, Booking`
3. `WHERE Member.MemberID = Booking.MemberID`
4. `AND Day = "Monday"`
5. `ORDER BY LastName ASC`

How it works:
- `FROM Member, Booking` takes the two tables.
- `Member.MemberID = Booking.MemberID` is the **link (join) condition**. It pairs each booking with the one member whose MemberID matches. Without it, the database pairs **every** booking with **every** member (5 × 4 = 20 rows of nonsense), and the join mark is lost.
- `AND Day = "Monday"` is the search condition, joined to the link with **AND**.
- **TableName.FieldName** (dot notation) says which table a field comes from. You **must** use it for a field that appears in both tables (MemberID here); for other fields it is optional and always accepted.

Result:

| FirstName | LastName | ClassName |
|---|---|---|
| Grace | Okoye | Spin |
| Asha | Patel | Spin |
| Tom | Reid | Boxfit |

The alternative form, also given full marks:
1. `SELECT FirstName, LastName, ClassName`
2. `FROM Member`
3. `INNER JOIN Booking ON Member.MemberID = Booking.MemberID`
4. `WHERE Day = "Monday"`
5. `ORDER BY LastName ASC`

**How the 6 marks are usually split** for a two-table query (one mark each):
- **A** the correct fields in SELECT, **and no others**;
- **B** the first correct table in FROM;
- **C** the second correct table, and no extra tables;
- **D** the link: primary key = foreign key, in WHERE or in JOIN … ON;
- **E** the search condition;
- **F** the ORDER BY clause.

Answers that contain any error are usually capped at 5. Case and spacing are ignored, but **field and table names must be spelt exactly as in the figure**.

**A building routine for the 6-marker:**
1. Underline every field the question says to show. That is the SELECT line, in that order.
2. Note which table each field, and each condition field, lives in. That gives FROM.
3. Find the key both tables share and write `Table1.Key = Table2.Key`.
4. Add the condition with AND, text in quotes.
5. Add ORDER BY with ASC or DESC if the question asks for an order.

### INSERT INTO … VALUES

Adds **one new record**:
1. `INSERT INTO Member (MemberID, FirstName, LastName, Plan, Age)`
2. `VALUES ("M005", "Lena", "Novak", "Gold", 41)`

- The field list in brackets and the values list must be in the **same order** and have the **same number** of items.
- Text in quotes, numbers without. The spec's form lists the fields; if the values are given for **every** field in table order, the field list can be left out, but including it is never wrong.
- A new record must have a **primary key value that is not already used** (M005, not M001).

### UPDATE … SET … WHERE

Changes values in records that **already exist**:
1. `UPDATE Member`
2. `SET Plan = "Gold", Age = 20`
3. `WHERE MemberID = "M002"`

- **SET** gives each field and its new value; separate several with commas.
- **WHERE** picks which records change. Use the **primary key** to change exactly one record.
- Forget the WHERE and **every record** in the table is changed.

You can also update several records at once on purpose, for example raising the cost of every Yoga class:
1. `UPDATE Booking`
2. `SET Cost = 5.50`
3. `WHERE ClassName = "Yoga"`

### DELETE FROM … WHERE

Removes whole records:
1. `DELETE FROM Booking`
2. `WHERE BookingID = "B503"`

- DELETE removes **entire rows**, so there is no field list. `DELETE FirstName FROM …` is wrong; to blank one value you would use UPDATE.
- Without WHERE, **every record** in the table is deleted.
- Deleting a member who still has bookings would leave Booking records pointing at a member who no longer exists. You don't need to know how a DBMS prevents this, but it is a good reason to delete the bookings first.

### Reading a query and giving its results

Some questions show you a query and ask for its output. Work through it clause by clause: **FROM** (which tables), **WHERE** (cross out every record that fails, checking each AND/OR), **SELECT** (keep only those columns), **ORDER BY** (sort what is left). Write the result as a table, or list the values in order.

::: terms
- **SQL**: Structured Query Language, the language used to search and change the data in a relational database.
- **Query**: a request to a database for data that meets given conditions, written in SQL with SELECT.
- **SELECT**: the clause listing the fields to show in the results, separated by commas.
- **FROM**: the clause naming the table or tables that the data comes from.
- **WHERE**: the clause giving the condition records must meet; in a two-table query it also links the tables.
- **ORDER BY**: the clause that sorts the results on a field, ASC for ascending or DESC for descending.
- **Join condition**: a condition such as Member.MemberID = Booking.MemberID that matches the foreign key to the primary key.
- **Dot notation**: writing TableName.FieldName to show which table a field belongs to.
- **INSERT INTO**: the statement that adds a new record, with the field names and a matching VALUES list.
- **UPDATE**: the statement that changes values in existing records, using SET for new values and WHERE to pick records.
- **DELETE FROM**: the statement that removes whole records that meet the WHERE condition.
:::

::: method
1. **Read the figure**: find which table holds each field the question mentions, and the key that links the tables.
2. **SELECT** exactly the fields asked for, in order, separated by commas. Nothing extra.
3. **FROM** the table, or both tables separated by a comma.
4. **WHERE**: for two tables, first `Table1.Key = Table2.Key`, then `AND` the condition. Text in quotes, numbers without, single `=`.
5. **ORDER BY** the named field, with **DESC** for largest first or Z to A.
6. **INSERT / UPDATE / DELETE**: use the exact template. UPDATE and DELETE need a WHERE, normally on the primary key.
7. **Check** every field and table name letter by letter against the figure.
:::

::: example Single-table query
Using the Member table, write an SQL query to list the MemberID and LastName of every member aged 30 or over, with the oldest first. (4)

1. `SELECT MemberID, LastName` (1)
2. `FROM Member` (1)
3. `WHERE Age >= 30` (1)
4. `ORDER BY Age DESC` (1)
:::

::: example Two-table query
Using the Member and Booking tables, write an SQL query to list the first name, last name and cost of every Spin booking made by a Gold member. The results must be in ascending order of last name. (6)

1. `SELECT FirstName, LastName, Cost` (A)
2. `FROM Member, Booking` (B, C)
3. `WHERE Member.MemberID = Booking.MemberID` (D)
4. `AND ClassName = "Spin" AND Plan = "Gold"` (E)
5. `ORDER BY LastName ASC` (F)

One mark for each lettered point.
:::

::: example Result of a query
Give the results of this query on the Booking table: `SELECT BookingID, Cost FROM Booking WHERE Day = "Tuesday" OR Cost > 6.80 ORDER BY Cost DESC` (3)

B504, 7.00 first (1); then B503, 5.00 and B505, 5.00 (1); no other records (1). B504 is Monday but costs more than 6.80; B503 and B505 are Tuesday.
:::

::: example Insert a record
Write an SQL statement to add a booking with ID B506 for member M003 to the Yoga class on Tuesday, costing 5.00. (3)

1. `INSERT INTO Booking (BookingID, MemberID, ClassName, Day, Cost)` (1)
2. `VALUES ("B506", "M003", "Yoga", "Tuesday", 5.00)` (1 for VALUES with the values, 1 for matching order and quotes on text)
:::

::: example Update and delete
Tom Reid (M002) has cancelled booking B504, and Dev Shah (M004) has moved to the Gold plan. Write the two SQL statements. (4)

1. `DELETE FROM Booking` (1)
2. `WHERE BookingID = "B504"` (1)
3. `UPDATE Member SET Plan = "Gold"` (1)
4. `WHERE MemberID = "M004"` (1)
:::

::: q
State the purpose of the WHERE clause in a SELECT query. (1)
---
It sets the condition/criteria a record must meet to be included in the results (1).
:::

::: q
Explain the difference between `ORDER BY Age ASC` and `ORDER BY Age DESC`. (2)
---
ASC sorts the results in ascending order, smallest age first (1); DESC sorts in descending order, largest age first (1).
:::

::: q
Write an SQL query to show all the fields of every Basic member in the Member table. (3)
---
`SELECT *` or all five fields listed (1); `FROM Member` (1); `WHERE Plan = "Basic"` (1).
:::

::: q
In a two-table query, explain why the condition `Member.MemberID = Booking.MemberID` is needed. (2)
---
It links each booking to the matching member, using the foreign key and primary key (1); without it every record in one table is combined with every record in the other, giving wrong/meaningless results (1).
:::

::: q
A student writes `UPDATE Booking SET Cost = 4.00` intending to change only booking B505. Explain what will happen and correct the statement. (3)
---
There is no WHERE clause, so the cost of every booking is changed to 4.00 (1). Corrected: `UPDATE Booking SET Cost = 4.00` (1) `WHERE BookingID = "B505"` (1).
:::

::: q
Write an SQL statement to delete every booking for the Boxfit class. (2)
---
`DELETE FROM Booking` (1) `WHERE ClassName = "Boxfit"` (1).
:::

::: watch
- In a two-table query, **link the tables**: `Table1.Key = Table2.Key`. Forgetting it is the most common lost mark.
- **SELECT only the fields asked for.** An extra field, or `SELECT *` when specific fields were asked for, loses the SELECT mark.
- **Spell field and table names exactly** as in the figure; no spaces where there are none.
- Use a **single** `=`. `==` is rejected.
- Put **text in quotes**, numbers without. Don't put field names in quotes.
- Each side of AND/OR needs a **full condition**: `Age > 18 AND Age < 30`.
- **DELETE** removes rows, so no field list. **UPDATE** and **DELETE** without WHERE affect **every record**.
- ORDER BY comes **last**, and largest-first or Z-to-A needs **DESC**.
:::

Explain why an UPDATE statement should normally use the primary key in its WHERE clause. (2)

::: test
A garden centre's database has these tables:
Customer(CustomerID, FirstName, LastName, Town, Loyalty) and Purchase(PurchaseID, CustomerID, PurchaseDate, Total).
Write an SQL query that lists the first name, last name and order total for every purchase made by a customer from Exeter. The results must be in descending order of total. (6)
---
Max 5 if any errors. I. case and spacing; A. table names before field names; R. == for =.
- A `SELECT FirstName, LastName, Total` and no other fields (1)
- B `FROM Customer` (1)
- C second table `Purchase` and no others (1)
- D `WHERE Customer.CustomerID = Purchase.CustomerID`, or `INNER JOIN Purchase ON Customer.CustomerID = Purchase.CustomerID` (1)
- E `AND Town = "Exeter"` (1)
- F `ORDER BY Total DESC` (1)
:::

::: test
A school's trip database has these tables:
Student(StudentID, FirstName, LastName, YearGroup) and TripPlace(PlaceID, StudentID, TripName, Deposit).
Write an SQL query that returns only the last name of the student, the trip name and the deposit for every Year 10 student who has paid a deposit of less than 20.00. The results must be in alphabetical order of last name. (6)
---

- A `SELECT LastName, TripName, Deposit` and no other fields (1)
- B `FROM Student` (1)
- C second table `TripPlace` and no others (1)
- D `WHERE Student.StudentID = TripPlace.StudentID` or the JOIN … ON form (1)

::: test
A student writes this two-table query: `SELECT FirstName, Total FROM Customer, Purchase WHERE Total > 100`. Explain the error and write the corrected WHERE clause. (3)
---
There is no condition linking the two tables (1), so every customer is combined with every purchase, giving wrong pairings (1). `WHERE Customer.CustomerID = Purchase.CustomerID AND Total > 100` (1).
:::

::: test
Explain why `CustomerID` must be written as `Customer.CustomerID` or `Purchase.CustomerID` in a query that uses both the Customer and Purchase tables. (2)
---
The field name CustomerID appears in both tables (1), so the table name is needed to make clear which table's field is meant; otherwise the query is ambiguous (1).
:::

::: test
Explain the difference between the DELETE and UPDATE statements, and what happens if either is run without a WHERE clause. (3)
---
DELETE removes whole records from a table (1); UPDATE changes the values of fields in existing records (1); without a WHERE clause, every record in the table is deleted / changed (1).
:::
