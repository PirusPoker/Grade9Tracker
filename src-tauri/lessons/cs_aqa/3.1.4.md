## What it is

A **sorting algorithm** puts the items in a list into order: ascending (smallest first, or A to Z) or descending. AQA names two: **bubble sort** and **merge sort**. As with searching, you need the **mechanics** of each, step by step, the ability to carry each out by hand, and their **advantages and disadvantages**.

**Bubble sort** works by making repeated **passes** through the list:
1. Compare the first two items. If they are in the wrong order, **swap** them.
2. Move along one place and compare the next **adjacent pair** (items 2 and 3), swapping if needed.
3. Carry on to the end of the list. That is **one pass**. The largest item has now "bubbled" to the end, into its final place.
4. Make another pass, and keep going until a **whole pass makes no swaps**. Then the list is sorted.

Sorting 5, 1, 4, 2, 8 into ascending order:

| Pass | Comparisons and swaps | List after the pass |
|---|---|---|
| 1 | 5 and 1 swap; 5 and 4 swap; 5 and 2 swap; 5 and 8 no swap | 1, 4, 2, 5, 8 |
| 2 | 1 and 4 no; 4 and 2 swap; 4 and 5 no; 5 and 8 no | 1, 2, 4, 5, 8 |
| 3 | no swaps at all | 1, 2, 4, 5, 8: stop |

The list was sorted after pass 2, but the algorithm only **knows** it is sorted when pass 3 makes no swaps. A list of n items needs **at most n - 1 passes** that make swaps, and each pass makes up to **n - 1 comparisons**.

A **swap** needs a temporary variable. If you write `a ← b` then `b ← a`, both end up with b's old value. Instead, store one value first:
1. `temp ← arr[i]`
2. `arr[i] ← arr[i + 1]`
3. `arr[i + 1] ← temp`

The whole bubble sort in AQA pseudo-code, using a **swapped flag** to stop as soon as a pass makes no swaps:
1. `swapped ← True`
2. `WHILE swapped = True`
3. `    swapped ← False`
4. `    FOR i ← 0 TO LEN(arr) - 2`
5. `        IF arr[i] > arr[i + 1] THEN`
6. `            temp ← arr[i]`
7. `            arr[i] ← arr[i + 1]`
8. `            arr[i + 1] ← temp`
9. `            swapped ← True`
10. `        ENDIF`
11. `    ENDFOR`
12. `ENDWHILE`

The FOR loop stops at `LEN(arr) - 2` because each comparison looks at `arr[i + 1]`. Going to `LEN(arr) - 1` would look past the end of the array. In Python, the same algorithm uses `while swapped:`, `for i in range(len(arr) - 1):`, and Python can swap in one line: `arr[i], arr[i + 1] = arr[i + 1], arr[i]`. To sort into **descending** order, change `>` to `<` on line 5.

**Merge sort** is a **divide and conquer** algorithm with two phases:
1. **Divide:** split the list in half, then split each half in half, and keep going until every sub-list contains **one item**. A list of one item is already sorted.
2. **Merge:** merge pairs of sub-lists back together **in order**, producing sorted lists of 2, then 4, then 8, and so on, until a single sorted list remains.

**How two sorted lists are merged** (this is where the sorting actually happens): compare the **first** item of each list, move the **smaller** one to the new list, and repeat. When one list is empty, copy the rest of the other list across. Merging 3, 8, 12 with 1, 9, 10:

| Compare | Take | New list so far |
|---|---|---|
| 3 and 1 | 1 | 1 |
| 3 and 9 | 3 | 1, 3 |
| 8 and 9 | 8 | 1, 3, 8 |
| 12 and 9 | 9 | 1, 3, 8, 9 |
| 12 and 10 | 10 | 1, 3, 8, 9, 10 |
| second list empty | 12 | 1, 3, 8, 9, 10, 12 |

The whole merge sort of 6, 2, 9, 4, 1, 7, 3, 8:

| Stage | Sub-lists |
|---|---|
| Start | [6, 2, 9, 4, 1, 7, 3, 8] |
| Split | [6, 2, 9, 4] [1, 7, 3, 8] |
| Split | [6, 2] [9, 4] [1, 7] [3, 8] |
| Split | [6] [2] [9] [4] [1] [7] [3] [8] |
| Merge | [2, 6] [4, 9] [1, 7] [3, 8] |
| Merge | [2, 4, 6, 9] [1, 3, 7, 8] |
| Merge | [1, 2, 3, 4, 6, 7, 8, 9] |

With an odd number of items, one half gets the extra item: [5, 3, 8] might split into [5] and [3, 8]. Either way round is accepted if you are consistent.

You will not be asked to write merge sort code at GCSE. It is usually written using **recursion** (a subroutine that calls itself), which is beyond the course. You must be able to **describe and carry out** both phases.

**Comparing the two sorts:**

| | Bubble sort | Merge sort |
|---|---|---|
| Speed on large lists | **slow**: the number of comparisons grows very quickly with the list size | **much faster** on large lists |
| Speed on nearly sorted lists | **fast** with a swapped flag: a sorted list needs only one pass | no faster: it always splits and merges everything |
| Memory | sorts **in place**: needs only one extra variable for a swap | needs **extra memory** to hold the sub-lists while merging |
| Ease of coding | **simple** to understand and write | **more complex** to write (usually recursive) |
| Consistency | time varies a lot with how unsorted the data is | takes a similar time whatever the order |

As a rule of thumb, merge sort suits **large** data sets where speed matters and memory is plentiful. Bubble sort suits **small** lists, **nearly sorted** lists, or devices with **very little memory**.

::: terms
- **Sorting algorithm**: an algorithm that puts the items of a list into ascending or descending order.
- **Bubble sort**: a sort that repeatedly passes through a list, comparing adjacent pairs and swapping any in the wrong order, until a pass makes no swaps.
- **Pass**: one complete run through the list in a bubble sort, comparing each adjacent pair once.
- **Swap**: exchanging the positions of two items, which needs a temporary variable to avoid losing one value.
- **Swapped flag**: a Boolean that records whether a pass made any swaps, so the sort can stop once a pass makes none.
- **Merge sort**: a sort that splits a list into single items and then merges them back together in order.
- **Divide and conquer**: solving a problem by splitting it into smaller parts, solving them, and combining the results.
- **Merge**: combining two sorted lists into one sorted list by repeatedly taking the smaller of their first items.
- **In place**: sorting within the original list without needing a second copy of the data.
:::

::: method
1. **"Show the list after one pass" (bubble sort):** compare pairs from the left, swapping as you go, and carry each swapped item forward into the next comparison. Write the list as it stands at the end of the pass.
2. **"Show every pass":** write the list after each pass, and include the final pass with **no swaps**, which is how the algorithm knows to stop.
3. **"Explain how bubble sort works":** compare adjacent items; swap if in the wrong order; move along to the end (one pass); repeat passes until a pass makes no swaps.
4. **"Explain how merge sort works":** split the list in half repeatedly until each sub-list has one item; merge pairs of sub-lists by comparing their first items and taking the smaller; repeat merging until one sorted list remains.
5. **Show a merge sort as stages:** one row per split level, then one row per merge level, with brackets around each sub-list.
6. **"Compare" questions:** pair your points: speed on large lists, memory, ease of coding, behaviour on nearly sorted data. Apply them to the scenario if there is one: size of data, memory available, how sorted the data already is.
:::

::: example One pass of bubble sort
Show the list 7, 3, 9, 1, 5 after the first pass of a bubble sort into ascending order. (2)

7 and 3 swap, giving 3, 7, 9, 1, 5; 7 and 9 stay; 9 and 1 swap, giving 3, 7, 1, 9, 5 (1).

9 and 5 swap. After pass 1 the list is 3, 7, 1, 5, 9, with the largest item, 9, now at the end (1).
:::

::: example Every pass of bubble sort
Carry on sorting 3, 7, 1, 5, 9 with a bubble sort. Show the list after each remaining pass and say when the algorithm stops. (3)

Pass 2: 3 and 7 stay; 7 and 1 swap; 7 and 5 swap; 7 and 9 stay, giving 3, 1, 5, 7, 9 (1).

Pass 3: 3 and 1 swap, then no more swaps, giving 1, 3, 5, 7, 9 (1).

Pass 4 makes no swaps, so the algorithm stops: the list is sorted (1).
:::

::: example Explain merge sort
Explain how the merge sort algorithm sorts a list. (4)

The list is repeatedly split in half (1)...

...until every sub-list contains only one item (1).

Pairs of sub-lists are then merged by comparing the first item of each and moving the smaller into the new list, until both are used up (1).

Merging continues, producing larger sorted lists, until one sorted list remains (1).
:::

::: example Merge sort by stages
Show how merge sort sorts 14, 7, 3, 12, 9, 11, 6, 2 into ascending order. (4)

Split into halves, then quarters: [14, 7, 3, 12] [9, 11, 6, 2], then [14, 7] [3, 12] [9, 11] [6, 2] (1).

Split into single items: [14] [7] [3] [12] [9] [11] [6] [2] (1).

Merge pairs in order: [7, 14] [3, 12] [9, 11] [2, 6], then [3, 7, 12, 14] [2, 6, 9, 11] (1).

Final merge: [2, 3, 6, 7, 9, 11, 12, 14] (1).
:::

::: example Choose a sort
A smartwatch stores the last 20 heart-rate readings, which are nearly always in order already. Its memory is very limited. Explain why bubble sort is a suitable choice. (3)

Bubble sort sorts in place, so it needs almost no extra memory, which suits the watch's limited memory (1).

With a swapped flag, a nearly sorted list needs only one or two passes, so bubble sort is quick in this case (1).

There are only 20 items, so merge sort's speed advantage on large lists would make little difference, and bubble sort is simpler to code and test (1).
:::

---
If one item is copied over the other first, the second item's value is overwritten and lost (1); the temporary variable holds one value so it can be put into the other position afterwards (1).

::: watch
- **Show every pass**, including the final pass with **no swaps**. That is how bubble sort ends, and it often carries a mark.
- In a pass, the item you swapped **moves on** into the next comparison. Do not compare against the old list.
- Merge sort's order comes from **merging**, not from splitting. "Split the list and sort the halves" does not explain it. Describe comparing the **first items** of two lists.
- Split **all the way down to single items** before any merging.
- Merge sort uses **more memory**; bubble sort sorts **in place**. Getting this backwards loses the mark.
- Bubble sort is **not always slow**: on a nearly sorted list with a swapped flag it can finish in one pass.
:::

Write a program, in pseudo-code or program code, that:

9. `            nums[i + 1] = temp`
10. `            swapped = True`
11. `print(nums)`
