## What it is

Paper 1 hands you algorithms you have never seen and asks what they do. Two skills answer almost every one of those questions: spotting the **inputs, processing and outputs**, and **tracing** the algorithm line by line to find its **purpose**.

**Inputs, processing and outputs.** Every algorithm takes data in, does something with it, and gives a result:
- **Input** is data that enters the algorithm from outside. In AQA pseudo-code it is usually a line with `USERINPUT`, such as `age ← USERINPUT`. Data passed into a subroutine as a parameter is also an input to that subroutine.
- **Processing** is anything that works on the data: calculations (`total ← total + price`), comparisons and decisions (`IF age ≥ 18 THEN`), loops, and changes to arrays or strings.
- **Output** is data leaving the algorithm, usually a line with `OUTPUT`. A value sent back with `RETURN` is the output of a subroutine.

Take this algorithm (the line numbers are the ones an exam would use):
1. `total ← 0`
2. `count ← 0`
3. `num ← USERINPUT`
4. `WHILE num ≠ -1`
5. `    total ← total + num`
6. `    count ← count + 1`
7. `    num ← USERINPUT`
8. `ENDWHILE`
9. `OUTPUT total DIV count`

Input happens on **lines 3 and 7**. Processing happens on lines 1, 2, 4, 5 and 6 (setting up, testing and updating values) and in the calculation `total DIV count` on line 9. Output happens on **line 9**. Notice that an input can appear twice: once before the loop and again inside it.

**Trace tables.** A trace table is a grid you fill in as you "run" the algorithm by hand. It records how the value of each variable changes as each line runs, so you can see exactly what the algorithm does.
- Give each **variable** its own column, in the order the question gives them. Add a column for **output** if there is one, and for a **condition** if it helps.
- Work through the code **one line at a time**, exactly as the computer would. Do not skip ahead because you think you know the answer.
- Write a new value in a column **only when that variable changes**. Move down a row as the algorithm moves on. You do not need to copy unchanged values into every row.
- For a loop, check the condition **every time** round. For a `FOR` loop, the counter takes each value from the start to the end **inclusive**.
- Keep going until the algorithm finishes, and include the **final output**.

Tracing the algorithm above with inputs 6, 3, 9 and -1:

| total | count | num | OUTPUT |
|---|---|---|---|
| 0 | 0 | 6 | |
| 6 | 1 | 3 | |
| 9 | 2 | 9 | |
| 18 | 3 | -1 | |
| | | | 6 |

When num becomes -1 the loop condition `num ≠ -1` is false, so the loop stops and the algorithm outputs 18 DIV 3, which is 6. The -1 is never added to the total. A value like this that only signals "stop" is called a **rogue value** (or sentinel).

**Determining the purpose.** Once you have traced it, say what the algorithm is **for**, in terms of its inputs. Here, the purpose is: *to input numbers until -1 is entered, then output their (whole-number) average*. "It adds numbers" is too vague to earn the mark. Name the result and what it is calculated from.

You can often find the purpose by **visual inspection**, just by reading the code and recognising a pattern. These patterns come up again and again:

| Pattern in the code | Purpose |
|---|---|
| `total ← 0` before a loop, `total ← total + x` inside it | totals the values |
| a total, then `total / count` or `total DIV count` | average (mean) |
| `max ← first item`, then `IF item > max THEN max ← item` | finds the largest value |
| `count ← count + 1` inside an `IF` | counts how many items meet a condition |
| `x MOD 2 = 0` | tests whether x is even |
| `n MOD 10` then `n ← n DIV 10` in a loop | takes the digits of n one at a time |
| `result ← ch + result` for each character | reverses a string |
| a loop that repeats until an input is acceptable | validation |
| `IF item = target THEN found ← True` | searches for a value |

**Tracing with arrays and DIV/MOD.** Arrays are indexed from **0**. Keep a column for the index (often `i`) and look up the item each time. `DIV` gives the whole-number part of a division and `MOD` gives the remainder: 17 DIV 5 = 3 and 17 MOD 5 = 2.
1. `nums ← [4, 7, 10, 3]`
2. `evens ← 0`
3. `FOR i ← 0 TO 3`
4. `    IF nums[i] MOD 2 = 0 THEN`
5. `        evens ← evens + 1`
6. `    ENDIF`
7. `ENDFOR`
8. `OUTPUT evens`

| i | nums[i] | nums[i] MOD 2 | evens | OUTPUT |
|---|---|---|---|---|
| | | | 0 | |
| 0 | 4 | 0 | 1 | |
| 1 | 7 | 1 | | |
| 2 | 10 | 0 | 2 | |
| 3 | 3 | 1 | | |
| | | | | 2 |

Purpose: to count how many numbers in the array are even.

**Tracing nested loops.** In a nested loop, the **inner loop runs all the way through for each single pass of the outer loop**. Slow down here: this is where most trace marks are lost.
1. `total ← 0`
2. `FOR i ← 1 TO 3`
3. `    FOR j ← 1 TO 2`
4. `        total ← total + i * j`
5. `    ENDFOR`
6. `ENDFOR`
7. `OUTPUT total`

| i | j | total | OUTPUT |
|---|---|---|---|
| | | 0 | |
| 1 | 1 | 1 | |
| | 2 | 3 | |
| 2 | 1 | 5 | |
| | 2 | 9 | |
| 3 | 1 | 12 | |
| | 2 | 18 | |
| | | | 18 |

The inner counter j goes 1, 2 for **every** value of i, so line 4 runs 3 × 2 = 6 times.

::: terms
- **Input**: data that enters an algorithm from outside, such as a value typed by the user with USERINPUT.
- **Processing**: the work an algorithm does on data, such as calculations, comparisons, decisions and loops.
- **Output**: data or information that an algorithm produces and sends out, such as a value displayed with OUTPUT.
- **Trace table**: a table used to record how the values of variables change as an algorithm is followed line by line.
- **Dry run**: working through an algorithm by hand, without a computer, to see what it does.
- **Visual inspection**: working out what an algorithm does by reading it and recognising familiar patterns.
- **Purpose**: what an algorithm is for: the result it produces from its inputs.
- **Rogue value**: a special input, such as -1, that is not real data and only signals that input has finished.
- **Nested loop**: a loop inside another loop, where the inner loop runs completely for each pass of the outer loop.
:::

::: method
1. **Read the whole algorithm first.** Find where it starts, which lines repeat, and what the variables are for.
2. **Set up the table** with the columns given, in that order. Fill in the starting values from any assignments before the loop.
3. **Go line by line.** For each line, update only the variable it changes. For an `IF`, work out the condition and follow only the branch that runs.
4. **At each loop test, check the condition with the current values.** A `WHILE` checks before each pass, a `REPEAT … UNTIL` after each pass, and a `FOR` counter takes every value up to and **including** the end value.
5. **For nested loops, finish the inner loop completely** before the outer counter moves on, then restart the inner loop from its first value.
6. **Write the output** in the output column at the moment the `OUTPUT` line runs, which is not always at the end.
7. **State the purpose** in terms of the inputs and the result: "outputs the largest of the numbers entered", not "it compares numbers".
8. **Input/processing/output questions:** inputs are the `USERINPUT` lines, outputs are the `OUTPUT` (or `RETURN`) lines, and everything that calculates, compares or loops is processing.
:::

::: example Identify inputs, processing and outputs
1. `price ← USERINPUT`
2. `qty ← USERINPUT`
3. `cost ← price * qty`
4. `IF cost > 50 THEN`
5. `    cost ← cost - 5`
6. `ENDIF`
7. `OUTPUT cost`
Give the line numbers where (a) input takes place; (b) output takes place; and (c) describe one piece of processing. (3)

(a) Lines 1 and 2, where USERINPUT is used (1).

(b) Line 7 (1).

(c) Any one, e.g. line 3 multiplies the price by the quantity to calculate the cost, or lines 4–5 take £5 off if the cost is over £50 (1).
:::

::: example Trace a loop that uses DIV and MOD
1. `n ← USERINPUT`
2. `total ← 0`
3. `WHILE n > 0`
4. `    total ← total + (n MOD 10)`
5. `    n ← n DIV 10`
6. `ENDWHILE`
7. `OUTPUT total`
Complete a trace table with columns n, total and OUTPUT when the input is 472, and state the purpose of the algorithm. (5)

Start: n is 472 and total is 0 (1).

First pass: 472 MOD 10 = 2, so total becomes 2; 472 DIV 10 = 47, so n becomes 47 (1).

Second pass: 47 MOD 10 = 7, so total becomes 9, and n becomes 4. Third pass: 4 MOD 10 = 4, so total becomes 13, and n becomes 0 (1).

| n | total | OUTPUT |
|---|---|---|
| 472 | 0 | |
| 47 | 2 | |
| 4 | 9 | |
| 0 | 13 | |
| | | 13 |

n is now 0, so the condition `n > 0` is false and the loop stops; 13 is output (1).

Purpose: to add up the digits of the number entered (1).
:::

::: example Find the purpose by inspection
1. `scores ← [12, 31, 8, 27]`
2. `best ← scores[0]`
3. `FOR i ← 1 TO 3`
4. `    IF scores[i] > best THEN`
5. `        best ← scores[i]`
6. `    ENDIF`
7. `ENDFOR`
8. `OUTPUT best`
State the purpose of this algorithm and the value it outputs. (2)

It finds and outputs the largest (highest) value in the array scores (1).

It outputs 31: best starts at 12, becomes 31 when i is 1, and 8 and 27 are both smaller (1).
:::

::: example Trace a nested loop
1. `count ← 0`
2. `FOR x ← 1 TO 3`
3. `    FOR y ← x TO 3`
4. `        count ← count + 1`
5. `    ENDFOR`
6. `ENDFOR`
7. `OUTPUT count`
Complete a trace table with columns x, y, count and OUTPUT. (4)

The inner loop starts at the **current value of x**, so it runs 3 times when x is 1 (1):

| x | y | count | OUTPUT |
|---|---|---|---|
| | | 0 | |
| 1 | 1 | 1 | |
| | 2 | 2 | |
| | 3 | 3 | |
| 2 | 2 | 4 | |
| | 3 | 5 | |
| 3 | 3 | 6 | |
| | | | 6 |

When x is 2 the inner loop runs for y = 2 and 3 only (1), and when x is 3 it runs once, for y = 3 (1).

The output is 6 (1).
:::

::: watch
- Write a value **only when it changes**, and keep each value in the row where it changes. A jumbled table loses accuracy marks.
- Do not stop one pass early: a `FOR i ← 1 TO 5` loop **includes** 5, and a `WHILE` loop stops only when its condition is false at the test.
- In nested loops, **restart the inner loop** for every pass of the outer loop, and check whether its start value depends on the outer counter.
- `DIV` gives a **whole number** and `MOD` gives the **remainder**: 7 DIV 2 = 3, 7 MOD 2 = 1. Writing 3.5 throws away the mark.
- A rogue value such as -1 is **not added** to the total. Check where the input sits in the loop.
- A purpose must name **the result**: "outputs the total of the numbers entered", not "it uses a loop".
- Arrays start at **index 0**. `nums[1]` is the **second** item.
:::
