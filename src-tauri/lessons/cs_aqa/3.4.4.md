## What it is

A processor can only carry out one kind of instruction: **machine code**, patterns of **binary** that its circuits are built to recognise. People, however, find it much easier to write programs in something closer to English. Programming languages therefore come in **levels**, and every program that is not already machine code must be **translated** before it can run.

### Low-level and high-level languages

| | **Low-level languages** | **High-level languages** |
|---|---|---|
| **Examples** | **machine code** and **assembly language** | Python, C#, VB.NET, Java, C++ |
| **Looks like** | binary (machine code) or short mnemonics such as ADD and STR (assembly) | English-like keywords (IF, WHILE, print) and maths-like expressions |
| **Relationship to the processor** | written for a **specific processor** or family of processors; uses its instruction set, registers and memory addresses directly | **independent** of the processor; the same source code can be translated for different processors |
| **Instructions per statement** | one assembly instruction = **one** machine code instruction | one statement usually becomes **many** machine code instructions |
| **Ease of use** | hard to write, read and debug; needs detailed knowledge of the hardware | easier and quicker to write, read, debug and maintain |
| **Typical use** | embedded systems, device drivers, controlling specific hardware, code that must be very fast or very small | almost all application software |

**Why most programs are written in high-level languages.** They are **quicker to write** and **easier to understand**, so programmers are more productive and make fewer mistakes. They are **easier to debug and maintain**, so teams can work on the same code for years. They are **portable**: the same program can be translated for different processors instead of being rewritten. And they come with **built-in functions and data structures** (string handling, arrays, records) that would take many lines of low-level code.

### Machine code and assembly language

Both are **low-level**, but they are not the same.

**Machine code** is the binary that the processor executes **directly**. Each type of processor has its own **instruction set**: the set of machine code instructions it understands. Machine code written for one processor family will not run on a different one. It is the **only** language that does **not** need translating.

**Assembly language** replaces each binary instruction with a short, memorable **mnemonic** (such as LDR for load, ADD, STR for store) and lets the programmer write numbers and addresses in a readable form. It has a **1:1 correspondence** with machine code: **each line of assembly becomes exactly one machine code instruction**. Because of this it is still processor-specific. It is often used to develop software for **embedded systems** and to **control specific hardware components**, where the programmer needs exact control.

The same small task in three levels (the assembly and machine code are illustrative, not from a real processor):

High-level (Python):
1. `total = price + tax`

Assembly language:
1. `LDR R0, price`
2. `LDR R1, tax`
3. `ADD R2, R0, R1`
4. `STR R2, total`

Machine code:
1. `0001 0000 0110 0100`
2. `0001 0001 0110 0101`
3. `0110 0010 0000 0001`
4. `0010 0010 0110 0110`

One high-level statement became four assembly instructions, and each assembly instruction became one machine code instruction.

**Advantages and disadvantages of low-level programming** (compared with high level):

| Advantages | Disadvantages |
|---|---|
| Gives **direct control of the hardware**: specific registers, memory addresses and devices | **Hard and slow** to write, read and debug; more chance of errors |
| Programs can be **very efficient**: they can run **faster** and use **less memory**, which matters in small embedded devices | **Not portable**: code is tied to one type of processor and must be rewritten for another |
| Machine code needs **no translation** at all; assembly is translated simply and exactly | Programmer needs **detailed knowledge** of the processor's architecture |
| Useful when no suitable high-level tools exist for a device | No built-in high-level features such as string handling, so programs are much longer |

### Translators

A **translator** converts source code into a form the processor can carry out. There are three common types.

**Compiler.** Translates the **whole** high-level program into **machine code** in one go, **before** it runs, producing an **executable** file.
- The executable runs **quickly**, because translation has already been done.
- Users only need the executable: they **do not need the compiler or the source code**, so the source code can be kept secret.
- Errors are reported for the whole program after compiling, which can make finding them slower during development.
- After **any change** the program must be **recompiled**, and the executable only runs on the type of processor (and operating system) it was compiled for.

**Interpreter.** Translates and runs a high-level program **one statement at a time**.
- An interpreter **does not produce machine code** for the program. For each statement it **calls its own machine code subroutines** to carry it out.
- It **stops at the first error** and shows where it is, so it is convenient while **developing and testing**: you can run and fix code straight away without waiting for a full compile.
- The program runs **more slowly**, because every statement is translated each time it is executed, even inside a loop.
- The **interpreter must be installed** on every computer that runs the program, and the **source code** has to be given out.

**Assembler.** Translates **assembly language** into **machine code**. Each assembly instruction becomes **one** machine code instruction.

| | Compiler | Interpreter | Assembler |
|---|---|---|---|
| Input | high-level source code | high-level source code | assembly language |
| Output | machine code (executable) | no machine code; runs each statement using its own routines | machine code |
| When translated | all at once, before running | statement by statement, while running | all at once, before running |
| Speed of running | fast | slower | fast |
| Best used when | distributing a finished program; speed matters; source code must be protected | developing and testing; learning; running the same code on different platforms | writing embedded or hardware-control software in assembly |

::: terms
- **Low-level language**: a language closely tied to a processor's instruction set: machine code or assembly language.
- **High-level language**: a programming language with English-like keywords that is independent of any one processor, such as Python or C#.
- **Machine code**: binary instructions that a processor can execute directly; specific to a processor or processor family.
- **Instruction set**: the complete set of machine code instructions that a particular type of processor can carry out.
- **Assembly language**: a low-level language using mnemonics, where each instruction corresponds to exactly one machine code instruction.
- **Mnemonic**: a short code word such as ADD or STR used in place of a binary machine code instruction.
- **Translator**: a program that converts source code written in one language into a form that can be executed.
- **Compiler**: a translator that converts a whole high-level program into machine code before it is run.
- **Interpreter**: a translator that runs a high-level program one statement at a time by calling its own machine code subroutines, without producing machine code.
- **Assembler**: a translator that converts assembly language into machine code, one machine code instruction per assembly instruction.
- **Portable**: able to run on different types of processor without being rewritten.
:::

::: method
1. **Identify the language level** from a sample: binary digits = machine code; mnemonics like ADD/LDR with registers = assembly; English-like keywords and variable names = high level.
2. **Compare levels**: always make a **two-sided** comparison ("high-level is …, whereas low-level is …").
3. **Why high level**: quicker to write, easier to read/debug/maintain, portable, built-in features.
4. **Why low level**: direct hardware control, efficient (fast, small), embedded systems.
5. **Translators**: say **what goes in, what comes out, when** it is translated, and the **consequence** (speed, need for the translator, error handling).
6. **Interpreters do not produce machine code**: they call their own subroutines. Never write "translates into machine code line by line".
7. **Scenario questions**: match the translator to the situation (developing → interpreter; selling/distributing → compiler; assembly → assembler) and justify.
:::

::: example Identify languages
A program is shown in three forms. Form P: `ADD R2, R0, R1`. Form Q: `0110 0010 0000 0001`. Form R: `z = x + y`. Identify the type of language used in each form. (2)

P is assembly language, Q is machine code, R is a high-level language (2).

1 mark for one or two correct.
:::

::: example Assembly versus machine code
Explain two differences between assembly language and machine code. (4)

Machine code is written in binary (1), whereas assembly uses mnemonics such as ADD, which are easier for people to read (1).

Machine code can be executed directly by the processor (1), whereas assembly must first be translated into machine code by an assembler (1).
:::

::: example Why high level
Explain why most programs are written in high-level languages. (3)

High-level languages use English-like keywords, so programs are quicker to write and easier to read (1). This makes them easier to debug and maintain (1). They are portable: the same source code can be translated to run on different types of processor instead of being rewritten (1).
:::

::: example Compiler or interpreter for a scenario
A company is developing a game. It will sell the finished game to customers. Explain which translator it should use (a) while developing the game and (b) for the version it sells. (4)

(a) An interpreter (1), because it runs the code straight away and stops at the first error, showing where it is, so programmers can test and fix each part quickly (1).

(b) A compiler (1), because it produces a machine code executable that runs fast, customers do not need a translator installed, and the source code is not given away (1).
:::

::: example Advantage of low level
Explain one reason why a programmer might write the software for a washing machine's controller in assembly language. (2)

Assembly gives direct control over the hardware, such as specific memory addresses and device registers (1), and can produce very small, fast code, which suits an embedded system with limited memory and processing power (1).
:::

---
Each assembly language instruction translates into exactly one machine code instruction (1).

::: q
Explain why machine code written for one processor may not run on a different type of processor. (2)
---
Each type of processor has its own instruction set (1), so the binary instructions written for one may not be recognised/mean something different on another (1).
:::

::: q
State two disadvantages of writing a program in a low-level language. (2)
---
Any two of: hard/slow to write; hard to read and debug; not portable/processor-specific; needs detailed knowledge of the hardware; programs are long (1 each).
:::

::: q
Explain how an interpreter carries out a program. (2)
---
It takes one statement at a time, analyses it and executes it before moving to the next (1), by calling its own machine code subroutines; it does not produce a machine code version of the program (1).
:::

::: q
Explain why a compiled program usually runs faster than the same program run by an interpreter. (2)
---
The translation has all been done before the program runs (1); an interpreter translates each statement every time it is executed, e.g. again on every pass of a loop (1).
:::

::: watch
- **Interpreters do not produce machine code.** They call their own routines for each statement. "Translates into machine code line by line" is marked wrong.
- **Compilers and assemblers** both produce machine code; **assemblers** take assembly language, **compilers** take high-level code.
- Assembly and machine code are **both low level** and **both processor-specific**.
- **Compiled code does not need the source code or the compiler** to run.
- Comparisons need **both sides**: say what one does and what the other does instead.
- In scenario questions, **justify** the translator using the scenario (development vs distribution, speed, protecting code).
:::
