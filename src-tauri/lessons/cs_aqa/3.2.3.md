## What it is

Programs calculate constantly: totals, averages, change, times, positions in a game. The spec lists five arithmetic operations, and the last two, **integer division** and **remainder**, are where most of the exam marks are.

| Operation | AQA pseudo-code | Example | Result |
|---|---|---|---|
| Addition | `+` | `7 + 2` | 9 |
| Subtraction | `-` | `7 - 2` | 5 |
| Multiplication | `*` | `7 * 2` | 14 |
| Real division | `/` | `7 / 2` | 3.5 |
| Integer division (quotient) | `DIV` | `7 DIV 2` | 3 |
| Remainder (modulus) | `MOD` | `7 MOD 2` | 1 |

**Real division** (`/`) gives the full answer, including any fractional part: 11 / 4 = 2.75. The result is a real number even when it divides exactly: 8 / 2 gives 4.0 in many languages.

**Integer division** (`DIV`) gives only the **whole number of times** one number goes into another, throwing away the remainder: 11 DIV 4 = 2, because 4 goes into 11 twice. **Remainder** (`MOD`) gives what is **left over**: 11 MOD 4 = 3, because 2 × 4 = 8 and 11 - 8 = 3. Think of it as a two-stage process, just like short division at primary school:

| Calculation | DIV (whole times) | MOD (left over) | Check: DIV × divisor + MOD |
|---|---|---|---|
| 11 ÷ 2 | 5 | 1 | 5 × 2 + 1 = 11 |
| 17 ÷ 5 | 3 | 2 | 3 × 5 + 2 = 17 |
| 20 ÷ 4 | 5 | 0 | 5 × 4 + 0 = 20 |
| 3 ÷ 8 | 0 | 3 | 0 × 8 + 3 = 3 |
| 125 ÷ 60 | 2 | 5 | 2 × 60 + 5 = 125 |

Notice the last two patterns. When the first number is **smaller** than the second, DIV is 0 and MOD is the first number itself (3 MOD 8 = 3). When it divides **exactly**, MOD is 0.

**In real languages** the symbols differ, so learn yours:

| AQA | Python | C# | VB.NET |
|---|---|---|---|
| `/` real division | `/` | `/` (with a real operand) | `/` |
| `DIV` | `//` | `/` when **both** operands are integers | `\` |
| `MOD` | `%` | `%` | `Mod` |

Watch the C# trap: `7 / 2` in C# gives **3**, not 3.5, because both values are integers. To get 3.5 you write `7.0 / 2` or convert one value to `double` first. In Python, `7 / 2` is always 3.5 and `7 // 2` is 3.

**Order of operations.** Programming languages follow the same order as maths (BIDMAS). **Brackets** come first. Then **multiplication and division**, which includes `DIV` and `MOD`, worked left to right. Then **addition and subtraction**, left to right. So:
- `2 + 3 * 4` is 14, because the multiplication happens first.
- `(2 + 3) * 4` is 20, because the brackets change the order.
- `10 - 4 - 3` is 3, worked left to right.
- `20 MOD 6 + 1` is 3, because MOD (2) is done before the addition.

Use brackets whenever there is any doubt. They cost nothing and make the code clearer. A classic error is calculating a mean as `a + b + c / 3`, which only divides c by 3. It should be `(a + b + c) / 3`.

**What DIV and MOD are used for.** These patterns come up in exam programs again and again:

| Task | Code | Example |
|---|---|---|
| Is n even? | `n MOD 2 = 0` | 14 MOD 2 = 0, so even |
| Is n odd? | `n MOD 2 = 1` (or `≠ 0`) | 15 MOD 2 = 1, so odd |
| Is n a multiple of k? | `n MOD k = 0` | 36 MOD 9 = 0, so yes |
| Minutes to hours and minutes | `hours ← mins DIV 60`, `left ← mins MOD 60` | 135 minutes is 2 h 15 min |
| Last digit of a number | `n MOD 10` | 472 MOD 10 = 2 |
| Remove the last digit | `n DIV 10` | 472 DIV 10 = 47 |
| Tens digit | `(n DIV 10) MOD 10` | (472 DIV 10) MOD 10 = 7 |
| Wrap round a cycle | `(day + 3) MOD 7` | day 5 + 3 → 8 MOD 7 = 1 |
| Full groups and leftovers | `boxes ← items DIV 12`, `spare ← items MOD 12` | 50 eggs: 4 full boxes, 2 spare |

The "wrap round" pattern deserves a closer look. If the days of the week are numbered 0 (Monday) to 6 (Sunday), then 3 days after day 5 (Saturday) is `(5 + 3) MOD 7 = 1`, which is Tuesday. MOD keeps the answer inside the range 0 to 6 however far you count on. The same trick works for the hours on a 24-hour clock (`MOD 24`) and for a player moving round a board of 40 squares (`MOD 40`).

**A worked program.** Converting a number of seconds into hours, minutes and seconds uses DIV and MOD three times. In AQA pseudo-code:
1. `total ← STRING_TO_INT(USERINPUT)`
2. `hours ← total DIV 3600`
3. `remaining ← total MOD 3600`
4. `minutes ← remaining DIV 60`
5. `seconds ← remaining MOD 60`
6. `OUTPUT hours, 'h ', minutes, 'm ', seconds, 's'`

The same program in Python:
1. `total = int(input("Seconds: "))`
2. `hours = total // 3600`
3. `remaining = total % 3600`
4. `minutes = remaining // 60`
5. `seconds = remaining % 60`
6. `print(hours, "h", minutes, "m", seconds, "s")`

With an input of 4000: 4000 DIV 3600 = 1 hour, leaving 400 seconds; 400 DIV 60 = 6 minutes; 400 MOD 60 = 40 seconds. Output: 1 h 6 m 40 s.

::: terms
- **Arithmetic operator**: a symbol that carries out a calculation, such as +, -, *, / , DIV or MOD.
- **Real division**: division that gives the full result including any fractional part, so 7 / 2 = 3.5.
- **Integer division (DIV)**: division that gives only the whole-number part of the result, so 7 DIV 2 = 3.
- **Remainder (MOD)**: the amount left over after integer division, so 7 MOD 2 = 1.
- **Quotient**: the whole-number result of an integer division.
- **Operator precedence**: the order in which operations are carried out: brackets, then multiplication and division (including DIV and MOD), then addition and subtraction.
- **Modular arithmetic**: arithmetic that wraps round after reaching a fixed value, done with MOD, as on a clock.
:::

::: method
1. **Evaluating DIV:** how many **whole** times does the second number go into the first? Never write a decimal.
2. **Evaluating MOD:** subtract (DIV × divisor) from the first number. Check that DIV × divisor + MOD gets you back to the start.
3. **Small first number:** if it is less than the divisor, DIV is 0 and MOD is the number itself.
4. **Precedence:** do brackets first, then `*`, `/`, `DIV`, `MOD` from left to right, then `+` and `-` from left to right.
5. **Choosing the operation in a program:** "how many whole groups?" → DIV; "how many left over?", "is it even?", "is it a multiple?", "wrap round" → MOD; "exact average or price" → real division.
6. **Writing the code:** use your language's symbols (Python `//` and `%`), convert input to a number first, and use brackets round anything that must be calculated before a division.
:::

::: example Evaluate the expressions
State the value of: (a) 23 DIV 5; (b) 23 MOD 5; (c) 23 / 5; (d) 4 MOD 9. (4)

(a) 4: 5 goes into 23 four whole times (1).

(b) 3: 4 × 5 = 20, and 23 - 20 = 3 (1).

(c) 4.6: real division keeps the fraction (1).

(d) 4: 9 goes into 4 zero times, leaving 4 (1).
:::

::: example Precedence
State the value of x after each of these statements.
- (a) `x ← 10 - 2 * 3`
- (b) `x ← (10 - 2) * 3`
- (c) `x ← 17 MOD 5 + 1`
Give all three values. (3)

(a) 4: the multiplication is done first, giving 10 - 6 (1).

(b) 24: the brackets are done first, giving 8 × 3 (1).

(c) 3: MOD is done before addition: 17 MOD 5 = 2, then 2 + 1 (1).
:::

::: example Even or odd
Write a selection statement that outputs 'Even' or 'Odd' for an integer stored in n, and explain how it works. (3)

`IF n MOD 2 = 0 THEN OUTPUT 'Even' ELSE OUTPUT 'Odd' ENDIF`. In Python: `if n % 2 == 0:` (1).

n MOD 2 is the remainder when n is divided by 2 (1).

Even numbers divide exactly by 2, so the remainder is 0; odd numbers always leave a remainder of 1 (1).
:::

::: example Packing problem
A bakery packs cupcakes in boxes of 6. Write the two assignment statements that calculate the number of full boxes and the number of cupcakes left over from `cakes`, and state the results for 50 cakes. (4)

`boxes ← cakes DIV 6` (1).

`left ← cakes MOD 6` (1).

For 50 cakes: 50 DIV 6 = 8 full boxes (1).

50 MOD 6 = 2 cupcakes left over, since 8 × 6 = 48 (1).
:::

::: watch
- **DIV never gives a decimal**: 11 DIV 2 is 5, not 5.5. **MOD gives the remainder**, not the decimal part: 11 MOD 2 is 1, not 0.5.
- When the first number is smaller, **DIV is 0 and MOD is the number itself**: 3 MOD 8 = 3.
- **Precedence**: multiplication and division (DIV and MOD too) before addition and subtraction. Bracket anything that must come first.
- Know your language: Python `//` and `%`; VB.NET `\` and `Mod`; in C#, `/` between two integers **is** integer division.
- An even-number test is `n MOD 2 = 0`, not `n / 2 = 0`.
:::
