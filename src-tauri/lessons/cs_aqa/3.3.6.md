## What it is

A digital photo or icon is stored as a **bitmap**: a grid of tiny squares, each one a single colour, with each colour stored as a binary code. This topic covers what the grid is made of, how big it is, how the colours are coded, how to calculate the file size, and how to turn binary into a picture and back.

**Pixels.** A **pixel** (short for **picture element**) is a **single point** in an image: the smallest element that has its own colour. A bitmap is a rectangular grid of pixels, and a screen displays the image by lighting each of its own pixels in the matching colour. Zoom far into a photo and you see the individual square pixels; at normal size they are too small to notice, so the image looks smooth.

**Image size** is the number of pixels **across** by the number **down**, written **width × height**. A 1920 × 1080 image is 1,920 pixels wide and 1,080 pixels high, so it contains 1920 × 1080 = 2,073,600 pixels. Image size is measured in **pixels**, not in centimetres.

**Colour depth** is the **number of bits used to represent each pixel**. It decides how many different colours each pixel can be:

| Colour depth (bits per pixel) | Number of possible colours | Typical use |
|---|---|---|
| 1 | 2 | black and white |
| 2 | 4 | very simple graphics |
| 4 | 16 | early computer graphics |
| 8 | 256 | simple images, icons |
| 24 | 16,777,216 | photographs ("true colour") |

Each extra bit **doubles** the number of colours: n bits give 2 to the power n colours. Notice that colour depth is the **bits**, not the number of colours: "a colour depth of 256" is wrong; "a colour depth of 8 bits, giving 256 colours" is right.

**How a bitmap represents an image.** The image is divided into a grid of pixels. Each pixel's colour is given a binary code that is **colour-depth bits long**. The codes are stored **in order**, usually row by row from the top left, so the file is one long string of bits; knowing the width tells the computer where each row ends. With a colour depth of 1 bit, a 1 might mean black and a 0 white. With 2 bits there are four codes, so a **key** is needed, such as:

| Code | Colour |
|---|---|
| 00 | white |
| 01 | black |
| 10 | red |
| 11 | blue |

A row stored as 00011011 would then be four pixels: white, black, red, blue.

**Effect on file size.** Every pixel needs colour-depth bits, so:
- **More pixels** (a bigger image size) means **more** codes to store, so a **bigger file**. Doubling both the width and the height gives **four times** as many pixels and four times the file size.
- **Greater colour depth** means **more bits per pixel**, so a **bigger file**. Changing from 8-bit to 24-bit colour makes the file **three times** as big.
- The benefit is quality: more pixels show more detail, and more colours give more realistic shading. The cost is storage space and the time taken to send the image.

For example, a 24-bit photo reduced to 8-bit colour becomes a third of the size but may show visible bands of colour in a sky; an image scaled from 2000 × 1500 down to 1000 × 750 becomes a quarter of the size but loses fine detail.

**Calculating file size.** AQA uses only the pixels and colour depth (ignore any extra data stored with the file):

| Unit | Formula |
|---|---|
| Size in **bits** | W × H × D |
| Size in **bytes** | (W × H × D) ÷ 8 |

where W is the width in pixels, H is the height in pixels and D is the colour depth in bits.

Worked example: an 800 × 600 image with a colour depth of 24 bits.
- Pixels: 800 × 600 = 480,000.
- Bits: 480,000 × 24 = 11,520,000 bits.
- Bytes: 11,520,000 ÷ 8 = 1,440,000 bytes.
- In larger units (3.3.3): 1,440 kB = 1.44 MB.

Worked example with colours given instead of depth: a 300 × 200 image that can use 16 colours. 16 colours needs 4 bits (2 to the power 4 = 16), so D = 4. Size = 300 × 200 × 4 = 240,000 bits = 30,000 bytes = 30 kB.

**Converting binary into a bitmap.** You are given the width, the colour depth and a bit pattern. Split the bits into rows of (width × depth) bits, then decode each pixel. A 1-bit image, 8 pixels wide, 1 = black (■) and 0 = white (□):

| Binary row | Pixels |
|---|---|
| 11111111 | ■■■■■■■■ |
| 00011000 | □□□■■□□□ |
| 00011000 | □□□■■□□□ |
| 00011000 | □□□■■□□□ |
| 00011000 | □□□■■□□□ |
| 00011000 | □□□■■□□□ |

It is a letter T. In an exam you shade squares on a grid.

**Converting a bitmap into binary.** Go the other way: read each row from left to right and write the code for every pixel. A 6 × 3 image, 1 = black:

| Pixels | Binary row |
|---|---|
| ■□□□□■ | 100001 |
| □■□□■□ | 010010 |
| □□■■□□ | 001100 |

If the colour depth is 2 bits, each pixel becomes **two** bits using the key, so a 6-pixel row becomes 12 bits.

::: terms
- **Pixel**: short for picture element; a single point in an image, the smallest part that has its own colour.
- **Bitmap**: an image stored as a grid of pixels, with each pixel's colour stored as a binary code.
- **Image size**: the dimensions of a bitmap in pixels, written as width × height.
- **Colour depth**: the number of bits used to represent the colour of each pixel.
- **Number of colours**: 2 to the power of the colour depth, e.g. 8 bits give 256 colours.
- **File size (bits)**: width × height × colour depth for a bitmap.
- **File size (bytes)**: width × height × colour depth, divided by 8.
:::

::: method
1. **Write down W, H and D.** If you are given a number of colours, convert it to bits (2 → 1, 4 → 2, 16 → 4, 256 → 8).
2. **Multiply W × H** to get the number of pixels.
3. **Multiply by D** to get bits. **Divide by 8** for bytes, then by 1,000 for kB and again for MB if asked.
4. **Show each step** with its unit; there is usually a mark for the method.
5. **Binary → image:** split the bits into rows of W × D bits, decode each pixel with the key, and shade the grid.
6. **Image → binary:** work row by row, left to right, writing D bits per pixel.
7. **Effect questions:** say what increases (pixels or bits per pixel), that file size increases, and by how much if you can (double, four times).
:::

::: example Calculate a file size
Calculate the file size, in bytes, of a 40 × 25 pixel image with a colour depth of 8 bits. Show your working. (2)

40 × 25 × 8 = 8,000 bits (1).

8,000 ÷ 8 = 1,000 bytes (1).
:::

::: example Colours to colour depth
An image is 500 × 400 pixels and uses 256 colours. Calculate its size in kilobytes. Show your working. (3)

256 colours need a colour depth of 8 bits (1).

500 × 400 × 8 = 1,600,000 bits (1).

1,600,000 ÷ 8 = 200,000 bytes = 200 kB (1).
:::

::: example Effect of changes
A 24-bit image is 1,000 × 800 pixels. Describe the effect on the file size of (a) changing the colour depth to 8 bits; (b) changing the image size to 2,000 × 1,600 pixels. (2)

(a) Each pixel uses a third of the bits, so the file size is divided by 3 (1).

(b) There are twice as many pixels across and twice as many down, so four times as many pixels and the file is four times as big (1).
:::

::: example Binary to image
A 5 × 4 black-and-white image uses 1 for black. Its data is 00100 01110 11111 00100. Draw the image. (2)

| Row | Pixels |
|---|---|
| 00100 | □□■□□ |
| 01110 | □■■■□ |
| 11111 | ■■■■■ |
| 00100 | □□■□□ |

Correct split into rows of 5 (1); all pixels correct, an arrow pointing up (1).
:::

::: example Two-bit image to binary
Using the key 00 = white, 01 = black, 10 = red, 11 = blue, write the binary for a row of four pixels: red, red, white, blue. (2)

10 10 00 11 (2), written as 10100011. 1 mark for three of the four pixels correct.
:::

---

Explain why increasing the colour depth of an image increases its file size. (2)
---
More bits are used to store each pixel (1), and every pixel in the image uses those extra bits, so the total number of bits increases (1).

::: watch
- Colour depth is **bits per pixel**, not the number of colours. 256 colours means a depth of **8**.
- Use **W × H × D** for bits, then **÷ 8** for bytes. Don't forget the ÷ 8 when bytes are asked for.
- Doubling **both** width and height makes the file **four** times bigger, not twice.
- When decoding binary, split into rows of **width × depth** bits.
- With a colour depth above 1, each pixel needs **several** bits: use the key for every pixel.
- AQA calculations use only pixels and colour depth: don't add anything for headers or metadata.
:::

::: test
An artist reduces the colour depth of a 24-bit image to 8 bits and halves both its width and its height. Calculate how many times smaller the new file is, and explain one effect on the image. (3)
---
Colour depth: 24 to 8 divides by 3 (1); halving width and height divides the pixels by 4 (1); so the file is 12 times smaller, with an effect such as fewer colours so shading is less realistic / less detail because there are fewer pixels (1).
:::

::: test
Explain why a 1-bit colour depth is suitable for a scanned page of black text but not for a photograph. (3)
---
1 bit gives only two colours (1), which is enough for black text on a white page and keeps the file small (1); a photograph has many shades and colours, which would all be forced to black or white, so it would look unrealistic (1).
:::
