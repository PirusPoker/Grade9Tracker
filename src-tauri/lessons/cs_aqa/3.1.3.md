## What it is

A **search algorithm** finds whether a value (the **target**) is in a list, and usually where it is. AQA names two: **linear search** and **binary search**. You need to know the **mechanics** of each, step by step, be able to carry each out by hand, and compare them.

**Linear search** checks the items **one at a time, in order**:
1. Start at the first item (index 0).
2. Compare it with the target. If they match, the item has been found: stop and report its position.
3. If not, move on to the next item.
4. Repeat until the target is found or there are no items left. If you reach the end, the target is not in the list.

Linear search works on **any list, sorted or unsorted**. It is simple to write. But it can be slow: if the list has 1,000 items and the target is last, or missing, it makes **1,000 comparisons**.

In AQA pseudo-code, a linear search that stops as soon as it finds the target:
1. `found ← False`
2. `i ← 0`
3. `WHILE found = False AND i < LEN(items)`
4. `    IF items[i] = target THEN`
5. `        found ← True`
6. `    ELSE`
7. `        i ← i + 1`
8. `    ENDIF`
9. `ENDWHILE`
10. `IF found THEN`
11. `    OUTPUT 'Found at position ', i`
12. `ELSE`
13. `    OUTPUT 'Not found'`
14. `ENDIF`

The same in Python:
1. `found = False`
2. `i = 0`
3. `while not found and i < len(items):`
4. `    if items[i] == target:`
5. `        found = True`
6. `    else:`
7. `        i = i + 1`

**Binary search** only works on a list that is **already sorted** (in numerical or alphabetical order). It keeps **halving** the part of the list that could still contain the target:
1. Set `low` to the first index and `high` to the last index.
2. Find the middle position: `mid ← (low + high) DIV 2`.
3. Compare the item at `mid` with the target.
   - If it is the target, stop: found.
   - If the target is **smaller**, it can only be in the **left half**, so discard the middle item and everything to its right: `high ← mid - 1`.
   - If the target is **larger**, it can only be in the **right half**: `low ← mid + 1`.
4. Repeat from step 2 while `low ≤ high`. If `low` becomes greater than `high`, there is nothing left to search and the target is not in the list.

`DIV` is used so that `mid` is always a whole-number index. With an even number of items there are two middle positions, and `DIV` picks the lower one. Some answers round up instead. Either is accepted, as long as you use the same rule all the way through.

**Worked binary search.** Find 40 in this sorted list:

| index | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|---|---|---|---|---|---|---|---|---|---|
| value | 3 | 8 | 12 | 19 | 25 | 31 | 40 | 47 | 52 |

| low | high | mid | items[mid] | decision |
|---|---|---|---|---|
| 0 | 8 | 4 | 25 | 40 > 25, so low ← 5 |
| 5 | 8 | 6 | 40 | found |

Only **two items are examined**, 25 and 40, where a linear search would have checked 7.

Searching the same list for 10, which is **not there**:

| low | high | mid | items[mid] | decision |
|---|---|---|---|---|
| 0 | 8 | 4 | 25 | 10 < 25, so high ← 3 |
| 0 | 3 | 1 | 8 | 10 > 8, so low ← 2 |
| 2 | 3 | 2 | 12 | 10 < 12, so high ← 1 |
| 2 | 1 | | | low > high: not found |

The items examined were 25, 8 and 12.

Binary search in AQA pseudo-code:
1. `found ← False`
2. `low ← 0`
3. `high ← LEN(items) - 1`
4. `WHILE found = False AND low ≤ high`
5. `    mid ← (low + high) DIV 2`
6. `    IF items[mid] = target THEN`
7. `        found ← True`
8. `    ELSE IF items[mid] < target THEN`
9. `        low ← mid + 1`
10. `    ELSE`
11. `        high ← mid - 1`
12. `    ENDIF`
13. `ENDWHILE`

In Python, line 5 becomes `mid = (low + high) // 2`, line 4 becomes `while not found and low <= high:`, and `ELSE IF` becomes `elif`.

**How many comparisons?** Each binary-search comparison halves what is left, so the number of comparisons grows very slowly:

| Items in list | Linear search, worst case | Binary search, worst case |
|---|---|---|
| 7 | 7 | 3 |
| 15 | 15 | 4 |
| 1,000 | 1,000 | about 10 |
| 1,000,000 | 1,000,000 | about 20 |

**Comparing the two:**

| | Linear search | Binary search |
|---|---|---|
| Data must be sorted? | **No**: works on any list | **Yes**: only works on sorted data |
| Speed on a large list | slow: may check every item | fast: halves the list each time |
| Speed on a small list | fine; the difference is tiny | fine, but the extra complexity gains little |
| Ease of writing | simple | more complex (low, high, mid) |
| Best case | 1 comparison (target first) | 1 comparison (target in the middle) |
| If the data changes often | items can be added anywhere | the list must be kept sorted, which takes time |

Sorting a list just to search it once can take longer than a linear search would have. Binary search pays off when the list is **already sorted**, or when it will be **searched many times**.

::: terms
- **Searching algorithm**: an algorithm that finds whether a target value is in a list, and usually its position.
- **Target**: the value a search is looking for.
- **Linear search**: checking each item in a list in turn, from the start, until the target is found or the end is reached.
- **Binary search**: searching a sorted list by repeatedly examining the middle item and discarding the half that cannot contain the target.
- **Midpoint**: the middle position of the part of the list still being searched, calculated as (low + high) DIV 2.
- **Sorted list**: a list in numerical or alphabetical order, which binary search requires.
- **Worst case**: the situation needing the most comparisons, such as the target being last or missing.
:::

::: method
1. **"Explain how linear search works":** start at the first item; compare each item with the target in turn; stop when found; or report not found after the last item. One mark per step.
2. **"Explain how binary search works":** the list must be sorted; examine the middle item; if it is the target, stop; if the target is smaller, discard the middle and the right half (otherwise the left half); repeat on the remaining half until found or no items are left.
3. **"List the items examined":** set up low, high and mid, and calculate `mid ← (low + high) DIV 2` each time. Write down the **value** at each mid, not just the index, unless indexes are asked for.
4. **Update low and high past the middle:** `low ← mid + 1` or `high ← mid - 1`. Do not re-examine the middle item.
5. **"Compare" questions:** make **paired points**: binary needs sorted data but linear does not; binary is faster on large lists because it halves the search each time, while linear may check every item; linear is simpler to code.
6. **Recommend for a scenario:** look at whether the data is sorted, how big it is, and how often it is searched or changed.
:::

::: example Linear search, items examined
Show the items examined when a linear search looks for 'Kim' in the list: 'Ola', 'Ben', 'Kim', 'Raj', 'Ali'. (2)

'Ola' is compared with the target and does not match; then 'Ben' does not match (1).

'Kim' matches, so the search stops after 3 comparisons, reporting position 2. 'Raj' and 'Ali' are never examined (1).
:::

::: example List the items examined in a binary search
The sorted list 2, 5, 9, 14, 20, 26, 33, 41, 48, 57, 63 is stored at indexes 0 to 10. List the items examined when a binary search is used to find 41. Use `mid ← (low + high) DIV 2`. (3)

low = 0, high = 10, mid = 5: 26 is examined; 41 > 26, so low becomes 6 (1).

mid = (6 + 10) DIV 2 = 8: 48 is examined; 41 < 48, so high becomes 7. Then mid = (6 + 7) DIV 2 = 6: 33 is examined; 41 > 33, so low becomes 7 (1).

mid = (7 + 7) DIV 2 = 7: 41 is examined and found. The items examined are 26, 48, 33, 41 (1).
:::

::: example Explain binary search
Explain how a binary search finds an item in a list. (4)

The list must already be sorted, and the search starts by examining the middle item (1).

If the middle item is the target, the search stops (1).

If the target is smaller than the middle item, the middle item and the upper half are discarded; if larger, the middle item and the lower half are discarded (1).

This is repeated on the remaining half until the target is found or there are no items left to search, when the target is not in the list (1).
:::

::: example Recommend a search
A shop keeps a list of 50,000 product codes in numerical order. It is searched thousands of times a day and changed once a week. Explain which search algorithm is more suitable. (3)

Binary search, because the list is already sorted, which binary search requires (1).

The list is large, and binary search halves the items left at each step, so it needs at most about 16 comparisons rather than up to 50,000 (1).

It is searched far more often than it is changed, so keeping it sorted costs little compared with the time saved on every search (1).
:::

::: q
Explain why binary search becomes much faster than linear search as a list gets larger. (2)
---
Each comparison in a binary search halves the number of items left (1), so doubling the list adds only one comparison, whereas a linear search's worst case doubles (1).
:::

::: watch
- **Binary search needs sorted data.** Leaving this out of a "compare" or "explain" answer is the classic missed mark.
- In a binary search, examine the **middle**, then move **past** it with `mid + 1` or `mid - 1`.
- Calculate the midpoint with **DIV**: (5 + 8) DIV 2 = 6. Stick to one rounding rule.
- "List the items examined" means the **values** compared, in order, ending with the target if it is found.
- Linear search does **not** need sorted data, and it is **not** always slower: on a tiny list, or with the target near the start, it can be just as quick.
- "Binary search splits the list in half" is not enough on its own. Say **which half is discarded and why**.
:::
