## What it is

Every program, however big, is built from a small set of **statement types**: **variable declarations**, **constant declarations**, **assignments**, **selection**, **iteration** and **subroutine** calls. This lesson covers the first four, and how they fit together. Iteration (loops) is in 3.2.2b and subroutines in 3.2.10.

**Variables.** A **variable** is a **named location in memory** that holds a value which **can change** while the program runs. A score, a running total or the user's name are all variables. **Declaring** a variable creates it. In C# and VB.NET you state its data type when you declare it. In Python a variable is created the first time a value is assigned to it.

| | AQA pseudo-code | Python | C# | VB.NET |
|---|---|---|---|---|
| Declare and assign | `score ← 0` | `score = 0` | `int score = 0;` | `Dim score As Integer = 0` |

**Assignment** stores a value in a variable. In AQA pseudo-code the arrow `←` means "becomes": `score ← 10` puts 10 into score, replacing whatever was there. The right-hand side is **worked out first**, then stored. That is why `count ← count + 1` makes sense: take the current count, add 1, and store the result back in count. An assignment is **not** an equation. `x ← x + 1` would be impossible in maths, but in a program it is one of the most common lines you will write.

**Constants.** A **constant** is a **named value that cannot change while the program runs**. You set it once, when you declare it. AQA pseudo-code writes constant names in capitals:
1. `CONSTANT VAT_RATE ← 0.2`
2. `CONSTANT MAX_ATTEMPTS ← 3`

In C#: `const double VatRate = 0.2;`. In VB.NET: `Const VAT_RATE As Double = 0.2`. Python has no true constants. By convention, a name in capitals such as `VAT_RATE = 0.2` is treated as a constant, and programmers agree never to change it.

**Why use named constants?** Compare these two versions of the same calculation:
- `total ← price * 1.2`
- `total ← price * (1 + VAT_RATE)`

The second is better, for three reasons:
- **Readability:** the name explains what the value means. A bare 1.2 in the middle of a calculation (a "magic number") says nothing.
- **Easy to update:** if the VAT rate changes, you edit **one line**, the declaration, and every use in the program changes with it. With the number typed in ten places, you might miss one.
- **Safety:** the value **cannot be changed by accident** while the program runs. An attempt to assign to it causes an error, rather than a hidden bug.

**Why use named variables?** Programs need to store values that change: input from the user, totals, counters, results. A name lets you refer to the value wherever it is needed and makes the code readable.

**Meaningful identifiers.** An **identifier** is the name given to a variable, constant or subroutine. Use names that say what the item holds or does: `totalCost`, `numberOfPupils`, `calculateVAT`, not `x`, `n2` or `thing`. Meaningful names:
- make the code **easier to read and understand**, by you later and by other programmers;
- make **errors easier to spot**: `totalCost ← totalCost - discount` is obviously sensible, but `t ← t - d` is not obviously anything;
- make the program **easier to maintain** and update.

Identifiers must follow the language's rules. They cannot contain spaces, cannot start with a digit, and cannot be a reserved word such as `if` or `while`. Common styles are camelCase (`highScore`) and snake_case (`high_score`). Single-letter names are acceptable for loop counters such as `i`, by convention.

**Selection.** Selection lets a program **choose** which statements to run, depending on a **condition** (an expression that is True or False).

A simple `IF`, where the statements run only if the condition is True:
1. `IF temperature > 25 THEN`
2. `    OUTPUT 'Hot day'`
3. `ENDIF`

`IF … ELSE`, choosing between two paths:
1. `IF age ≥ 18 THEN`
2. `    OUTPUT 'Adult ticket'`
3. `ELSE`
4. `    OUTPUT 'Child ticket'`
5. `ENDIF`

`ELSE IF` chains, choosing between several paths. The conditions are checked **in order from the top**, and **only the first True branch runs**:
1. `IF mark ≥ 70 THEN`
2. `    grade ← 'A'`
3. `ELSE IF mark ≥ 50 THEN`
4. `    grade ← 'B'`
5. `ELSE IF mark ≥ 30 THEN`
6. `    grade ← 'C'`
7. `ELSE`
8. `    grade ← 'U'`
9. `ENDIF`

A mark of 75 is also ≥ 50 and ≥ 30, but it gets an 'A', because the first True branch wins. That is why **order matters**: if the `≥ 30` test came first, every mark from 30 up would get a 'C'.

In Python, `ELSE IF` is written `elif` and indentation marks each block:
1. `if mark >= 70:`
2. `    grade = "A"`
3. `elif mark >= 50:`
4. `    grade = "B"`
5. `else:`
6. `    grade = "U"`

C# writes `else if`, with braces round each block. VB.NET writes `ElseIf … Then` and ends with `End If`.

**Nested selection.** An `IF` **inside** another `IF` is **nested selection**. The inner condition is only checked if the outer one is True (or only in the `ELSE` branch, depending on where it sits):
1. `IF gameWon THEN`
2. `    OUTPUT 'You win!'`
3. `    IF score > highScore THEN`
4. `        highScore ← score`
5. `        OUTPUT 'New high score'`
6. `    ENDIF`
7. `ENDIF`

The high-score check only happens when the game has been won. Nesting is useful when the second decision only makes sense after the first. Indentation keeps it readable, and every `IF` needs its own `ENDIF`.

**Combining statement types.** All imperative programs are built from three **combining principles**:
- **Sequence:** statements run one after another, in order.
- **Selection:** a choice of which statements to run, made with `IF`.
- **Iteration:** statements repeated, using a loop (3.2.2b).

Real programs combine them freely: a sequence of assignments, then a loop containing an `IF`, inside which another assignment.

::: terms
- **Variable**: a named location in memory holding a value that can change while the program runs.
- **Constant**: a named value that is set once and cannot change while the program runs.
- **Declaration**: a statement that creates a variable or constant, often stating its data type.
- **Assignment**: a statement that stores a value in a variable, replacing its previous value.
- **Identifier**: the name given to a variable, constant or subroutine.
- **Meaningful identifier**: a name that describes what the item holds or does, such as totalCost.
- **Sequence**: statements carried out one after another in the order they are written.
- **Selection**: choosing which statements to run depending on whether a condition is True or False.
- **Nested selection**: a selection statement placed inside another selection statement.
- **Condition**: an expression that evaluates to True or False, used to control selection and iteration.
:::

::: method
1. **"Explain why a constant is used":** give a benefit **and** say why it helps: "the value is declared once, so if it needs updating it only needs changing in one place, reducing errors". "It doesn't change" alone is not enough.
2. **Variable versus constant:** a variable's value can change while the program runs; a constant's cannot.
3. **Meaningful identifiers:** they make code easier to understand and maintain, especially by other programmers, and make mistakes easier to spot.
4. **Tracing selection:** for an `ELSE IF` chain, test the conditions **from the top** and stop at the **first True** one. For nested IFs, only look inside if the outer condition lets you in.
5. **Writing selection:** put the **most restrictive** condition first in an `ELSE IF` chain (highest grade, or oldest age band), and use `ELSE` for "everything else".
6. **Program-writing questions:** use meaningful names, initialise variables, use constants for fixed values, close every `IF` with `ENDIF` (or correct indentation in Python), and test the boundaries of each condition in your head.
:::

::: example Why use a constant
A program uses the value 0.15 in five different places to calculate a service charge. Explain why the programmer should use a named constant instead. (2)

The constant's name, such as SERVICE_RATE, makes clear what 0.15 means, so the code is easier to read (1).

If the rate changes, it only needs updating in one place, the declaration, rather than in five places where one might be missed (1).
:::

::: example Trace an ELSE IF chain
1. `IF speed > 100 THEN`
2. `    fine ← 300`
3. `ELSE IF speed > 80 THEN`
4. `    fine ← 150`
5. `ELSE IF speed > 70 THEN`
6. `    fine ← 100`
7. `ELSE`
8. `    fine ← 0`
9. `ENDIF`
State the value of fine when speed is (a) 85; (b) 70; (c) 101. (3)

(a) 150: 85 is not > 100, but it is > 80, so line 4 runs and the later tests are skipped (1).

(b) 0: 70 is not > 70, so every condition is False and the ELSE runs (1).

(c) 300: the first condition is True (1).
:::

::: example Nested selection
1. `IF member = True THEN`
2. `    IF visits ≥ 10 THEN`
3. `        OUTPUT 'Free coffee'`
4. `    ELSE`
5. `        OUTPUT 'Stamp added'`
6. `    ENDIF`
7. `ELSE`
8. `    OUTPUT 'Join today'`
9. `ENDIF`
State the output when (a) member is True and visits is 10; (b) member is False and visits is 12. (2)

(a) 'Free coffee': the outer condition is True, and 10 ≥ 10 is True (1).

(b) 'Join today': the outer condition is False, so the inner IF is never checked, whatever the visits (1).
:::

::: example A selection program
Write a program that asks for the number of tickets and outputs the total cost. Tickets cost £12 each, but orders of 10 or more tickets cost £9 each. Use a constant for each price. (5)

Declare the two prices as named constants (1):
1. `CONSTANT FULL_PRICE ← 12`
2. `CONSTANT GROUP_PRICE ← 9`

Take the input (1):
- `tickets ← STRING_TO_INT(USERINPUT)`

Select the right price with the correct boundary, 10 or more (1), and calculate the cost in each branch (1):
- `IF tickets ≥ 10 THEN`
- `    cost ← tickets * GROUP_PRICE`
- `ELSE`
- `    cost ← tickets * FULL_PRICE`
- `ENDIF`

Output the result (1):
- `OUTPUT 'Total: £', cost`
:::

::: watch
- A constant **cannot change while the program runs**. Saying "it never changes" is not enough. Add the benefit: **one place to update**, **readable**, **cannot be changed by mistake**.
- In an `ELSE IF` chain, **only the first True branch runs**. Put the narrowest or highest condition first.
- `x ← x + 1` changes x. It is not a comparison. In Python, `=` assigns and `==` compares.
- Every `IF` needs an `ENDIF` (or correct indentation in Python). Nested IFs need **one each**.
- Use **meaningful names** in your own code. The spec requires examiners to be able to follow your logic.
- Boundaries: "10 or more" is `≥ 10`, not `> 10`.
:::
