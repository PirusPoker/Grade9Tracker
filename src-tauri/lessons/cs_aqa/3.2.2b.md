## What it is

**Iteration** means **repetition**: running the same block of statements again and again. Without it, a program to add up 1,000 numbers would need 1,000 lines. With it, three lines do the job. AQA divides iteration into two kinds, and you must know both, **in theory as well as in code**, even if your language does not support every form.

**Definite (count-controlled) iteration** repeats a **fixed number of times**, known before the loop starts. In AQA pseudo-code this is the `FOR` loop:
1. `FOR i ← 1 TO 5`
2. `    OUTPUT i`
3. `ENDFOR`

This outputs 1, 2, 3, 4, 5. The **loop counter** `i` starts at the first value, goes up by 1 each time, and the loop runs for the last value too: AQA's `FOR` limits are **inclusive**. A `STEP` changes the jump: `FOR i ← 0 TO 20 STEP 5` gives 0, 5, 10, 15, 20, and `FOR i ← 10 TO 1 STEP -1` counts down. AQA pseudo-code can also loop **over each item** of an array or each character of a string: `FOR name IN names` or `FOR ch IN word`. The number of passes is still fixed, by the length of the array or string.

| | AQA pseudo-code | Python | C# | VB.NET |
|---|---|---|---|---|
| 1 to 5 | `FOR i ← 1 TO 5` | `for i in range(1, 6):` | `for (int i = 1; i <= 5; i++)` | `For i = 1 To 5` … `Next` |
| step 2 | `FOR i ← 0 TO 10 STEP 2` | `for i in range(0, 11, 2):` | `for (int i = 0; i <= 10; i += 2)` | `For i = 0 To 10 Step 2` |
| each item | `FOR x IN items` | `for x in items:` | `foreach (int x in items)` | `For Each x In items` |

Python's `range` **stops before** its end value, so `range(1, 6)` gives 1 to 5. This is the most common off-by-one error when turning AQA pseudo-code into Python.

**Indefinite (condition-controlled) iteration** repeats **until a condition changes**. The number of passes is **not known in advance**: it depends on what happens while the program runs, such as what the user types. There are two forms, depending on **where the condition is tested**.

**Condition at the start: `WHILE`.** The condition is checked **before** each pass. If it is False the very first time, the loop body **never runs at all**:
1. `total ← 0`
2. `num ← STRING_TO_INT(USERINPUT)`
3. `WHILE num ≠ 0`
4. `    total ← total + num`
5. `    num ← STRING_TO_INT(USERINPUT)`
6. `ENDWHILE`
7. `OUTPUT total`

If the first input is 0, the body is skipped and 0 is output. A `WHILE` loop keeps going **while** its condition is True.

**Condition at the end: `REPEAT … UNTIL` (and `DO … WHILE`).** The body runs **first**, then the condition is checked. So the body **always runs at least once**:
1. `REPEAT`
2. `    choice ← USERINPUT`
3. `UNTIL choice = 'A' OR choice = 'B'`

`REPEAT … UNTIL` keeps going **until** its condition becomes True. Some languages write the condition at the end the other way round, as `DO … WHILE condition`, which keeps going **while** the condition is True. For example, `DO … WHILE NotSolved` is the same as `REPEAT … UNTIL Solved`. C# has `do { … } while (…);` and VB.NET has `Do … Loop Until …`.

**Python has no condition-at-the-end loop.** You get the same effect with a `while True` loop that `break`s out at the end:
1. `while True:`
2. `    choice = input("A or B? ")`
3. `    if choice == "A" or choice == "B":`
4. `        break`

You still need to understand `REPEAT … UNTIL` for the exam even if you write Python, because AQA's pseudo-code uses it.

**Choosing the right loop:**

| Situation | Best loop | Why |
|---|---|---|
| repeat an exact number of times, e.g. 10 questions | `FOR` | the number of passes is known in advance |
| process every item in an array | `FOR` or `FOR … IN` | the length is known |
| keep reading input until a rogue value, e.g. 0 or -1 | `WHILE` | it may need to run zero times |
| keep asking until input is valid | `REPEAT … UNTIL` | the user must be asked at least once |
| a menu that shows until the user chooses Quit | `REPEAT … UNTIL` | the menu must show at least once |
| a game that continues while lives > 0 | `WHILE` | check before each round |

**Infinite loops.** A condition-controlled loop must **change something that its condition depends on**, or it will never stop. This loop never ends, because `count` never changes:
1. `count ← 0`
2. `WHILE count < 5`
3. `    OUTPUT 'Hello'`
4. `ENDWHILE`

Adding `count ← count + 1` inside the loop fixes it.

**Counters and running totals.** Two patterns appear inside almost every loop:
- A **counter** counts how many times something happens: set `count ← 0` **before** the loop, and do `count ← count + 1` inside it.
- A **running total** adds values up: set `total ← 0` **before** the loop, and do `total ← total + value` inside it.

Setting either one to 0 **inside** the loop resets it on every pass, which is a classic logic error.

**Nested iteration.** A loop inside another loop. The **inner loop runs completely for every single pass of the outer loop**. This prints a 3 × 4 times-table grid:
1. `FOR row ← 1 TO 3`
2. `    line ← ''`
3. `    FOR col ← 1 TO 4`
4. `        line ← line + INT_TO_STRING(row * col) + ' '`
5. `    ENDFOR`
6. `    OUTPUT line`
7. `ENDFOR`

Output: `1 2 3 4`, then `2 4 6 8`, then `3 6 9 12`. Line 4 runs 3 × 4 = 12 times. Loops can be nested inside condition-controlled loops too. AQA's own example is a `FOR` inside a `WHILE NotSolved`. Loops can also contain selection, and selection can contain loops: any statement type can go inside any other.

::: terms
- **Iteration**: repeating a block of statements.
- **Definite iteration**: count-controlled repetition, where the number of passes is fixed before the loop starts, as in a FOR loop.
- **Indefinite iteration**: condition-controlled repetition, where the loop continues until a condition changes, as in WHILE or REPEAT.
- **Loop counter**: the variable in a FOR loop that takes each value in the range in turn.
- **Pre-condition loop**: a loop with its condition at the start (WHILE), whose body may run zero times.
- **Post-condition loop**: a loop with its condition at the end (REPEAT … UNTIL or DO … WHILE), whose body always runs at least once.
- **Nested iteration**: a loop inside another loop, where the inner loop runs fully for each pass of the outer loop.
- **Infinite loop**: a loop whose condition never becomes false (or true, for UNTIL), so it never stops.
- **Running total**: a variable that has each new value added to it inside a loop.
- **Counter**: a variable increased by 1 inside a loop to count how many times something happens.
:::

::: method
1. **"What type of iteration is this?":** `FOR` is **definite / count-controlled**. `WHILE` and `REPEAT … UNTIL` are **indefinite / condition-controlled**. Then say where the condition is: at the start (WHILE) or at the end (REPEAT).
2. **"State the difference between WHILE and REPEAT":** WHILE tests **before** each pass so it may run **zero** times; REPEAT tests **after** each pass so it always runs **at least once**.
3. **Count FOR passes carefully:** both limits are included. 1 TO 10 is 10 passes; 0 TO 10 is 11; 2 TO 10 STEP 2 is 5.
4. **Writing a condition-controlled loop:** set up the variable the condition uses **before** the loop (or read the first input), and **update it inside** the loop. Otherwise the loop is infinite.
5. **Writing a validation loop:** use REPEAT … UNTIL valid, or in Python `while` with the input repeated inside, and output an error message for invalid input.
6. **Running totals and counters:** initialise them **before** the loop, update them **inside**, and use them **after** the loop finishes.
7. **Nested loops:** trace the inner loop to completion for each outer value, and multiply passes to count how often the innermost line runs.
:::

::: example Count the passes
State how many times each loop body runs: (a) `FOR i ← 1 TO 10`; (b) `FOR i ← 0 TO 10`; (c) `FOR i ← 3 TO 15 STEP 3`. (3)

(a) 10: i takes 1, 2, …, 10 (1).

(b) 11: i takes 0 to 10, and both ends count (1).

(c) 5: i takes 3, 6, 9, 12 and 15 (1).
:::

::: example WHILE versus REPEAT
Explain the difference between a WHILE loop and a REPEAT … UNTIL loop. (2)

A WHILE loop checks its condition at the start, before each pass, so if the condition is False at first the body never runs (1).

A REPEAT … UNTIL loop checks its condition at the end, after each pass, so the body always runs at least once (1).
:::

::: example Choose a loop
A program asks the user for a PIN and keeps asking until a 4-digit PIN is entered. State the most suitable type of loop and justify your choice. (2)

A REPEAT … UNTIL loop (condition-controlled, with the condition at the end) (1).

The user must be asked at least once, and the number of attempts is not known in advance (1).
:::

::: example Convert FOR to WHILE
Rewrite `FOR i ← 1 TO 5` / `OUTPUT i * 2` / `ENDFOR` using a WHILE loop, so that the output is the same. (3)

Initialise the counter before the loop (1):
1. `i ← 1`
2. `WHILE i ≤ 5`

Inside the loop, do the output and then increase the counter, or the loop never ends (1):
- `    OUTPUT i * 2`
- `    i ← i + 1`
- `ENDWHILE`

The condition must be `≤ 5`, not `< 5`, to include the last pass (1).
:::

::: example A running-total program
Write a program that keeps asking the user for the price of an item until they enter 0, then outputs the number of items and the total price. (5)

Initialise the total and the counter before the loop (1), and read the first price (1):
1. `total ← 0`
2. `count ← 0`
3. `price ← STRING_TO_REAL(USERINPUT)`

Use a condition-controlled loop that stops at 0 (1). Inside it, update the total and counter, then read the next price (1):
- `WHILE price ≠ 0`
- `    total ← total + price`
- `    count ← count + 1`
- `    price ← STRING_TO_REAL(USERINPUT)`
- `ENDWHILE`

Output both results after the loop (1):
- `OUTPUT count, ' items, total £', total`

::: watch
- **REPEAT always runs at least once; WHILE may not run at all.** That is the answer to "the difference".
- `REPEAT … UNTIL` stops when its condition becomes **True**; `WHILE` stops when its condition becomes **False**. Do not mix them up when converting.
- AQA `FOR` limits are **inclusive**. Python's `range` **excludes** the end, so `range(1, 6)` is 1 to 5.
- Initialise totals and counters **before** the loop. Resetting them inside the loop is a logic error.
- Every condition-controlled loop must **update** what its condition tests, or it is infinite.
- Definite = count-controlled = FOR. Indefinite = condition-controlled = WHILE / REPEAT. Use the spec words.
:::
