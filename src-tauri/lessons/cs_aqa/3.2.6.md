## What it is

A **data structure** is an organised way of storing **several related items of data under one name**, so a program can work with them together. A shopping list, a class register, a seating plan and a contact card are all everyday data structures. Without them, a program storing 30 pupils' marks would need 30 separate variables, `mark1` to `mark30`, and a separate line of code for each one. With an array, one name and one loop handle all 30. AQA requires two kinds: **arrays** (one- and two-dimensional) and **records**.

**One-dimensional arrays.** An array stores a **collection of items**, usually of the **same data type**, under one identifier. Each item (an **element**) is reached by its **index**: its position, **counting from 0**.
1. `scores ← [12, 7, 15, 9]`
2. `OUTPUT scores[0]`
3. `scores[2] ← 20`
4. `OUTPUT LEN(scores)`

Line 2 outputs 12, the **first** element. Line 3 replaces 15 with 20. Line 4 outputs 4, the number of elements. The indexes run from 0 to 3, so the **last index is always LEN − 1**. `scores[4]` does not exist, and trying to use it causes an error.

| index | 0 | 1 | 2 | 3 |
|---|---|---|---|---|
| scores | 12 | 7 | 20 | 9 |

Arrays are usually **fixed in size** once created, and every element has the same type. Python's **lists** play the part of arrays and are more flexible: they can grow with `append` and can mix types. In the exam, treat a Python list as an array. C# writes `int[] scores = {12, 7, 15, 9};` and VB.NET writes `Dim scores() As Integer = {12, 7, 15, 9}`. VB.NET uses round brackets for indexes: `scores(0)`.

**Processing an array with a loop.** Arrays and FOR loops go together. The loop counter becomes the index:
1. `total ← 0`
2. `highest ← scores[0]`
3. `FOR i ← 0 TO LEN(scores) - 1`
4. `    total ← total + scores[i]`
5. `    IF scores[i] > highest THEN`
6. `        highest ← scores[i]`
7. `    ENDIF`
8. `ENDFOR`
9. `OUTPUT total, highest`

This totals the array and finds the largest value in one pass. When you only need the values and not their positions, `FOR s IN scores` is simpler. In Python, `for i in range(len(scores)):` loops over the indexes and `for s in scores:` over the values.

**Two-dimensional arrays.** A 2D array is a **grid** (a table) of elements, with **rows and columns**. In AQA pseudo-code it is an array of arrays, and an element is reached with **two indexes: `[row][column]`**, both from 0. This array holds the noon temperature in 3 towns (rows) on 4 days (columns):
1. `temps ← [[12, 15, 11, 14], [9, 10, 8, 7], [14, 18, 16, 15]]`

| | col 0 | col 1 | col 2 | col 3 |
|---|---|---|---|---|
| **row 0** | 12 | 15 | 11 | 14 |
| **row 1** | 9 | 10 | 8 | 7 |
| **row 2** | 14 | 18 | 16 | 15 |

`temps[1][2]` is row 1, column 2, which is **8**. `temps[2][1]` is **18**. `LEN(temps)` is 3, the number of rows, and `LEN(temps[0])` is 4, the length of one row. Python lists of lists use exactly the same `temps[1][2]` notation. C# uses `temps[1, 2]` and VB.NET uses `temps(1, 2)`.

To visit every element, use **nested loops**: the outer loop picks a row and the inner loop walks across its columns. This outputs each town's total:
1. `FOR row ← 0 TO 2`
2. `    total ← 0`
3. `    FOR col ← 0 TO 3`
4. `        total ← total + temps[row][col]`
5. `    ENDFOR`
6. `    OUTPUT 'Town ', row, ': ', total`
7. `ENDFOR`

The output is 52, 34 and 63. Notice that `total ← 0` sits **inside** the outer loop, so each town starts from zero. To total each **column** (each day) instead, swap the loops: column on the outside, row on the inside.

**Records.** An array holds **many items of the same type**. A **record** holds **several items of different types about one thing**. Each item in a record is a **field**, with its own name and data type. In AQA pseudo-code, you first **define** the record type, then **create** records of that type:
1. `RECORD Book`
2. `    title : String`
3. `    author : String`
4. `    price : Real`
5. `    pages : Integer`
6. `    inStock : Boolean`
7. `ENDRECORD`
8. `b ← Book('Holes', 'L. Sachar', 7.99, 272, True)`
9. `OUTPUT b.title`
10. `b.price ← 6.49`

A field is reached with a **dot**: `b.title` is 'Holes'. Line 10 changes one field and leaves the others as they were. The values in line 8 must be given in the same order as the fields in the definition.

Python has no `RECORD` keyword. The usual stand-ins are a **class** or a **dictionary**. With a dictionary, `b = {"title": "Holes", "price": 7.99}` and `b["price"] = 6.49`. With a class, the fields are attributes, `b.price = 6.49`, which matches AQA's dot notation. C# and VB.NET have a `struct` / `Structure`, or a class. Whichever you use, the idea is the same: named fields of different types grouped as one item.

**Arrays of records.** The most useful structure of all combines the two: an array where **each element is a record**, like the rows of a table where each row describes one item:
1. `books ← [Book('Holes', 'L. Sachar', 7.99, 272, True), Book('Wonder', 'R. J. Palacio', 8.99, 320, False)]`
2. `FOR bk IN books`
3. `    IF bk.inStock THEN`
4. `        OUTPUT bk.title, ' £', bk.price`
5. `    ENDIF`
6. `ENDFOR`

`books[1].title` is 'Wonder': first choose the record with its index, then the field with a dot.

**Choosing a structure:**

| Data | Structure |
|---|---|
| 30 test marks | 1D array of integers |
| marks for 30 pupils in 5 tests | 2D array (30 rows × 5 columns) |
| one pupil's name, date of birth, form and whether they have free meals | a record |
| the details of every pupil in the school | an array of records |
| a noughts-and-crosses board | a 3 × 3 2D array of characters |

::: terms
- **Data structure**: an organised way of storing a collection of related data items under one name so they can be processed together.
- **Array**: a data structure holding a number of elements, usually of the same data type, accessed by an index.
- **Element**: one item stored in an array.
- **Index**: the position of an element in an array, counting from 0.
- **One-dimensional array**: an array whose elements form a single list, accessed by one index.
- **Two-dimensional array**: an array whose elements form a grid of rows and columns, accessed by two indexes, [row][column].
- **Record**: a data structure grouping several related fields, which can be of different data types, about one item.
- **Field**: one named item of data within a record, with its own data type.
- **Array of records**: an array in which each element is a record, like the rows of a table.
:::

::: method
1. **Index questions:** count from **0**. For `a[3]`, count 0, 1, 2, 3 along the array. For `t[r][c]`, find the row **first**, then the column.
2. **Looping over an array:** `FOR i ← 0 TO LEN(arr) - 1`, never `TO LEN(arr)`. Use `FOR x IN arr` when you do not need the index.
3. **2D arrays:** nested loops, outer for rows and inner for columns. Reset a per-row total **inside** the outer loop.
4. **Records:** define the fields with their types; create a record with values in the field order; access and change fields with `record.field`.
5. **Arrays of records:** `arr[i].field`. Loop over the array, then test or output a field of each record.
6. **"Why use an array/record" questions:** an array lets one name and one loop handle many values, instead of many variables and repeated code. A record keeps related data of different types together as one item.
:::

::: example Read and change a 1D array
`names ← ['Ali', 'Bea', 'Cal', 'Dee', 'Eve']`. State (a) the value of `names[3]`; (b) the value of `LEN(names)`; (c) a statement that changes 'Bea' to 'Ben'. (3)

(a) 'Dee': index 3 is the fourth element (1).

(b) 5 (1).

(c) `names[1] ← 'Ben'` (1).
:::

::: example Read a 2D array
`grid ← [[3, 8, 1], [6, 2, 9], [4, 7, 5]]`. State the values of (a) `grid[0][2]`; (b) `grid[2][0]`; (c) `grid[1][1] + grid[2][1]`. (3)

(a) 1: row 0 is [3, 8, 1], and column 2 of it is 1 (1).

(b) 4: row 2 is [4, 7, 5], and column 0 of it is 4 (1).

(c) 9: grid[1][1] is 2 and grid[2][1] is 7 (1).
:::

::: example Define and use a record
A gym stores, for each member, their name, age, monthly fee and whether they have paid. Write a record definition, create a record for Sam, aged 34, paying £25.50 who has paid, and write a statement to record that Sam's fee has gone up to £27. (4)

Define the record with suitable field names and types (2):
1. `RECORD Member`
2. `    name : String`
3. `    age : Integer`
4. `    fee : Real`
5. `    paid : Boolean`
6. `ENDRECORD`

Create the record with the values in field order (1):
- `m ← Member('Sam', 34, 25.50, True)`

Update one field with dot notation (1):
- `m.fee ← 27`
:::

::: example Totals in a 2D array
`sales` is a 2D array with 4 rows (shops) and 7 columns (days). Write an algorithm that outputs the total sales for each shop. (4)

Use an outer loop over the shops (rows), 0 to 3 (1), and reset the total for each shop inside it (1):
1. `FOR shop ← 0 TO 3`
2. `    total ← 0`

An inner loop over the days (columns), 0 to 6, adds each element (1):
- `    FOR day ← 0 TO 6`
- `        total ← total + sales[shop][day]`
- `    ENDFOR`

Output the total after the inner loop, inside the outer loop (1):
- `    OUTPUT total`
- `ENDFOR`
:::

::: watch
- Arrays start at **index 0**. The last index is **LEN − 1**. Looping `TO LEN(arr)` goes one past the end.
- In `t[r][c]`, the **row comes first**. Check which dimension the question calls rows.
- Reset per-row totals **inside** the outer loop, or every row's total includes the rows before it.
- A record groups **different types about one thing**. An array groups **many items of one type**. Do not swap the definitions.
- Use **dot notation** for fields: `m.fee ← 27`, and `arr[i].field` for an array of records.
- In Python, say that your list stands for an array, and your class or dictionary for a record.
:::

::: test
`stock` is an array of records. Each record has the fields `name : String`, `qty : Integer` and `price : Real`. Write an algorithm, in pseudo-code or program code, that outputs the name of every item with a quantity below 5, and then outputs the total value (quantity × price) of all the stock. (4)
---
Example (pseudo-code):
1. `total ← 0`
2. `FOR item IN stock`
3. `    IF item.qty < 5 THEN`
4. `        OUTPUT item.name`
5. `    ENDIF`
6. `    total ← total + item.qty * item.price`
7. `ENDFOR`
8. `OUTPUT total`
Mark points:
- A. Loop through every record in the array (1).
- B. Correct test of the qty field and the name output (1).
- C. Value of each item calculated using two fields (1).
- D. Running total initialised and output after the loop (1).
Accept index-based access, e.g. `stock[i].qty`, and Python, C# or VB.NET.
:::

::: test
A cinema stores its seats in a 2D array `seats` with 10 rows (0 to 9) and 12 seats per row (0 to 11). Each element is True if the seat is booked and False if it is free. Write a program, in pseudo-code or program code, that:
- counts the number of free seats in each row and outputs the row number with its count;
- outputs the total number of free seats in the cinema;
- outputs 'Sold out' if there are no free seats. (6)
---
Example answer (Python):
1. `total_free = 0`
2. `for row in range(10):`
3. `    free = 0`
4. `    for seat in range(12):`
5. `        if seats[row][seat] == False:`
6. `            free = free + 1`
7. `    print("Row", row, "has", free, "free")`
8. `    total_free = total_free + free`
9. `print("Total free:", total_free)`
10. `if total_free == 0:`
11. `    print("Sold out")`
Mark points:
- A. Outer loop over all 10 rows (0 to 9) (1).
- B. Inner loop over all 12 seats (0 to 11) (1).
- C. Element accessed as [row][seat] and tested for being free (1).
- D. Row count reset for each row and output with the row number (1).
- E. Overall total accumulated and output after the loops (1).
- F. 'Sold out' output only when the total is 0 (1).
Accept AQA pseudo-code, C# (`seats[row, seat]`) or VB.NET equivalents.
:::
