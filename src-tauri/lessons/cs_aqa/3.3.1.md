## What it is

A **number base** is the number of different digits a counting system uses, and so the value each column is worth. You already use **base 10**. Computer science needs two more: **base 2** (binary), which is what computers actually store, and **base 16** (hexadecimal), a shorthand that people use to read and write binary. When a number could be read in more than one base, the base is written as a small subscript: 11₁₀ is eleven, 11₂ is three, 11₁₆ is seventeen.

**Decimal (base 10)** uses ten digits, 0 to 9. Each column is worth **10 times** the column to its right:

| Thousands | Hundreds | Tens | Units |
|---|---|---|---|
| 1000 | 100 | 10 | 1 |

So 254₁₀ means 2 hundreds + 5 tens + 4 units. When a column reaches 9 and you add one, it resets to 0 and you carry 1 to the next column.

**Binary (base 2)** uses only two digits, **0 and 1**. Each binary digit is a **bit**. Each column is worth **2 times** the one to its right. For 8 bits (one byte), the column values are:

| 128 | 64 | 32 | 16 | 8 | 4 | 2 | 1 |
|---|---|---|---|---|---|---|---|
| 0 | 1 | 0 | 0 | 1 | 1 | 0 | 1 |

That pattern is 64 + 8 + 4 + 1 = 77. The right-hand bit (worth 1) is the **least significant bit**; the left-hand bit (worth 128) is the **most significant bit**. Eight bits can hold 256 different patterns, the values **0 to 255**. Counting in binary goes 0, 1, 10, 11, 100, 101, 110, 111, 1000, …: each column flips back to 0 and carries as soon as it passes 1.

**Hexadecimal (base 16)** needs sixteen digits. It uses 0 to 9, then the letters **A to F** for the values ten to fifteen:

| Hex digit | 0–9 | A | B | C | D | E | F |
|---|---|---|---|---|---|---|---|
| Decimal value | 0–9 | 10 | 11 | 12 | 13 | 14 | 15 |

Each column is worth **16 times** the one to its right, so a two-digit hex number has a **sixteens** column and a **units** column. 2F₁₆ is 2 sixteens + 15 units = 47. The largest two-digit hex number, FF, is 15 × 16 + 15 = 255, the same as the largest 8-bit binary number. (How to convert in every direction is the next topic, 3.3.2.)

**Why computers use binary.** A computer's processor and memory are built from billions of tiny electronic switches (transistors) that are either **on or off**. Two states map neatly onto the two digits 1 and 0, and a circuit only has to tell two states apart, which makes it reliable. So **all data and all program instructions** are stored and processed in binary: numbers, letters, images, sounds, videos and the machine-code instructions the CPU carries out are all, in the end, patterns of bits.

**A bit pattern means nothing on its own.** The same 8 bits can stand for completely different things depending on how a program **interprets** them. Take 01000001:

| Interpreted as | Meaning |
|---|---|
| An unsigned integer | the number 65 |
| A character (ASCII / Unicode code, 3.3.5) | the letter 'A' |
| Part of a black-and-white bitmap (3.3.6) | a row of 8 pixels: white, black, then five white, then black (if 1 means black) |
| A sound sample (3.3.7) | one amplitude measurement |
| A machine-code instruction | an operation for the CPU to carry out |

The computer does not label the data; the **program** using it decides what it represents. That is why opening an image file in a text editor shows gibberish: the same bits are being read as characters.

**Why hexadecimal is used.** Computers never store or process hex: everything inside is binary. Hex exists **for people**. Its advantages:
- It is **shorter**: one hex digit stands for exactly **four bits** (a **nibble**), so a byte is two hex digits. 1101 0110 becomes D6.
- It is **easier for humans to read, write and remember** than long strings of 0s and 1s.
- People make **fewer mistakes** copying or typing two hex digits than eight bits.
- It is **quick to convert to and from binary**, much quicker than converting decimal, because each hex digit maps directly onto a group of four bits.

You meet hex wherever people need to see the bits behind something:
- **Colour codes** in web pages and graphics software, such as #FF0000 for pure red: two hex digits each for red, green and blue.
- **MAC addresses** that identify network hardware, written as six pairs of hex digits.
- **Memory addresses** and **error codes** shown to programmers.
- Looking at the raw contents of a file or of memory when debugging.

The mark that is lost every year: hex does **not** save storage space or make processing faster. The data is still stored as binary whatever notation a person uses to write it down.

::: terms
- **Number base**: the number of different digits a number system uses; each column is worth the base times the column to its right.
- **Decimal**: base 10, the number system with digits 0 to 9 and column values 1, 10, 100 and so on.
- **Binary**: base 2, the number system with digits 0 and 1 and column values 1, 2, 4, 8, 16 and so on.
- **Hexadecimal**: base 16, the number system with digits 0 to 9 and A to F, where A to F stand for 10 to 15.
- **Bit**: a single binary digit, 0 or 1.
- **Nibble**: a group of four bits, which is exactly one hexadecimal digit.
- **Bit pattern**: a sequence of bits whose meaning depends on how a program interprets it.
- **Most significant bit**: the left-hand bit of a binary number, which has the largest place value.
:::

::: method
1. **Identify the base** from the digits or subscript: only 0/1 suggests binary; any of A to F means hex.
2. **Write the column values** above the digits: 128 … 1 for binary, 16 and 1 for two-digit hex, 100, 10, 1 for decimal.
3. **For "why binary"**: two-state switches (on/off), so all data and instructions are stored as 0s and 1s.
4. **For "what does this bit pattern represent"**: say it depends on how the program interprets it, and give two or more different meanings.
5. **For "why hex"**: give a human benefit (shorter, easier to read, fewer errors) **and** the link to binary (one digit per 4 bits, easy to convert).
6. **Never** say hex uses less memory or is faster for the computer.
:::

::: example Place values
State the value of the digit 1 in each of these numbers, in decimal: (a) 100₂; (b) 100₁₆; (c) 10₁₆. (3)

(a) 4: the third binary column is worth 4 (1).

(b) 256: the third hex column is worth 16 × 16 (1).

(c) 16: the second hex column is worth 16 (1).
:::

::: example One pattern, many meanings
A memory location holds the bit pattern 01000010. Explain why it is not possible to say what this data represents without more information. (2)

A bit pattern has no meaning on its own; its meaning depends on how the program using it interprets it (1). For example, it could be the integer 66, the character 'B', part of an image or a machine-code instruction (1).
:::

::: example Why hexadecimal
A web designer sees colours written as hex codes such as #3A7FC2 rather than as 24-bit binary numbers. Explain two reasons why hexadecimal is used. (4)

Hex is much shorter, with six digits instead of 24 bits (1), so it is easier for the designer to read, remember and type (1).

Each hex digit represents exactly four bits (1), so it is quick and simple to convert to and from the binary the computer actually stores, and fewer mistakes are made than when copying binary (1).
:::

::: example Spot the false claim
A student writes: "Programs store data in hex because it takes up less memory than binary." Explain why the student is wrong. (2)

The computer always stores data as binary; hex is only a way of writing it for humans (1), so it uses exactly the same amount of memory / makes no difference to processing (1).
:::

::: example Why binary
Explain why computers use binary to represent data and instructions. (2)

Computers are built from switches / transistors that have only two states, on and off (1); these two states map directly to the digits 1 and 0, so all data and instructions must be represented using binary (1).
:::

::: watch
- Hex is used **by people**. Answers saying hex "saves memory", "is faster" or "is what computers use" score **nothing**.
- A "why hex" answer needs a **reason and its effect**: "shorter, **so** easier to read and fewer errors"; "one digit per 4 bits, **so** easy to convert".
- The hex letters are **A = 10 to F = 15**. There is no G, and 16 is written 10₁₆.
- A bit pattern's meaning depends on the **program interpreting it**; give examples of at least two meanings.
- 8 bits store **256** values, but the largest is **255** because 0 is one of them.
:::

::: test

---
Explanation (max 3): 7E is two characters instead of eight bits, so it is quicker and easier for the programmer to read (1); less likely to be misread or miscopied (1); each hex digit corresponds to exactly four bits, so the programmer can still see the underlying binary easily (1); hex is only for display, the computer still stores binary (1).
Binary: 0111 1110 (1).

::: test
Explain why 8-bit binary and two-digit hexadecimal can represent exactly the same range of values. (3)
---
8 bits can be split into two groups of four bits / nibbles (1); each nibble has 16 possible patterns, the same as the 16 hex digits 0 to F (1); so both represent 0 to 255 / 256 values, with FF = 1111 1111 = 255 (1).
:::

::: test
Explain the difference between decimal, binary and hexadecimal in terms of the digits used and the column values. (3)
---
Decimal uses digits 0–9 and each column is worth 10 times the one to its right (1). Binary uses digits 0 and 1 and each column is worth 2 times the one to its right (1). Hexadecimal uses 0–9 and A–F and each column is worth 16 times the one to its right (1).
:::
