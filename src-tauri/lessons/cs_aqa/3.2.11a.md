## What it is

Users make mistakes, and some users try to misuse a program on purpose. A **robust** program keeps working sensibly whatever it is given: it does not crash, loop forever or produce nonsense when someone types a blank, a letter instead of a number, or a silly value. A **secure** program only lets the right people in. Paper 1 tests both by asking you to **write** short routines: **validation routines**, which check that input is sensible, and **authentication routines**, which check who the user is.

**Validation** is an automatic check, made by the program, that input data is **sensible and allowed** before it is used. It does **not** prove the data is correct: an age of 14 passes a range check of 11 to 18 even if the user is really 15. The spec names three simple checks you must be able to write:

| Check | What it tests | Example rule | AQA pseudo-code condition for *invalid* data |
|---|---|---|---|
| **Presence** (empty string) | Something has been entered | Name must not be blank | `name = ''` |
| **Length** (minimum length) | The string has enough characters | Password at least 8 characters | `LEN(pw) < 8` |
| **Range** | A number lies between two limits | Rating 1 to 10 | `rating < 1 OR rating > 10` |

Other checks exist and can be used where a question needs them: a **maximum length**, a **format** check (e.g. a code of two letters then four digits, using character codes from 3.2.8), a **type** check (is the input a number?), and a **lookup** check (is the input one of a list of allowed values?).

**Writing the range condition.** Valid data is `rating ≥ 1 AND rating ≤ 10`. Invalid data is the opposite: `rating < 1 OR rating > 10`. Mixing these up (writing `rating < 1 AND rating > 10`, which can never be true) is a very common logic error.

**A validation loop** re-prompts until the input is valid, so the program never continues with bad data. Two common shapes:

*Check, then loop while invalid (WHILE):*
1. `rating ← STRING_TO_INT(USERINPUT)`
2. `WHILE rating < 1 OR rating > 10`
3. `    OUTPUT 'Must be 1 to 10. Try again.'`
4. `    rating ← STRING_TO_INT(USERINPUT)`
5. `ENDWHILE`

*Ask, then repeat until valid (REPEAT … UNTIL):*
1. `REPEAT`
2. `    name ← USERINPUT`
3. `    IF name = '' THEN`
4. `        OUTPUT 'Name cannot be blank'`
5. `    ENDIF`
6. `UNTIL name ≠ ''`

The WHILE version needs the input **twice** (once before the loop, once inside). The REPEAT version needs it once, because the body always runs at least once. Both are fine in an exam. A plain IF is **not** a validation loop: it complains once and then carries on with the bad value.

**Combining checks.** A password that must be at least 8 characters, and a username that must not be blank:
1. `REPEAT`
2. `    user ← USERINPUT`
3. `UNTIL LEN(user) > 0`
4. `pw ← USERINPUT`
5. `WHILE LEN(pw) < 8`
6. `    OUTPUT 'Password too short'`
7. `    pw ← USERINPUT`
8. `ENDWHILE`

In Python, a range check loop looks like this:
1. `mark = int(input("Mark (0-100): "))`
2. `while mark < 0 or mark > 100:`
3. `    print("Out of range")`
4. `    mark = int(input("Mark (0-100): "))`

Python can also write `while not (0 <= mark <= 100):`. Note that `int(input())` crashes if the user types letters; making a program robust against that needs a type check, which goes beyond the three named checks.

**Validation is not verification.** **Verification** checks that data has been entered or copied **accurately**, for example asking for an email or password twice and comparing the two (double entry). Validation asks "is it allowed?"; verification asks "is it what the user meant?". Neither guarantees the data is true.

**Authentication** confirms the **identity** of a user, most simply with a **username and password**. At GCSE the details are stored in **plain text** inside the program (real systems would never do this; they store a hashed password, but you do not need encryption here). The routine compares the entered values with the stored ones:
1. `CONSTANT USER ← 'jsmith'`
2. `CONSTANT PASS ← 'Blue42sky'`
3. `attempts ← 0`
4. `ok ← False`
5. `WHILE ok = False AND attempts < 3`
6. `    u ← USERINPUT`
7. `    p ← USERINPUT`
8. `    IF u = USER AND p = PASS THEN`
9. `        ok ← True`
10. `    ELSE`
11. `        attempts ← attempts + 1`
12. `        OUTPUT 'Details incorrect'`
13. `    ENDIF`
14. `ENDWHILE`
15. `IF ok THEN`
16. `    OUTPUT 'Welcome'`
17. `ELSE`
18. `    OUTPUT 'Account locked'`
19. `ENDIF`

Key design points, each of which tends to be a mark:
- **Both** values must match, so the condition uses **AND**. Using OR would let in anyone who knows only the username.
- The number of attempts is **limited** (here 3), which slows down someone guessing passwords.
- The message on failure does not say **which** item was wrong, so an attacker cannot confirm a username exists.
- The outcome after the loop depends on **why** it ended (success or too many attempts), so a Boolean flag or a final check is needed.
- Comparison is **case-sensitive**: 'blue42sky' does not match 'Blue42sky'.

**Several users.** Store usernames and passwords in two arrays at matching indexes (or in records, 3.2.6), find the username's index, then check the password at the same index:
1. `users ← ['amir', 'beth', 'cara']`
2. `passwords ← ['K9pole', 'tulip77', 'Zed!x']`
3. `found ← False`
4. `FOR i ← 0 TO LEN(users) - 1`
5. `    IF users[i] = u AND passwords[i] = p THEN`
6. `        found ← True`
7. `    ENDIF`
8. `ENDFOR`

**Why it matters.** Validation makes programs **robust**: bad data is caught at the point of entry, so later calculations do not fail or give misleading results ("garbage in, garbage out"). Authentication makes programs **secure**: only authorised users can reach data or features. Both are part of AQA's "robust and secure programming".

::: terms
- **Robust program**: a program that keeps working sensibly, without crashing, whatever input it is given.
- **Validation**: an automatic check by the program that input data is sensible and allowed before it is used.
- **Presence check**: a validation check that something has been entered, i.e. the string is not empty.
- **Length check**: a validation check that a string has at least (or at most) a set number of characters.
- **Range check**: a validation check that a number lies between a lower and an upper limit.
- **Validation loop**: a loop that keeps asking for input until it passes the validation checks.
- **Verification**: checking that data has been entered or copied accurately, e.g. by typing it twice and comparing.
- **Authentication**: confirming the identity of a user, for example by checking a username and password.
- **Plain text password**: a password stored and compared exactly as typed, without encryption.
:::

::: method
1. **Read the rule** in the question and write the condition for **valid** data first (e.g. `n ≥ 1 AND n ≤ 10`).
2. **Flip it for the loop**: loop WHILE the data is **invalid** (`n < 1 OR n > 10`), or REPEAT … UNTIL the data is **valid**.
3. **Input before the WHILE and again inside it**; with REPEAT, input once inside.
4. **Give a helpful message** inside the loop each time the input is rejected.
5. **Convert numeric input** to an integer before a range check (`STRING_TO_INT` / `int()`).
6. **For a login:** store the username and password, input both, compare **both** with AND, count failed attempts, stop after the limit, and output a different message for success and for lock-out.
7. **Check limits are inclusive** where the question says "between 1 and 10 inclusive" or "at least 8".
:::

::: example Write the condition
A program asks for a year group, which must be from 7 to 11. Write the condition that is True when the input `yr` is **invalid**. (2)

`yr < 7 OR yr > 11` (2). 1 mark for a correct valid condition (`yr ≥ 7 AND yr ≤ 11`) used the wrong way round, or for AND instead of OR.
:::

::: example Validation loop
Write a validation routine, in pseudo-code or program code, that asks the user for a nickname and keeps asking until the nickname is at least 3 characters long. (3)

Python:
1. `nick = input("Nickname: ")`
2. `while len(nick) < 3:`
3. `    print("At least 3 characters, please")`

::: example Validation or verification
A website asks a user to type a new password twice and rejects it if it is fewer than 10 characters. Identify which part is validation and which is verification, and explain the purpose of each. (4)

The minimum-length test is validation (1): it checks the password is allowed / sensible (1).

Typing the password twice is verification (1): it checks the password was entered accurately, with no typing mistake (1).
:::

::: example Spot the security flaw
A login routine contains the line `IF u = USER OR p = PASS THEN`. Explain the flaw and correct it. (2)

With OR, a user is let in if just one of the two matches, so anyone who knows the username gets in without the password (1). Correct line: `IF u = USER AND p = PASS THEN` (1).
:::

::: q
Explain the difference between validation and authentication. (2)
---
Validation checks that input data is sensible / allowed (1); authentication checks that the user is who they claim to be, e.g. with a username and password (1).
:::

::: watch
- Validation checks data is **sensible**, not **correct**. Never say it makes data accurate.
- The **invalid** range condition uses **OR** (`x < 1 OR x > 10`); the **valid** one uses **AND**. AND on the invalid side can never be True.
- A validation **loop** must re-input **inside** the loop, or it loops forever. An IF is not a loop.
- "At least 8" means `LEN(pw) < 8` is invalid; 8 itself is allowed. Check the boundary.
- In a login, **both** username and password must match: use **AND**.
- Count attempts and **stop** at the limit, then output a message that depends on whether the user succeeded.
:::

::: test
Write an authentication routine, in pseudo-code or program code, that:
- stores the username 'teacher' and the password 'Mark5cheme';
- asks the user to enter a username and a password;
- allows a maximum of three attempts;
- outputs 'Logged in' if both match, or 'Locked out' after three failed attempts. (6)
---
Example answer (Python):
1. `attempts = 0`
2. `success = False`
3. `while attempts < 3 and not success:`
4. `    u = input("Username: ")`
5. `    p = input("Password: ")`
6. `    if u == "teacher" and p == "Mark5cheme":`
7. `        success = True`
8. `    else:`
9. `        attempts = attempts + 1`
10. `if success:`
11. `    print("Logged in")`
12. `else:`
13. `    print("Locked out")`
Mark points:
- A. Username and password both input inside the loop (1).
- B. Both compared with the stored values using AND (1).
- C. Attempt counter initialised and incremented on each failure (1).
- D. Loop ends when the user succeeds (1).
- E. Loop ends after three failed attempts (not two or four) (1).
- F. Correct single message: 'Logged in' on success, 'Locked out' otherwise (1).
Accept AQA pseudo-code, C# or VB.NET.
