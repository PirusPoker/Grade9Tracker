## What it is

Many programs need behaviour that is not the same every time: a dice roll, a quiz that asks questions in a different order, a game enemy that moves unpredictably, a simulation of traffic arriving at a junction, or a long list of made-up marks to test a program with. **Random number generation** gives a program a number it could not have predicted, chosen from a range you set. The spec only asks you to **use** random numbers in your programs. You do **not** need to know how the computer produces them: they are really **pseudo-random** (made by a calculation that looks random), but that is beyond GCSE.

**AQA pseudo-code.** The exam writes a random whole number as:
- `RANDOM_INT(a, b)`: a random integer from `a` to `b`, **including both ends**.
- `RANDOM_INT(1, 6)` can give 1, 2, 3, 4, 5 or 6. It is a fair six-sided dice.
- `RANDOM_INT(0, 9)` can give any of the ten digits.

**Python.** You must import the `random` module first, usually with `import random` at the top of the program. Then:

| Python | Possible values | Ends |
|---|---|---|
| `random.randint(1, 6)` | 1, 2, 3, 4, 5, 6 | **both** ends included, like AQA |
| `random.randrange(1, 6)` | 1, 2, 3, 4, 5 | the **end is excluded** |
| `random.randrange(0, 10, 2)` | 0, 2, 4, 6, 8 | stepped, end excluded |
| `random.choice(names)` | any one item of the list `names` | n/a |

**C# and VB.NET.** Create a `Random` object once, then call `Next`. The second number is **excluded**, so a dice is `rnd.Next(1, 7)`:
- C#: `Random rnd = new Random();` then `int roll = rnd.Next(1, 7);`
- VB.NET: `Dim rnd As New Random()` then `Dim roll As Integer = rnd.Next(1, 7)`

The table shows the single biggest trap: **AQA and Python's randint include the top value; randrange, C# and VB.NET do not.** A dice coded as `random.randrange(1, 6)` can never roll a 6, and an exam mark scheme will treat that as a wrong range.

**Making the range you need.** You can stretch or shift a random integer with arithmetic:
- An even number from 2 to 20: `RANDOM_INT(1, 10) * 2`.
- A multiple of 5 from 0 to 100: `RANDOM_INT(0, 20) * 5`.
- A temperature from −10 to 30: `RANDOM_INT(-10, 30)`. Negative ends are fine.
- A random **index** of an array: `RANDOM_INT(0, LEN(arr) - 1)`, because indexes start at 0 and the last one is LEN − 1. Using `RANDOM_INT(0, LEN(arr))` can pick an index that does not exist and crash the program.
- A random capital letter: `CODE_TO_CHAR(RANDOM_INT(65, 90))`, using the character codes from 3.2.8.
- A true/false coin toss: `heads ← RANDOM_INT(0, 1) = 1`.

**Where random numbers appear in exam programs.** They are rarely asked about alone. Instead they sit inside a bigger program you write or trace:

*A dice game.* Two dice are rolled; a double scores 10 bonus points:
1. `d1 ← RANDOM_INT(1, 6)`
2. `d2 ← RANDOM_INT(1, 6)`
3. `score ← d1 + d2`
4. `IF d1 = d2 THEN`
5. `    score ← score + 10`
6. `ENDIF`
7. `OUTPUT score`

Each dice needs its **own** call. Writing `d1 ← RANDOM_INT(1, 6)` then `d2 ← d1` would always give a double.

*A guessing game.* The computer chooses once, **before** the loop, and the user keeps guessing:
1. `secret ← RANDOM_INT(1, 100)`
2. `guesses ← 0`
3. `REPEAT`
4. `    guess ← STRING_TO_INT(USERINPUT)`
5. `    guesses ← guesses + 1`
6. `    IF guess > secret THEN`
7. `        OUTPUT 'Too high'`
8. `    ELSE IF guess < secret THEN`
9. `        OUTPUT 'Too low'`
10. `    ENDIF`
11. `UNTIL guess = secret`
12. `OUTPUT 'Correct in ', guesses, ' guesses'`

If line 1 were inside the loop, the secret number would change after every guess and the game would be unfair.

*A maths quiz.* Random questions, so every attempt is different:
1. `correct ← 0`
2. `FOR q ← 1 TO 5`
3. `    a ← RANDOM_INT(2, 12)`
4. `    b ← RANDOM_INT(2, 12)`
5. `    OUTPUT 'What is ', a, ' times ', b, '?'`
6. `    ans ← STRING_TO_INT(USERINPUT)`
7. `    IF ans = a * b THEN`
8. `        correct ← correct + 1`
9. `    ENDIF`
10. `ENDFOR`
11. `OUTPUT 'Score: ', correct, '/5'`

*A simulation.* Roll a dice 600 times and count each face in an array:
1. `counts ← [0, 0, 0, 0, 0, 0]`
2. `FOR i ← 1 TO 600`
3. `    roll ← RANDOM_INT(1, 6)`
4. `    counts[roll - 1] ← counts[roll - 1] + 1`
5. `ENDFOR`

The `- 1` maps a roll of 1 to index 0 and a roll of 6 to index 5. Each count should come out near 100, but not exactly.

**Tracing and testing with random numbers.** You cannot predict the output of a program that uses random numbers, so exam questions **tell you** what values the random calls return ("assume the first call returns 4 and the second returns 4"), and you trace from there. When you test your own program, you can temporarily replace the random call with a fixed value so you can check each path, then put it back.

::: terms
- **Random number generation**: producing a number a program cannot predict, chosen from a range set by the programmer.
- **RANDOM_INT(a, b)**: the AQA pseudo-code function that returns a random integer from a to b, including both a and b.
- **Pseudo-random number**: a number produced by a calculation that appears random; how this works is not examined.
- **random.randint**: the Python function that returns a random integer with both ends of the range included.
- **random.randrange**: the Python function that returns a random integer from a range whose end value is excluded.
- **Inclusive range**: a range in which the first and last values can both be produced.
- **Off-by-one error**: a logic error where a range or loop is one value too big or too small, such as a dice that never rolls 6.
- **Simulation**: a program that models a real situation, often using random numbers to imitate chance events.
:::

::: method
1. **Read the range in the question** and decide the smallest and largest values that must be possible.
2. **Pick the call that includes both ends**: `RANDOM_INT(low, high)` in AQA pseudo-code, `random.randint(low, high)` in Python, `rnd.Next(low, high + 1)` in C# or VB.NET.
3. **In Python, import the module** (`import random`) at the top, or the call fails.
4. **Generate once, in the right place**: before a loop if the value must stay the same (a secret number), inside the loop if it must change (each dice roll, each quiz question).
5. **Use a separate call** for each independent value (two dice need two calls).
6. **Store the result in a variable** if you need it more than once; calling the function again gives a different number.
7. **For array indexes, use 0 to LEN − 1.** For other ranges, multiply or add to stretch or shift a basic range.
8. **When tracing**, use exactly the random values the question gives you.
:::

State the smallest and largest values that each statement can produce: (a) `x ← RANDOM_INT(5, 15)`; (b) `y ← RANDOM_INT(1, 4) * 3`; (c) `z ← random.randrange(0, 50)` in Python. (3)

(a) 5 and 15: AQA's RANDOM_INT includes both ends (1).

(b) 3 and 12: the random part is 1 to 4, then multiplied by 3 (1).

(c) 0 and 49: randrange excludes the end value (1).
:::

::: example Choosing a random item
`colours ← ['red', 'blue', 'green', 'yellow']`. Write a pseudo-code statement that outputs a random colour from the array, and explain your choice of range. (3)

`OUTPUT colours[RANDOM_INT(0, 3)]` (1). Accept `RANDOM_INT(0, LEN(colours) - 1)`.

Array indexes start at 0 (1), so the last index is 3, one less than the length of 4; using 4 could pick an index that does not exist (1).
:::

3. `d2 = random.randint(1, 6)`
4. `print(d1, d2)`
5. `if d1 == d2:`

Explain why a program that uses a random number to decide what happens can be hard to test, and how a programmer can test it. (3)
---
The output is different each run, so the expected result cannot be predicted (1). The programmer can temporarily replace the random call with fixed values (1) chosen to test each path through the program, then restore it (1). Accept: run it many times and check every outcome appears and all values stay in range (1).

::: watch
- `RANDOM_INT(a, b)` and Python `randint(a, b)` **include** b; `randrange(a, b)`, C# and VB.NET `Next(a, b)` **exclude** b.
- A random **index** runs from 0 to LEN − 1, not 1 to LEN.
- Generate a secret number **once, before** the loop. Generating it inside the loop keeps changing the target.
- Two dice need **two calls**. Copying one roll into another variable is not a second roll.
- Store a random value in a variable if you need it again; a second call gives a different number.
- In Python, forgetting `import random` makes the program fail.
:::

::: test
Write a program, in pseudo-code or program code, for a number guessing game that:
- generates a random number from 1 to 50 inclusive;
- lets the user guess repeatedly until they are correct;
- after each wrong guess, outputs 'Higher' or 'Lower';

---
Example answer (Python):
1. `import random`
2. `secret = random.randint(1, 50)`
3. `count = 0`
4. `guess = 0`
5. `while guess != secret:`
6. `    guess = int(input("Guess: "))`
7. `    count = count + 1`
8. `    if guess < secret:`
9. `        print("Higher")`
10. `    elif guess > secret:`
11. `        print("Lower")`
12. `print("Correct! Guesses:", count)`
Mark points:
- A. Random integer generated with the range 1 to 50 inclusive (1).
- B. Random number generated once, before the loop (1).
- C. Guess input from the user and converted to an integer (1).
- D. Loop that repeats until the guess equals the secret number (1).
- E. Counter initialised to 0 before the loop and incremented once per guess (1).
- F. 'Higher' output when the guess is too low (1).
- G. 'Lower' output when the guess is too high (1).
- H. Number of guesses output after the loop, once only (1).
Accept AQA pseudo-code (RANDOM_INT, REPEAT … UNTIL), C# or VB.NET (`rnd.Next(1, 51)`).

::: test
