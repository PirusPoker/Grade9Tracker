## What it is

A single comparison such as `age ≥ 18` is often not enough. Real decisions combine tests: a ticket is cheap if you are **under 16 or over 65**, and a login loop keeps going **while** the password is wrong **and** attempts are left. **Boolean operators** join or reverse conditions. The spec names three: **NOT**, **AND** and **OR**. You must be able to use them, alone and in combination, in the conditions of selection and iteration.

**AND** is True only when **both** sides are True:

| A | B | A AND B |
|---|---|---|
| False | False | False |
| False | True | False |
| True | False | False |
| True | True | True |

**OR** is True when **at least one** side is True (including when both are):

| A | B | A OR B |
|---|---|---|
| False | False | False |
| False | True | True |
| True | False | True |
| True | True | True |

**NOT** reverses a single value: NOT True is False, and NOT False is True.

These are exactly the AND, OR and NOT logic gates you meet in 3.4.2, written as program code rather than drawn as circuits.

| | AQA pseudo-code | Python | C# | VB.NET |
|---|---|---|---|---|
| and | `AND` | `and` | `&&` | `And` (or `AndAlso`) |
| or | `OR` | `or` | two pipe characters (the vertical-bar key, typed twice) | `Or` (or `OrElse`) |
| not | `NOT` | `not` | `!` | `Not` |

**Using them in selection:**
1. `IF age < 16 OR age ≥ 65 THEN`
2. `    price ← 4`
3. `ELSE`
4. `    price ← 7`
5. `ENDIF`

A 12-year-old makes the first part True, so the whole condition is True. A 70-year-old makes the second part True. A 30-year-old makes both parts False, so the ELSE runs.

**Using them in iteration.** Loop conditions often need two tests: one for "the job is done" and one for "we have run out of chances" or "we have reached the end":
1. `found ← False`
2. `attempts ← 0`
3. `WHILE attempts < 3 AND NOT found`
4. `    guess ← USERINPUT`
5. `    IF guess = secret THEN`
6. `        found ← True`
7. `    ENDIF`
8. `    attempts ← attempts + 1`
9. `ENDWHILE`

The loop continues only while **both** are true: there are attempts left **and** the answer has not been found. As soon as either becomes false, it stops. `found` is a Boolean variable, so it can be used directly. `NOT found` is the same as `found = False`, and `IF found THEN` is the same as `IF found = True THEN`.

**Every side must be a complete condition.** In English we say "x is more than 1 and less than 10", but in code each side of AND or OR must be a full comparison:
- Wrong: `x > 1 AND < 10`. Right: `x > 1 AND x < 10`.
- Wrong: `answer = 'Y' OR 'y'`. Right: `answer = 'Y' OR answer = 'y'`.

The second wrong version does not cause an error in Python. It quietly treats `'y'` as True, so the condition is **always** True. That makes it a logic error rather than a syntax error.

**AND or OR?** A common mistake is using OR for a range check. `mark ≥ 0 OR mark ≤ 100` is True for **every** number, since any number is either at least 0 or at most 100. A value **inside** a range needs **AND**: `mark ≥ 0 AND mark ≤ 100`. A value **outside** a range needs **OR**: `mark < 0 OR mark > 100`.

**Order and brackets.** Most languages work out **NOT first, then AND, then OR**, just as multiplication comes before addition. So `a OR b AND c` means `a OR (b AND c)`. If you mean `(a OR b) AND c`, you must write the brackets. Using brackets whenever you combine AND with OR makes the meaning clear and avoids mistakes. For example, a discount for members who spend over £50, or for anyone in the sale:
- `(member AND spend > 50) OR inSale`. This is very different from:
- `member AND (spend > 50 OR inSale)`, which gives non-members nothing at all.

**Evaluating a compound condition** step by step: work out each comparison as True or False, then apply NOT, then AND, then OR (or brackets first). With `x ← 4` and `y ← 9`:
1. `x > 3 AND y < 5`: True AND False, which is **False**.
2. `x > 3 OR y < 5`: True OR False, which is **True**.
3. `NOT (x = 4)`: NOT True, which is **False**.
4. `NOT (x > 5 AND y > 5)`: NOT (False AND True), which is NOT False, which is **True**.

**Rewriting with NOT.** Negating a compound condition swaps AND with OR and reverses each comparison. "Not (in range)" means "too low **or** too high": `NOT (x ≥ 1 AND x ≤ 10)` is the same as `x < 1 OR x > 10`. And "not (a or b)" means "neither": `NOT (raining OR windy)` is the same as `NOT raining AND NOT windy`. This is useful when changing a WHILE loop (keep going **while** …) into a REPEAT … UNTIL loop (stop **when** …). `WHILE attempts < 3 AND NOT found` becomes `UNTIL attempts = 3 OR found`.

::: terms
- **Boolean operator**: an operator that combines or reverses Boolean values; at GCSE these are AND, OR and NOT.
- **AND**: a Boolean operator that gives True only when both of its conditions are True.
- **OR**: a Boolean operator that gives True when at least one of its conditions is True.
- **NOT**: a Boolean operator that reverses a value, turning True into False and False into True.
- **Compound condition**: a condition made of two or more comparisons joined by Boolean operators.
- **Boolean variable**: a variable holding True or False, which can be used directly as a condition.
- **Flag**: a Boolean variable that records whether something has happened, such as found or gameOver.
:::

::: method
1. **Evaluating:** turn each comparison into True or False first. Then apply brackets, then NOT, then AND, then OR.
2. **Choosing AND or OR:** "both must be true" or "inside a range" → AND; "either is enough" or "outside a range" → OR.
3. **Writing conditions:** every side must be a **complete comparison** with its own variable: `x > 1 AND x < 10`.
4. **Loops with two exit reasons** (found it, or ran out): a WHILE needs `AND` of the two "keep going" conditions; an UNTIL needs `OR` of the two "stop" conditions.
5. **Mixing AND and OR:** always add brackets so the order is unambiguous.
6. **Boolean variables:** use them directly (`IF found THEN`, `WHILE NOT gameOver`). Comparing them with True is allowed but not needed.
:::

::: example Evaluate compound conditions
`a ← 5`, `b ← 12`, `ok ← False`. State whether each is True or False: (a) `a < 10 AND b < 10`; (b) `a < 10 OR b < 10`; (c) `NOT ok AND b > a`; (d) `NOT (a = 5 OR ok)`. (4)

(a) False: True AND False (1).

(b) True: True OR False (1).

(c) True: NOT False is True, and 12 > 5 is True, so True AND True (1).

(d) False: a = 5 is True, so the bracket is True OR False, which is True, and NOT True is False (1).
:::

::: example Write a condition
A lift should only move when the doors are closed and the load is no more than 800 kg. Write the condition using a Boolean variable `doorsClosed` and a variable `load`. (2)

`doorsClosed AND load ≤ 800` (or `doorsClosed = True AND load ≤ 800`).

One mark for each correct part: the door test (1) and `load ≤ 800` joined with AND (1).
:::

::: example Fix the condition
A program contains `IF choice = 'A' OR 'B' THEN`. Explain why this is wrong and correct it. (2)

Each side of OR must be a complete comparison; `'B'` on its own is not a test of choice (1).

Correct version: `IF choice = 'A' OR choice = 'B' THEN` (1).
:::

::: example Loop with two conditions
A game gives the player up to 5 guesses to find a secret number. Explain why the loop condition is `WHILE guesses < 5 AND NOT correct`, and not the same condition with OR. (3)

The loop should only continue while there are guesses left and the number has not been found, so both must be True: that needs AND (1).

With AND, the loop stops as soon as either the 5th guess has been made or the guess is correct (1).

With OR, the loop would continue after a correct guess (because guesses < 5 is still True), and after 5 wrong guesses (because NOT correct is still True). It would only stop when both were false (1).
:::

::: watch
- Each side of AND/OR needs a **complete comparison**: `x > 1 AND x < 10`, not `x > 1 AND < 10`.
- **Inside a range = AND. Outside a range = OR.** Using OR for a range check accepts everything.
- **NOT, then AND, then OR.** Add brackets whenever you mix AND and OR.
- A WHILE loop with two "keep going" conditions uses **AND**. The equivalent UNTIL uses **OR** of the two "stop" conditions.
- OR is True when **both** sides are True too. It is not "one or the other but not both".
- A Boolean flag can be the condition itself: `WHILE NOT found`.
:::

Explain the difference in meaning between `(member AND spend > 50) OR sale` and `member AND (spend > 50 OR sale)`. (2)

A user may withdraw cash if the amount is a multiple of 10, and is no more than both their balance and the daily limit of £300. Write the condition, using `amount` and `balance`. (3)

::: test
Explain why a loop that searches for an item in an array needs a condition with AND, such as `WHILE i < LEN(items) AND NOT found`. (2)

The loop must stop when the item is found (1), and also when the end of the array is reached so it does not go past the last index; it should only continue while both are still true (1).
