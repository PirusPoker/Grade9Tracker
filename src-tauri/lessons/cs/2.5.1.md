## What it is

A CPU can only execute **machine code** — binary instructions. Writing whole programs in binary would be almost impossible, so we write in **programming languages** and then **translate** them into machine code. Languages sit on a scale from **high-level** (close to human language) to **low-level** (close to the hardware).

**High-level languages** (for example Python, Java, C# and Visual Basic) are written in words and symbols close to English and mathematics, and one statement can stand for many machine-code instructions.
- *Advantages:* easier to read, write, learn and debug; **portable**, so the same code can run on different types of computer once translated; the programmer does not need to know the details of the hardware.
- *Disadvantages:* must be translated before the CPU can run it, and the finished code is often **less efficient** — slower and using more memory — than carefully written low-level code.

**Low-level languages** are close to the hardware and specific to one type of processor.
- **Machine code** is the binary instructions the CPU executes **directly**.
- **Assembly language** uses short **mnemonics** such as `LDA`, `ADD` and `STO`, where roughly one instruction translates to one machine-code instruction.
- *Advantages:* can be extremely **efficient** and gives **direct control of the hardware**, so it is used for device drivers and embedded systems where speed and memory really matter.
- *Disadvantages:* hard to write, read and debug, and **not portable** — code written for one processor will not run on a different one.

**Translators, and why one is needed:** because the CPU understands only machine code, source code written in any other language must be translated into machine code before it can run. There are **three** types:

- **Compiler** — translates the **whole program in one go**, before it is run, producing a separate **executable** file. It **reports all the errors together** at the end. The executable then runs quickly and needs neither the source code nor the compiler, but you must **recompile** after every change.
- **Interpreter** — translates and runs the program **one line at a time**, every time it is run. It **stops at the first error** it reaches, which makes finding errors easier. But it is **slower**, because it re-translates on every run, and the interpreter must be **present each time** the program runs; there is no standalone executable.
- **Assembler** — translates **assembly language** into machine code, roughly one instruction to one.

**When each is used:** an interpreter suits **development, learning and testing** (for example Python), because you can run code quickly and find errors one at a time; a compiler suits **finished, distributed software**, because it runs fast and hides the source code. An assembler is used whenever a program is written in assembly language.

::: terms
- **High-level language**: a programming language that uses English-like statements and is independent of the hardware, e.g. Python.
- **Low-level language**: a language close to the hardware — machine code or assembly language.
- **Machine code**: binary instructions that the CPU can execute directly.
- **Assembly language**: a low-level language that uses short mnemonics, each translating to one machine-code instruction.
- **Translator**: a program that converts source code into machine code.
- **Compiler**: a translator that converts the whole program into machine code in one go, producing an executable file.
- **Interpreter**: a translator that translates and runs a program one line at a time, stopping at the first error.
- **Assembler**: a translator that converts assembly language into machine code.
:::

::: method
**Comparing a compiler and an interpreter for full marks** — for each point, give *both* halves:
1. **How much is translated:** compiler = the whole program at once; interpreter = one line at a time.
2. **When:** compiler = once, before running; interpreter = every time the program runs.
3. **Errors:** compiler = reports all errors at the end; interpreter = stops at the first error found.
4. **Output:** compiler = produces a separate executable; interpreter = produces none, so the interpreter is needed each run.
5. **Speed:** compiled code runs faster; interpreted code is slower because it is translated as it runs.
:::

::: example Advantages of a high-level language
State two advantages of writing a program in a high-level language rather than machine code. [2]

It is easier to read, write and debug because it is close to human language, and it is portable, so the same program can be run on different types of computer once it has been translated.
:::

::: example Why a translator is needed
Explain why a translator is needed to run a program written in Python. [2]

The CPU can only execute machine code, but Python source code is a high-level language that the CPU cannot run directly. A translator is needed to convert the Python code into machine code so that the processor can execute it.
:::

::: example Compiler versus interpreter
Describe two differences between a compiler and an interpreter. [4]

A compiler translates the **whole program in one go** and produces an executable file, whereas an interpreter translates and runs the program **one line at a time** with no executable produced. A compiler also **reports all the errors together at the end** of compilation, while an interpreter **stops as soon as it reaches the first error**.
:::

::: example Choosing an interpreter
A programmer is still writing and testing a program, and keeps making mistakes. Explain why an interpreter is useful to them. [3]

An interpreter runs the code one line at a time and stops at the first error it meets, showing exactly where the problem is, which makes mistakes quick to locate and fix. Because it runs the code directly without a separate compile step, the programmer can make a change and test it again immediately, which suits repeated testing during development.
:::

::: example Choosing a low-level language
Give one situation where a low-level language would be chosen, and why. [2]

Writing a device driver or an embedded system, because low-level code can be made very efficient and gives direct control of the hardware, which matters where speed and limited memory are critical.
:::

::: q
Why can a CPU not run high-level source code directly?
---
Because the CPU can only execute machine code, so any other language must first be translated into machine code.
:::

::: q
Give one advantage and one disadvantage of a low-level language.
---
Advantage: it can be very efficient and control the hardware directly. Disadvantage: it is hard to read and write and is not portable between different processors.
:::

::: q
What is the difference between machine code and assembly language?
---
Machine code is the binary instructions the CPU runs directly; assembly language uses short mnemonics that stand for those instructions and must be translated by an assembler.
:::

::: q
A compiler finds ten errors in a program. When and how does it report them?
---
It reports them all together at the end of compilation, rather than stopping at the first one.
:::

::: q
Why does interpreted code usually run more slowly than compiled code?
---
Because an interpreter translates the program line by line every time it runs, whereas a compiler translates it once in advance into an executable that then runs directly.
:::

::: q
After compiling a program, does the user need the compiler or the source code to run it? Explain.
---
No; compilation produces a standalone executable, so the finished program runs on its own without the source code or the compiler.
:::

::: q
What does an assembler do?
---
It translates a program written in assembly language into machine code, roughly one instruction to one machine-code instruction.
:::

::: q
Why is a high-level language described as portable?
---
Because the same source code can be translated and run on different types of computer or processor, rather than being tied to one.
:::

::: watch
- **Compiler versus interpreter: give both halves.** A compiler translates the whole program at once and reports all errors at the end; an interpreter translates line by line and stops at the first error. Answering with only one side is the usual dropped mark.
- **A compiler produces an executable; an interpreter does not.** That is why compiled programs run without the translator and interpreted ones need it every time.
- **"Translated once" versus "translated every run"** is the reason compiled code is faster — say it, do not just assert that "compilers are faster".
- **Machine code and assembly are both low-level, but not the same.** Machine code is binary; assembly uses mnemonics and needs an **assembler**.
- **High-level = portable and easy; low-level = efficient and hardware-specific.** Match the language to what the question values — ease of writing, or raw speed and control.
:::
