## What it is

A CPU's **performance** — how much work it gets through each second — is decided mainly by three things: its **clock speed**, its **cache size** and its **number of cores**. A grade 9 answer never judges a processor on one of these alone; it explains how each one changes the amount of work done and how they trade off.

**Clock speed**
- The CPU contains a **clock** that sends out regular electrical pulses, and each pulse drives the CPU through the steps of the **fetch-execute cycle**.
- Clock speed is the **number of cycles per second**, measured in **hertz (Hz)**. Modern CPUs run in **gigahertz (GHz)**; 1 GHz is one billion ($10^9$) cycles per second, so a 3.5 GHz CPU carries out about 3.5 billion cycles each second.
- A **higher clock speed means more instructions are fetched and executed per second**, so, all else being equal, the computer is faster.
- **Overclocking** means running the clock faster than the manufacturer intended. It can raise speed but generates **more heat**, needs extra cooling and risks instability or damage.

**Cache size**
- **Cache** is a small amount of very fast memory inside or very close to the CPU. It holds copies of the instructions and data the CPU is using or is likely to need next.
- Fetching from cache is **much faster** than fetching from RAM. A **larger cache** holds **more** of what the CPU needs, so the CPU makes **fewer slow trips to RAM** and waits less — more instructions per second.
- Cache comes in levels: **L1** (smallest, fastest, closest), then **L2** and **L3** (larger, slightly slower, but still far faster than RAM).

**Number of cores**
- A **core** is a complete processing unit that can run its own fetch-execute cycle. A **dual-core** CPU has 2, a **quad-core** 4, and so on.
- More cores let the CPU **process more instructions at the same time (in parallel)**, so more work is done at once.
- **But doubling the cores does not double the speed**, because:
  - the **software must be written to split its work** across cores (multi-threaded); a single-threaded program uses only one core and leaves the rest idle;
  - some tasks are **sequential** — each step needs the result of the last — and cannot be parallelised;
  - the cores must **coordinate** and often share cache, memory and buses, which adds overhead.

These three interact: a high clock speed with a tiny cache can lose to a lower clock speed with a big cache and more cores.

::: method
Answering a CPU-performance question:
1. **Spot which factor changed** — clock speed, cache size or number of cores.
2. **Clock speed:** more cycles per second means more instructions fetched and executed per second, so faster. Mention heat/power if it is pushed high.
3. **Cache size:** a bigger cache holds more likely-next data, so fewer slow fetches from RAM and less waiting.
4. **Cores:** more cores means more instructions processed at once, **but only if the software splits its work** across them.
5. **Comparing two CPUs:** weigh all three together; never decide on clock speed alone.
6. Whatever the factor, **link it to "instructions per second" / "work done per second"** — that is where the mark is.
:::

::: example What clock speed means
State what is meant by clock speed and what a speed of 3 GHz tells you. [2]

Clock speed is the number of fetch-execute cycles the CPU performs each second, measured in hertz. A speed of 3 GHz means the CPU carries out three billion cycles per second, so it can fetch and execute instructions very rapidly.
:::

::: example Why more cores is not "times faster"
A computer's processor is upgraded from dual-core to quad-core. Explain why the computer may not run a particular program twice as fast. [3]

More cores let the CPU execute more instructions simultaneously, but this only helps if the program is written to divide its work across the cores. If the program is single-threaded it runs on one core while the others sit idle. Some tasks are also sequential and cannot be split, and the cores add coordination overhead, so the real speed-up is usually less than the increase in cores.
:::

::: example How cache size helps
Explain how increasing the size of the CPU's cache can improve performance. [3]

Cache is very fast memory close to the CPU that stores instructions and data it is likely to reuse. A larger cache can hold more of this data, so the CPU finds what it needs in cache more often and makes fewer trips to the much slower RAM. Because it spends less time waiting for data, the CPU executes more instructions per second.
:::

::: example Choosing between two CPUs
CPU A is 3.6 GHz dual-core with 2 MB of cache. CPU B is 2.8 GHz quad-core with 8 MB of cache. State which is likely better for video editing and justify your answer. [3]

CPU B is likely better. Video-editing software is written to use multiple cores, so its four cores let far more of the work be processed in parallel than A's two, and its larger 8 MB cache reduces slow accesses to RAM. Although A has a higher clock speed, that advantage applies mainly to single-threaded work, so for this heavily multi-threaded task B should outperform it.
:::

::: example The limit of clock speed
A student says "to make any program faster, just raise the clock speed." Give two reasons this is too simple. [2]

Raising the clock speed increases heat and power use, so it cannot be raised indefinitely without better cooling and it risks instability. Performance also depends on cache size and the number of cores, and a program held up waiting for data from RAM will not speed up just because the clock is faster.
:::

::: q
What does clock speed measure, and in what unit?
---
The number of fetch-execute cycles the CPU performs per second, measured in hertz (usually gigahertz, GHz).
:::

::: q
How many cycles per second is 1 GHz?
---
One billion ($10^9$) cycles per second.
:::

::: q
Why does a larger cache reduce the time the CPU spends waiting?
---
It holds more of the instructions and data the CPU is likely to need, so the CPU fetches from cache instead of making slow trips to RAM.
:::

::: q
What is a core?
---
A complete processing unit within the CPU that can carry out its own fetch-execute cycle.
:::

::: q
Give one reason doubling the number of cores rarely doubles real performance.
---
The software may not be written to split its work across cores, or the task is sequential, so the extra cores sit idle.
:::

::: q
What is overclocking, and give one risk of it?
---
Running the clock faster than its rated speed; it produces more heat and can cause instability or damage.
:::

::: q
A task cannot be broken into parallel parts. Would extra cores or a higher clock speed help it more?
---
A higher clock speed (and larger cache), because extra cores would stay idle for a task that must run sequentially.
:::

::: q
Why is comparing two CPUs on clock speed alone unreliable?
---
Because cache size and the number of cores also affect performance, and software differs in how well it uses multiple cores.
:::

::: watch
- **More cores only help if the software splits its work across them** — always say this, or the answer reads as if cores are simply "faster".
- Some tasks are **sequential** and cannot be parallelised, so extra cores stay idle.
- **Clock speed is cycles per second** (Hz/GHz) — it is not the number of cores and not the size of the cache.
- Don't judge a CPU on one number; **clock speed, cache and cores work together**.
- Say **why** cache helps — fewer slow trips to RAM — not just "it's faster".
- A very high clock speed means **more heat and power**, which limits how far it can be pushed.
:::
