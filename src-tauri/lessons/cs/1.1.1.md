## What it is

The **CPU** (central processing unit) is the part of the computer that fetches, decodes and executes instructions — it does the actual processing. Almost all computers follow the **von Neumann architecture**: a single main memory holds *both* the program instructions *and* the data they work on, and the CPU fetches them one at a time (the *stored program* concept).

Inside the CPU:
- The **control unit (CU)** directs everything — it fetches and decodes each instruction and sends control signals so the other parts carry it out.
- The **arithmetic logic unit (ALU)** does the arithmetic (add, subtract) *and* the logic (AND, OR, comparisons).
- The **cache** is a small, very fast memory inside or very close to the CPU that holds copies of the instructions and data likely to be needed next, so the CPU waits less for slower RAM.
- The **registers** are tiny, extremely fast stores that each hold one value while an instruction is carried out.

The registers the cycle uses:
- **PC** (program counter) — holds the **address** of the **next** instruction.
- **MAR** (memory address register) — holds the **address** being read from or written to.
- **MDR** (memory data register) — holds the **data or instruction** just read from, or about to be written to, memory.
- **CIR** (current instruction register) — holds the instruction being decoded and executed.
- **Accumulator (ACC)** — holds the **result** of the ALU's calculations.

::: terms
- **CPU (central processing unit)**: the component that processes data and instructions by carrying out the fetch-execute cycle.
- **Fetch-execute cycle**: the repeated process in which the CPU fetches an instruction from memory, decodes it and executes it.
- **ALU (arithmetic logic unit)**: the part of the CPU that carries out calculations and logical comparisons.
- **CU (control unit)**: the part of the CPU that decodes instructions and sends control signals to coordinate the other components.
- **Register**: a very small, very fast storage location inside the CPU.
- **Cache**: a small amount of very fast memory inside or close to the CPU that stores frequently used data and instructions.
- **Program counter (PC)**: the register that holds the memory address of the next instruction to be fetched.
- **MAR (memory address register)**: the register that holds the address of the memory location currently being read from or written to.
- **MDR (memory data register)**: the register that holds the data or instruction just fetched from, or about to be written to, memory.
- **Accumulator**: the register that holds the result of calculations carried out by the ALU.
- **Von Neumann architecture**: a computer design in which data and instructions are stored together in the same memory, and the CPU fetches and executes one instruction at a time.
:::

::: method
The **fetch-execute cycle** — repeated for every instruction:
1. **Fetch:** the address in the **PC** is copied into the **MAR**.
2. The instruction at that address is copied from memory into the **MDR**.
3. It is copied from the MDR into the **CIR**, and the **PC** is incremented so it points at the next instruction.
4. **Decode:** the control unit works out what the instruction in the CIR means.
5. **Execute:** the instruction is carried out — e.g. the ALU does a calculation and stores the result in the **accumulator**, or data is loaded/stored.
6. Repeat, using the new PC value.

To answer a "describe the cycle" question, **name the registers at each step** — that is where the marks are.
:::

::: example Walking through the fetch-execute cycle
Describe the stages of the fetch-execute cycle. [4]

The program counter holds the address of the next instruction; this address is copied into the MAR. The instruction stored at that address is fetched from main memory into the MDR, and the program counter is incremented so it points to the following instruction. The instruction is then decoded by the control unit, which works out what operation is required. Finally it is executed — for example the ALU performs a calculation and stores the result in the accumulator.
:::

::: example Address register vs data register
State the difference between the MAR and the MDR. [2]

The **MAR** holds an *address* — the memory location about to be read from or written to. The **MDR** holds the *contents* of a location — the actual data or instruction fetched from, or to be written to, that address.
:::

::: example What von Neumann means
Explain what is meant by the von Neumann architecture. [2]

A single main memory stores both program instructions and data together, and the CPU fetches and executes them one at a time along a shared bus. This *stored program* concept is why a computer can run any program simply by loading different instructions into memory.
:::

::: example Why cache speeds things up
Explain how cache improves CPU performance. [3]

Cache is a small amount of very fast memory inside or very close to the CPU that stores copies of instructions and data the CPU has used or is likely to use again. Retrieving them from cache is much faster than fetching them from RAM, so the CPU spends less time waiting and carries out more instructions per second.
:::

::: q
Name the two registers used in the first step of the fetch stage, and say what each holds.
---
The **PC** (program counter), which holds the address of the next instruction, and the **MAR** (memory address register), into which that address is copied.
:::

::: q
State the purpose of the control unit.
---
It manages the fetch-decode-execute cycle — fetching and decoding each instruction and sending control signals to the other components so it is carried out.
:::

::: q
A student says "the ALU stores the program while it runs." Give two corrections.
---
The ALU does not store the program — main memory (RAM) does; and the ALU only performs arithmetic and logic operations, putting results in the accumulator.
:::

::: q
What does the accumulator hold, and which component puts values into it?
---
It holds the result of a calculation or logic operation; the ALU puts values into it.
:::

::: q
Explain why the program counter is incremented during the fetch stage.
---
So that once the current instruction has been fetched, the PC already points to the next instruction and the cycle continues in order — unless a later jump instruction overwrites it.
:::

::: q
In the von Neumann architecture, what two kinds of thing are stored together in main memory?
---
Program instructions and the data those instructions operate on.
:::

::: q
Give one reason a CPU uses registers rather than RAM for every value during an instruction.
---
Registers are inside the CPU and far faster to access than RAM, so using them avoids the delay of a trip to main memory for every value.
:::

::: watch
- **MAR holds an address; MDR holds data.** Swapping them is the single most common CPU-question error — the MAR says *where*, the MDR says *what*.
- **Name the registers.** "The instruction is fetched from memory" scores less than "the address in the PC is copied to the MAR, and the instruction is loaded into the MDR."
- The PC is **incremented during the fetch**, and a jump instruction can overwrite it — which is why programs are not always linear.
- The ALU does arithmetic **and logic** (comparisons, AND/OR), not just sums.
- Say *why* cache helps — fewer slow trips to RAM — not just "it's fast".
:::

::: test
Describe the three stages of the fetch-decode-execute cycle. (3)
---
Fetch: the instruction at the address in the program counter is copied from memory into the CPU via the MAR and MDR (1); decode: the control unit works out what the instruction means (1); execute: the instruction is carried out, e.g. by the ALU, and the program counter moves on (1).
:::

::: test
State the purpose of the memory address register (MAR) and the memory data register (MDR). (2)
---
MAR holds the address in memory that is about to be read from or written to (1); MDR holds the data or instruction just read from, or about to be written to, that address (1).
:::

::: test
State the purpose of the arithmetic logic unit. (2)
---
Performs arithmetic (add, subtract) (1) and logical operations and comparisons (AND, OR, greater than) (1).
:::

::: test
Explain what the program counter holds and how it changes during the cycle. (2)
---
The address of the next instruction to be fetched (1); it is incremented by one each cycle, or replaced by a new address after a jump instruction (1).
:::

::: test
Describe two key features of the von Neumann architecture. (2)
---
Instructions and data are stored together in the same memory (1); a single processor with registers fetches instructions one at a time in sequence (1).
:::

::: test
Explain the role of the cache in the fetch-decode-execute cycle. (2)
---
Very fast memory inside or next to the CPU holding recently or frequently used instructions and data (1); the CPU checks the cache first, avoiding a slower trip to RAM (1).
:::

::: test
Explain why the accumulator is needed. (1)
---
It holds the results of calculations from the ALU so they can be used in the next operation without going back to memory.
:::

::: test
A program has a jump instruction. Explain how the CPU carries it out. (2)
---
The control unit decodes the jump and writes the target address into the program counter (1); the next fetch takes its instruction from that address instead of the following one (1).
:::
