## What it is

J277 names **two searches** and **three sorts**, and you must be able to carry each one out **by hand** and show your working.

**Linear search** — start at the first item and check each one in turn until you find what you are looking for or reach the end. It works on **any** list, sorted or not, but on a long list it is slow because it may check every item.

**Binary search** — only works on a list that is already **sorted**. Look at the **middle** item: if it is the target, stop; if the target is smaller, throw away the middle and everything to its right and search the left half; if larger, search the right half. Each step **halves** the list, so it finds things in far fewer checks than a linear search.

**Bubble sort** — make repeated **passes** along the list. On each pass, compare every **adjacent pair** and **swap** any that are in the wrong order. The largest value "bubbles" to the end on each pass. Keep going until a whole pass makes no swaps. It is simple to understand but slow.

**Merge sort** — **divide and conquer**. Keep splitting the list in half until every piece is a **single item** (a single item is already sorted), then **merge** the pieces back together two at a time, always taking the smaller front item first, until the whole list is rebuilt in order. It is efficient on large lists but needs **more memory** to hold the pieces.

**Insertion sort** — build a **sorted section** at the front of the list one item at a time. Take the next item and **insert** it into its correct place among the items already sorted, shuffling larger ones up to make room. It is good on small or nearly-sorted lists.

**Comparing them:** binary search is faster than linear but needs the data sorted first; merge sort is efficient but uses more memory than the others; bubble sort is the simplest to write but the slowest; insertion sort does well when the list is already close to sorted.

::: method
The five algorithms, step by step:
1. **Linear search** — check item 0, then item 1, then item 2... Stop as soon as you find the target (give its position) or run off the end (report "not found").
2. **Binary search** — set `low` to the first index and `high` to the last. Find the middle: `mid = (low + high) DIV 2`. If the middle item is the target, stop. If the target is smaller, set `high = mid - 1`; if larger, set `low = mid + 1`. Repeat until found or `low > high`.
3. **Bubble sort** — pass along the list comparing each adjacent pair and swapping any out of order. Repeat passes until a whole pass makes no swaps; the list is then sorted.
4. **Merge sort** — split the list in half again and again until each part holds one item, then merge parts back together in order, two at a time, until one sorted list remains.
5. **Insertion sort** — treat the first item as a sorted section of one. Take each following item in turn and insert it into its right place in that sorted section.

For a sort, **show every pass**, not just the final list — the marks are in the passes.
:::

::: example Linear search
Use a linear search to find 7 in this list: 4, 2, 7, 1, 9. [3]

Check each item from the start until you find 7:

| Index | Value | Is it 7? |
| --- | --- | --- |
| 0 | 4 | no |
| 1 | 2 | no |
| 2 | 7 | yes — found |

7 is found at **index 2**, after 3 comparisons. A linear search would work here even though the list is not sorted.
:::

::: example Binary search
Use a binary search to find 23 in this sorted list: 2, 5, 8, 11, 17, 23, 30 (indexes 0 to 6). [4]

Each step checks the middle item, where `mid = (low + high) DIV 2`, then throws away half the list:

| low | high | mid | value at mid | 23 vs value |
| --- | --- | --- | --- | --- |
| 0 | 6 | 3 | 11 | 23 > 11, search the right half |
| 4 | 6 | 5 | 23 | found |

23 is found at **index 5** in just **2 checks**. A linear search could have taken up to 7. Binary search is faster, but it only works because the list is sorted.
:::

::: example Bubble sort
Sort 5, 3, 8, 1 into order using bubble sort, showing each pass. [4]

Pass 1 compares each adjacent pair left to right: compare 5 and 3, swap to get 3, 5, 8, 1; compare 5 and 8, leave; compare 8 and 1, swap to get 3, 5, 1, 8. The largest value, 8, has bubbled to the end.

The list after each full pass:

| After pass | List | Swaps made? |
| --- | --- | --- |
| 1 | 3, 5, 1, 8 | yes |
| 2 | 3, 1, 5, 8 | yes |
| 3 | 1, 3, 5, 8 | yes |
| 4 | 1, 3, 5, 8 | no — sorted |

Pass 4 makes no swaps, so the algorithm stops: the list is sorted.
:::

::: example Insertion sort
Sort 5, 2, 4, 1 using insertion sort, showing each step. [4]

Start with the first item as a sorted section of one, then insert each next item into its correct place:

| Step | Item inserted | Sorted section | Whole list |
| --- | --- | --- | --- |
| Start | — | 5 | 5, 2, 4, 1 |
| 1 | 2 | 2, 5 | 2, 5, 4, 1 |
| 2 | 4 | 2, 4, 5 | 2, 4, 5, 1 |
| 3 | 1 | 1, 2, 4, 5 | 1, 2, 4, 5 |

Each item is placed in order among the items already sorted, growing the sorted section by one each time until the whole list is done.
:::

::: example Merge sort
Sort 6, 3, 8, 1 using merge sort, showing the split and the merge. [4]

First keep splitting until every piece is a single item, then merge the pieces back in order:

| Stage | Lists |
| --- | --- |
| Split once | 6, 3  and  8, 1 |
| Split again | 6  and  3  and  8  and  1 |
| Merge pairs | 3, 6  and  1, 8 |
| Merge final | 1, 3, 6, 8 |

To merge 3, 6 with 1, 8: compare the front items 3 and 1, take 1; compare 3 and 8, take 3; compare 6 and 8, take 6; then 8 is left, so take 8. The result is 1, 3, 6, 8.
:::

::: q
Why does a binary search only work on a sorted list?
---
Because it decides which half to keep by assuming everything to the left of an item is smaller and everything to the right is larger. If the list is not sorted that assumption is false, so it would throw away the half that contains the target.
:::

::: q
Do one pass of bubble sort on 4, 1, 3, 2 and give the list after that pass.
---
Compare 4 and 1, swap to 1, 4, 3, 2; compare 4 and 3, swap to 1, 3, 4, 2; compare 4 and 2, swap to 1, 3, 2, 4. After pass 1 the list is 1, 3, 2, 4.
:::

::: q
An algorithm repeatedly splits a list into halves down to single items, then merges them back in order. Which algorithm is it?
---
Merge sort — it divides the list down to single items and then merges the pieces back together in order.
:::

::: q
When would a linear search be a sensible choice even though binary search is faster?
---
When the list is short, or when it is unsorted and not worth sorting first, since linear search works on any list without needing it to be sorted.
:::

::: q
In a binary search of a sorted list of 7 items, which item is checked first?
---
The middle item, at index 3 (`(0 + 6) DIV 2 = 3`). Binary search always starts by checking the middle.
:::

::: q
Give one advantage and one disadvantage of merge sort compared with bubble sort.
---
Advantage: merge sort is much more efficient (faster) on large lists. Disadvantage: it uses more memory, because it has to hold all the split-up pieces while merging.
:::

::: q
Describe how insertion sort builds up a sorted list.
---
It keeps a sorted section at the front, starting with the first item. It takes each following item in turn and inserts it into its correct place within that sorted section, so the sorted part grows by one item each time until the whole list is sorted.
:::

::: q
How does a bubble sort know it can stop?
---
When it completes a whole pass without making any swaps. No swaps means every adjacent pair is already in order, so the list is sorted.
:::

::: watch
- **Binary search needs sorted data — say so.** State the list must be sorted, and that each step checks the middle and discards half.
- **Show every pass of a sort, not just the final list.** The marks are in the passes, so write the list after each one.
- Bubble sort works on **adjacent pairs**; do not jump items — compare 1st with 2nd, 2nd with 3rd, and so on.
- Merge sort is **split down to single items, then merge back in order** — describe both halves, not just "it sorts it".
- Insertion sort **inserts into the already-sorted front section**; it is not the same as bubble sort's swapping of neighbours.
- Comparisons: binary is faster but needs sorting first; merge is efficient but uses more memory; bubble is simple but slow; insertion is strong on nearly-sorted lists.
:::
