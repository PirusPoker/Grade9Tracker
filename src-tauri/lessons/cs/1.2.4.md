## What it is

Everything a computer stores — numbers, text, images and sound — is held as **binary**: patterns of `0`s and `1`s (**bits**). 8 bits make a **byte**; 4 bits make a **nibble**. This topic is about the codes that turn each kind of data into binary, and the sums the exam asks you to do with them.

**Binary numbers.** With 8 bits you can represent $2^8 = 256$ different values — the denary numbers $0$ to $255$. Each column has a **place value**, doubling from right to left: `128 64 32 16 8 4 2 1`. Add the place values above the `1`s to read a binary number; find which place values sum to your target to write one.

**Hexadecimal** (hex) is **base 16**. Its digits run $0$–$9$ then $A$–$F$, where $A = 10$ up to $F = 15$. One hex digit is exactly one **nibble** (4 bits), so **two hex digits = one byte**. Hex is used because it is far shorter and less error-prone for humans than long binary strings — it appears in colour codes (e.g. `#FF00AA`), memory addresses and MAC addresses. Conversion is easy precisely because $16 = 2^4$.

**Characters.** A **character set** maps every character to a unique binary code. **ASCII** uses **7 bits**, giving $2^7 = 128$ characters — enough for English letters, digits and punctuation. **Unicode** uses more bits per character, giving over a million codes, so it covers almost every writing system plus emoji. Codes are **contiguous and ordered**: `'A'` is $65$, `'B'` is $66$; `'a'` is $97$; `'0'` is $48$. So `'A'` to `'Z'` run $65$–$90$ with no gaps — which lets you work out one code from another.

**Images.** A **bitmap** image is a grid of **pixels**, each storing one colour as a binary value. **Colour depth** is the number of **bits per pixel**: $n$ bits give $2^n$ colours (1 bit → 2 colours, 8 bits → 256, 24 bits → over 16 million). **Resolution** is the number of pixels, often given as width × height or as pixels per inch — more pixels means more detail. File size in bits $\approx$ **width × height × colour depth**. **Metadata** is "data about the data" stored in the file — width, height, colour depth, resolution, date and file format — so the computer knows how to display it.

**Sound.** Sound is an **analogue** wave. To store it digitally the computer **samples** it: it measures the wave's height at regular intervals and records each measurement as a binary number. **Sample rate** is the number of samples per second, measured in **hertz (Hz)**. **Bit depth** is the number of bits used per sample. File size in bits $\approx$ **sample rate × bit depth × duration** (× number of channels). A higher sample rate or bit depth gives a more accurate recording — better quality — but a bigger file.

::: terms
- **Denary**: the base-10 number system that people normally use.
- **Binary**: the base-2 number system, using only the digits 0 and 1.
- **Hexadecimal**: the base-16 number system, using 0–9 and A–F; one hex digit represents 4 bits.
- **Overflow error**: when the result of a calculation needs more bits than are available to store it.
- **Binary shift**: moving all the bits of a binary number left (multiplying by 2 for each place) or right (dividing by 2 for each place).
- **Most significant bit (MSB)**: the leftmost bit, with the highest place value.
- **Character set**: a defined list of characters recognised by a computer, each with a unique binary code.
- **ASCII**: a character set using 7 bits, giving 128 characters — English letters, digits, punctuation and control codes.
- **Unicode**: a character set using more bits per character (up to 32), so it can represent characters from almost every language and emoji.
- **Pixel**: a single point of colour in a bitmap image.
- **Colour depth**: the number of bits used to store the colour of each pixel.
- **Resolution**: the number of pixels in an image, usually given as width × height.
- **Metadata**: data about a file stored with it — for an image, its width, height and colour depth, and often the date and camera used.
- **Sample**: a measurement of the amplitude of a sound wave at one moment, stored as a binary number.
- **Sample rate**: the number of samples taken per second, measured in hertz (Hz).
- **Bit depth**: the number of bits used to store each sample.
- **Duration**: the length of the sound recording, in seconds.
:::

::: method
1. **Denary → binary:** write the place values `128 64 32 16 8 4 2 1`. Going left to right, if a place value fits into what is left of your number, write `1` and subtract it; otherwise write `0`. The bits you write are the answer.
2. **Binary → denary:** add up the place values that sit above a `1`.
3. **Add two 8-bit numbers:** add column by column from the right, carrying a `1` to the next column whenever a column totals `2` (`10`) or `3` (`11`). If a `1` is carried *out of the leftmost (8th) column*, that is **overflow** — the true answer is too big for 8 bits and the stored result is wrong.
4. **Binary → hex:** split the 8 bits into two nibbles of 4. Convert each nibble to one hex digit ($0$–$15 \to 0$–$F$), then write them side by side.
5. **Hex → binary:** replace each hex digit with its 4-bit nibble, then join them.
6. **Denary → hex:** either convert to binary first and group into nibbles, or divide by $16$ — the quotient is the first digit, the remainder the second.
7. **Binary shift:** to shift left by $n$, move every bit $n$ places left, fill the right with `0`s, and **discard** the bits pushed off the left end; to shift right by $n$, move every bit $n$ places right and discard the bits pushed off the right end. A left shift of $n$ multiplies by $2^n$; a right shift of $n$ divides by $2^n$. Bits pushed off the end are **lost**.
:::

::: example Denary to 8-bit binary [2]
Convert the denary number $210$ to 8-bit binary. [2]

Place values: `128 64 32 16 8 4 2 1`.
$210 - 128 = 82$, so the $128$ column is `1`.
$82 - 64 = 18$, so the $64$ column is `1`.
$32$ does not fit into $18$ → `0`.
$18 - 16 = 2$, so the $16$ column is `1`.
$8$ → `0`, $4$ → `0`.
$2 - 2 = 0$, so the $2$ column is `1`; the $1$ column is `0`.
Answer: $210 = 11010010_2$.
:::

::: example Adding 8-bit binary with overflow [4]
Add $10011011_2$ and $11010110_2$ as 8-bit numbers, and state whether overflow occurs. [4]

Add column by column from the right, carrying when a total is `2` or `3`:
| | binary | denary |
| --- | --- | --- |
| | `1001 1011` | 155 |
| + | `1101 0110` | 214 |
| = | `0111 0001` | 113 (a `1` is carried out of the byte) |
Column by column: $1{+}0{=}1$; $1{+}1{=}10$ (write `0`, carry `1`); the carries ripple left; the leftmost column gives $1{+}1{=}10$, writing `0` and **carrying a `1` out of the byte**.
Answer: the 8-bit result is $01110001_2$, and **overflow has occurred** — a carry has come out of the most-significant bit and cannot be stored, so the true answer $369$ is lost.
:::

::: example Hex to binary and denary [3]
Convert $0\text{x}D6$ to 8-bit binary and to denary. [3]

Split the hex into its two digits: `D` and `6`.
$D = 13 = 1101_2$; $6 = 0110_2$.
Join the nibbles: $0\text{x}D6 = 1101\,0110_2 = 11010110_2$.
For denary: $D \times 16 + 6 = 13 \times 16 + 6 = 208 + 6 = 214$.
Answer: $0\text{x}D6 = 11010110_2 = 214$.
:::

::: example Binary shifts, both directions [4]
(a) Left-shift $00010110_2$ by 2 places. (b) Right-shift $11011000_2$ by 3 places. State the effect of each. [4]

(a) $00010110_2 = 22$. Move every bit 2 places left, fill the right with `0`s; the two leftmost bits are pushed off and lost:
$00010110 \to 01011000_2 = 88$. Effect: multiplied by $2^2 = 4$, since $22 \times 4 = 88$.
(b) $11011000_2 = 216$. Move every bit 3 places right, fill the left with `0`s; the three rightmost bits are pushed off and lost:
$11011000 \to 00011011_2 = 27$. Effect: divided by $2^3 = 8$, since $216 \div 8 = 27$.
:::

::: example Image file size [4]
A bitmap is $200$ pixels wide, $150$ pixels high, with a colour depth of $24$ bits. Calculate its size in kilobytes ($1$ KB $= 1000$ bytes). [4]

File size (bits) $=$ width $\times$ height $\times$ colour depth.
$= 200 \times 150 \times 24 = 720000$ bits.
Convert to bytes: $720000 \div 8 = 90000$ bytes.
Convert to kilobytes: $90000 \div 1000 = 90$ KB.
Answer: $90$ KB. (A $24$-bit colour depth stores $2^{24} \approx 16.7$ million colours per pixel.)
:::

::: example Sound file size [4]
A mono clip is sampled at $8000$ Hz with a bit depth of $8$ bits for $5$ seconds. Calculate the file size in kilobytes. [4]

File size (bits) $=$ sample rate $\times$ bit depth $\times$ duration.
$= 8000 \times 8 \times 5 = 320000$ bits.
Convert to bytes: $320000 \div 8 = 40000$ bytes.
Convert to kilobytes: $40000 \div 1000 = 40$ KB.
Answer: $40$ KB. Doubling either the sample rate or the bit depth would double the file size.
:::

::: example Denary to hexadecimal [2]
Convert the denary number 183 to hexadecimal. [2]

Divide by 16: 183 ÷ 16 = 11 remainder 7 (1).

11 is B in hexadecimal, so 183 = B7 (1). Check: 11 × 16 + 7 = 176 + 7 = 183.
:::

::: example Binary to hexadecimal [2]
Convert the 8-bit binary number 10111001 to hexadecimal. [2]

Split into two nibbles: 1011 and 1001 (1).

1011 = 8 + 2 + 1 = 11 = B; 1001 = 8 + 1 = 9, so the answer is B9 (1).
:::

::: example ASCII and Unicode [3]
Explain why Unicode is used instead of ASCII for a messaging app used around the world. [3]

ASCII uses 7 bits per character, so it can represent only 128 characters — enough for English but not for other alphabets (1).

A worldwide app must show Arabic, Chinese, Hindi and emoji, which need thousands of different codes (1).

Unicode uses more bits per character (up to 32), so it has over a million codes and can represent characters from almost every language — at the cost of each character taking more storage (1).
:::

::: example Bits needed for a character set [2]
A character set must represent 90 different characters. State the minimum number of bits needed for each character, and explain why. [2]

7 bits (1). 6 bits give 2 × 2 × 2 × 2 × 2 × 2 = 64 codes, which is too few; 7 bits give 128 codes, enough for 90 characters (1).
:::

::: example Resolution, colour depth and file size [3]
A photographer changes a camera setting from 12 megapixels to 24 megapixels, keeping the same colour depth. Explain the effect on the images. [3]

The resolution doubles — there are twice as many pixels in each image (1).

So the image is more detailed and can be enlarged or cropped further before it looks blocky (1).

Each pixel still needs the same number of bits, so twice the pixels means the file size roughly doubles, and the memory card holds about half as many photos (1).
:::

::: example Sample rate and bit depth [4]
A music app offers "standard" audio (22,050 Hz, 16-bit) and "high quality" audio (44,100 Hz, 24-bit). Explain why high quality sounds better and why it uses more data. [4]

The higher sample rate takes twice as many samples per second, so the digital wave follows the original sound wave more closely (1).

The higher bit depth gives more possible values for each sample, so each sample records the amplitude more precisely (1).

Both make the playback closer to the original sound (1), but more samples, each with more bits, means more bits per second — so the file is bigger and streaming uses more data (1).
:::

::: example Metadata [2]
Explain why an image file must store metadata as well as the pixel data. [2]

The pixel data is only a long string of binary colour values (1); the computer needs metadata such as the width, height and colour depth to know how many bits make up each pixel and where each row ends, so it can display the image correctly (1).
:::

---

::: q
The binary number $00000111$ is right-shifted by one place. Give the result and explain what is lost.
---
$00000111_2 = 7$ becomes $00000011_2 = 3$. The `1` pushed off the right-hand end is lost, so the halving is rounded down — the remainder disappears and you get $3$, not $3.5$.
:::

::: q
Explain why a left shift by 3 places multiplies an 8-bit number by 8.
---
Each place value is worth twice the one to its right, so moving every bit one place left doubles the value; shifting by 3 places doubles it three times, i.e. $\times 2^3 = \times 8$.
:::

::: q
In ASCII the code for `'A'` is $65$. State the code for `'H'` and explain how you know.
---
`'H'` is $72$: character codes are contiguous, and `H` is 7 letters after `A`, so $65 + 7 = 72$.
:::

::: q
ASCII uses 7 bits per character. Explain why it cannot represent every character in Chinese, and what solves this.
---
7 bits give only $2^7 = 128$ codes — far too few for thousands of Chinese characters. Unicode uses more bits per character, giving over a million codes, so it can represent them all.
:::

::: q
A stereo (2-channel) sound is sampled at $44100$ Hz, at $16$-bit depth, for $10$ seconds. Give the file size in bits.
---
$44100 \times 16 \times 10 \times 2 = 14112000$ bits (about $1.76$ MB).
:::

::: watch
- **Say what happens to the bits pushed off the end of a shift — they are lost.** "Left shift multiplies, right shift divides" only earns full marks if you add that the discarded bits are gone (so a right shift loses any remainder).
- **Overflow is a carry *out of the leftmost bit* that cannot be stored** — not just "a big number". Name it and show the carry.
- **Two hex digits = one byte; one hex digit = one nibble (4 bits).** Convert through nibbles, never by guessing.
- **Colour depth is bits *per pixel*, and $n$ bits give $2^n$ colours** — a common slip is to say "$n$ colours".
- **OCR uses $1$ KB $= 1000$ bytes.** Divide bits by 8 for bytes, then by 1000 (not 1024) for KB, or the file-size marks are lost.
- **Higher sample rate / bit depth / resolution → better quality *and* a bigger file.** State both halves of the trade-off.
:::
