## What it is

Every defence in this topic counters **particular** threats, and the exam rewards you for **matching the right defence to the right attack**. A mismatched pair — a firewall "against phishing", say — scores nothing. Learn each method as *what it is*, *how it works* and *which threat from 1.4.1 it stops*.

**Penetration testing** — deliberately **attacking your own system, or hiring ethical hackers to do so, in order to find weaknesses before real attackers do**, then reporting them to be fixed. There are two kinds:
- **White-box** testing: the tester is given **inside knowledge** of the system, simulating a **malicious insider**.
- **Black-box** testing: the tester has **no prior knowledge**, simulating an **external attacker**.

**Anti-malware software (antivirus)** — **scans files and the system for malware**, comparing them against a database of known malware **signatures**, then **quarantines or removes** anything malicious and blocks suspicious downloads. It **must be kept up to date** or it will not recognise new threats. *Counters:* viruses, worms, trojans, spyware, ransomware.

**Firewall** — hardware or software that **monitors and controls the traffic entering and leaving a network**, checking each packet against a set of rules and **blocking unauthorised connections** between the network and the internet. It acts as a barrier. *Counters:* unauthorised access and hacking; helps limit some malware and DoS traffic.

**User access levels (permissions)** — giving each user **only the access they need** to data and functions, so, for example, a teacher can edit grades but a student cannot. This **limits the damage a single account can do** and protects sensitive data. *Counters:* insider misuse and unauthorised access to confidential data.

**Strong passwords** — long passwords mixing **upper and lower case letters, numbers and symbols**, not reused and changed regularly, usually backed by **locking the account after several failed attempts**. This makes password guessing far harder. *Counters:* brute-force and guessing attacks.

**Encryption** — **scrambling data into ciphertext with a key** so that if it is **intercepted or stolen it cannot be read** without the key. It does not stop the data being taken, but it makes it **useless** to the attacker. *Counters:* data interception and theft.

**Physical security** — protecting the **hardware itself**: locked server rooms, keypad, keycard or **biometric** door locks, CCTV, and locking devices to desks. *Counters:* theft of equipment and physical tampering with servers.

**Matching the defence to the threat** — the summary you should be able to reproduce:
- Malware → **anti-malware** (kept updated)
- Unauthorised network access / hacking → **firewall**
- Insider misuse of data → **user access levels**
- Brute-force attack → **strong passwords + account lockout**
- Data interception and theft → **encryption**
- Theft of hardware → **physical security**
- Unknown weaknesses → **penetration testing** (finds them first)
- **Phishing / social engineering → user education and training** (no software defence stops a user being tricked)

::: method
**Answering a "how would you protect this system?" question** — the approach that earns every mark:
1. **Identify the specific threat** named in the scenario — is it malware, brute force, interception, physical theft, or social engineering?
2. **Name the defence that directly counters that threat** using the matching list above.
3. **Explain how that defence stops that threat** — the mechanism, not just what it is (e.g. "a firewall blocks unauthorised incoming connections", not merely "a firewall protects the network").
4. If the scenario contains **several** threats, give **one matched defence for each**, and do not repeat the same measure for every problem.

The examiner is checking the *link* between attack and defence. A correct-sounding measure aimed at the wrong threat scores nothing.
:::

::: example Penetration testing [4]
Explain what penetration testing is and why an organisation would use it. [4]

Penetration testing is when an organisation deliberately attacks its own system, often using ethical hackers, to find security weaknesses. The testers probe for vulnerabilities such as weak passwords or unpatched software and then report what they find. The organisation uses it so that these weaknesses can be discovered and fixed before a real attacker finds and exploits them, improving security proactively.
:::

::: example How a firewall protects a network [3]
Explain how a firewall helps protect a network. [3]

A firewall monitors all the traffic entering and leaving the network and checks each data packet against a set of rules. Any traffic that does not meet the rules, such as an unauthorised connection attempt from the internet, is blocked. This prevents attackers from gaining unauthorised access to the devices on the network.
:::

::: example Why encryption still helps [3]
A company sends confidential data across a network and is worried about interception. Explain how encryption protects the data, even though it cannot prevent interception. [3]

Encryption scrambles the data into ciphertext using a key before it is sent. If an attacker intercepts the data as it travels, they receive only the scrambled ciphertext, which cannot be understood without the key. So although encryption does not stop the data being intercepted, it makes the stolen data useless to the attacker.
:::

::: example Protecting a school network [6]
A school is worried about three things: pupils installing malware, attackers guessing staff passwords, and laptops being stolen from classrooms. Recommend and justify a security measure for each. [6]

To counter malware, the school should install anti-malware software and keep it updated, so it scans for and removes known viruses, worms and trojans before they spread. To counter password guessing, staff should use strong passwords combined with locking an account after several failed attempts, which makes an automated brute-force attack impractical. To counter theft, physical security such as locking laptops to desks and keeping rooms secured with keycard locks stops the hardware being removed. Each measure is matched to a specific threat.
:::

::: q
What is the purpose of penetration testing?
---
To deliberately attack a system to find its security weaknesses so they can be fixed before a real attacker exploits them.
:::

::: q
State the difference between white-box and black-box penetration testing.
---
In white-box testing the tester has inside knowledge of the system (simulating an insider); in black-box testing they have none (simulating an external attacker).
:::

::: q
Why must anti-malware software be kept up to date?
---
So its database of malware signatures includes newly created threats; an out-of-date scanner will fail to recognise and remove new malware.
:::

::: q
How do user access levels reduce risk?
---
They give each user only the access they need, limiting what a single account can see or change and so limiting the damage from insider misuse or a compromised account.
:::

::: q
Which threat do strong passwords and account lockouts defend against, and how?
---
Brute-force attacks: long complex passwords give far more combinations to try, and locking the account after several failed attempts stops the automated guessing.
:::

::: q
Give two examples of physical security and the threat they address.
---
Locking devices to desks and using keycard or biometric locks on server rooms; they address theft of hardware and physical tampering.
:::

::: q
Which defence counters phishing, and why is it not a firewall?
---
User education and training, because phishing tricks a person rather than attacking the network, so a firewall filtering traffic cannot stop a user being deceived.
:::

::: watch
- **Match the defence to the attack.** A firewall does nothing against phishing; **user training** does. Mismatched pairs score nothing.
- **Anti-malware must be kept up to date** — an out-of-date signature database misses new malware.
- **Encryption does not prevent interception or theft** — it makes the stolen data unreadable. Say this precisely.
- **Penetration testing finds and reports weaknesses; it does not fix them** — the organisation acts on the report.
- A **firewall filters network traffic** to block unauthorised access; it is **not** an antivirus and does not remove malware already on a machine.
- **Strong passwords counter brute force** — pair them with **account lockout** for the full explanation.
:::
