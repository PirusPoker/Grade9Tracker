## What it is

An **IDE (Integrated Development Environment)** is a single application that brings together all the tools a programmer needs to **write, run, test and debug** a program in one place, instead of using a separate program for each job. Examples include IDLE, Thonny, PyCharm, Visual Studio and VS Code.

The tools OCR expects you to know:

- **Editor (source-code editor)** — where you type and change the code. It helps you with features such as **syntax highlighting** (colouring keywords, strings and comments so the structure is clear and mistakes stand out), **auto-complete / auto-suggest** (offering to finish names as you type, which is faster and avoids spelling errors), **automatic indentation** and **line numbering**.
- **Error diagnostics / debugger** — tools that help you **find and fix errors**. The IDE reports **syntax errors** with a message pointing to the line, and a **debugger** lets you set **breakpoints** (pause the program at a chosen line to inspect it), **step** through the code one line at a time to watch what happens, and **watch variables** to see their current values — which is how you track down **logic errors**.
- **Run-time environment** — lets you **run the program from inside the IDE** to test it, without needing separate software set up, and shows the **output** and any **run-time errors** as it executes.
- **Translator** — a **compiler or interpreter** built into the IDE, so the code can be turned into machine code and run directly without leaving the environment.

Together these mean a programmer can write, run and fix code in one window, catching mistakes early and testing changes instantly.

::: method
**Answering "explain how [an IDE tool] helps the programmer"** — three steps every time:
1. **Name** the tool or feature — syntax highlighting, breakpoint, auto-complete, run-time environment.
2. **Say what it does** — the action it performs.
3. **State the benefit to the programmer** — this is where the mark is: it *saves time*, *catches an error earlier*, *makes a bug easier to find*, or *reduces typing mistakes*. A name with no benefit does not score an "explain" mark.
:::

::: example Two editor features
State two features of an IDE's editor and explain how each helps the programmer. [4]

**Syntax highlighting** colours keywords, strings and comments differently, which makes the structure of the code clear and helps the programmer spot a mistyped keyword or an unclosed string quickly. **Auto-complete** offers to finish the names of variables and commands as they are typed, which speeds up writing the code and reduces the spelling mistakes that would otherwise cause errors.
:::

::: example Breakpoints and stepping
Explain how breakpoints and stepping help a programmer find a logic error. [3]

A breakpoint pauses the program at a chosen line, so the programmer can inspect the values of the variables at that exact point. Stepping then runs the program one line at a time from there, so they can watch how those values change and see precisely where the output first becomes wrong. This pinpoints the line causing the logic error, which a plain error message would not reveal because the program still runs.
:::

::: example The run-time environment
Explain the purpose of the run-time environment in an IDE. [2]

It lets the programmer run and execute their program from within the IDE to test it, without needing to set up separate software, and it displays the program's output and any run-time errors as it runs.
:::

::: example How syntax highlighting helps
Describe how syntax highlighting helps a programmer write correct code. [2]

It displays different parts of the code — keywords, strings and comments — in different colours, so the structure is easy to read at a glance. A keyword that is mistyped, or a string with a missing quotation mark, shows up in the wrong colour, letting the programmer catch the mistake as they type rather than when the program fails.
:::

::: example Error diagnostics
Explain how the error diagnostics in an IDE help a programmer fix a syntax error. [2]

When the code will not run, the IDE reports the syntax error with a message and points to the line where it was detected, so the programmer knows what kind of mistake it is and where to look. This lets them correct it far more quickly than searching through the whole program by hand.
:::

What do the letters IDE stand for, and what is an IDE?
---
Integrated Development Environment; a single application containing all the tools needed to write, run, test and debug programs.
:::

Name four tools you would expect to find in an IDE.
---
Any four of: editor, error diagnostics or debugger, run-time environment, and a translator (compiler or interpreter).
:::

What does auto-complete do, and how does it help the programmer?
---
It offers to finish the names of variables and commands as they are typed, which speeds up writing code and reduces spelling mistakes.
:::

What is a breakpoint used for?
---
To pause the program at a chosen line so the programmer can inspect the values of variables at that point while debugging.
:::

::: q
How does stepping through code help find a bug?
---
It runs the program one line at a time so the programmer can watch how the variables change and see exactly where the output first goes wrong.

---
To convert the source code into machine code, using a built-in compiler or interpreter, so it can be run directly from the IDE.

Why is stating only the name of a feature not enough to earn an "explain how it helps" mark?
---
Because the mark is for the benefit to the programmer — such as saving time or catching an error earlier — not just for naming what the feature is.

Syntax highlighting, automatic indentation or line numbering — any one is acceptable.

The IDE combines the editor, translator, run-time environment and debugging tools in one place, so they can write, run and fix code without switching between separate programs.
:::

::: watch
- **Say what the tool does *for the programmer*, not just its name.** "It has syntax highlighting" is not enough — "syntax highlighting colours the code so a mistyped keyword stands out as you type" earns the mark.
- **Know the four tools:** editor, error diagnostics/debugger, run-time environment and translator — and one benefit of each.
- **Breakpoint versus stepping:** a breakpoint *pauses* execution at a line; stepping *runs one line at a time* from there. They work together to find logic errors.
- **Syntax highlighting and error diagnostics catch different things from breakpoints.** Highlighting and diagnostics flag **syntax** errors as you write; breakpoints and stepping help you hunt **logic** errors that only show at run time.
- **An IDE does not write the program for you.** It makes writing, running and debugging faster and easier — keep your answer about *helping* the programmer.
:::
