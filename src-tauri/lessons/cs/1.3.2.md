## What it is

Once devices are connected, they need to agree *how* to talk. This topic covers the physical connection, keeping data private, how devices are addressed, and the rules — **protocols** — that make communication work.

**Wired versus wireless connections**:
- **Wired (Ethernet)** — devices joined by physical cables (copper or fibre). Faster, higher bandwidth, more reliable and more secure (you must physically plug in), with little interference — but it is **not portable**, cabling is costly to install, and you are limited by cable length.
- **Wireless** — devices connect using **radio waves**, so they are portable and cheap to add, but connections are slower, less reliable, more prone to interference from walls and distance, and **less secure** because signals are broadcast through the air where they can be intercepted. Two common technologies:
  - **Wi-Fi** — connects devices to a LAN or the internet through a wireless access point; medium-to-long range with reasonably high bandwidth.
  - **Bluetooth** — a short-range (about 10 m), low-power, low-bandwidth link **directly between two devices**, such as a phone and wireless headphones.

**Encryption** — because wireless data travels through the air, anyone in range can **intercept** it. Encryption **scrambles the data into ciphertext using a key**, so that even if it is intercepted it **cannot be understood** without the matching key; only the intended recipient can **decrypt** it back to readable plaintext. This is why Wi-Fi uses encryption and why secure websites use HTTPS. The point to make in the exam: encryption does not stop interception — it makes intercepted data **useless** to the attacker.

**IP address versus MAC address** — both identify a device, but in different ways:
- An **IP address (Internet Protocol address)** is a **logical** address assigned to a device **when it joins a network**. It identifies where the device is so data can be **routed** to it, and it **can change** — you get a different one on a different network. **IPv4** is four numbers 0–255 (e.g. 192.168.1.4); **IPv6** is longer and written in hexadecimal, giving far more addresses.
- A **MAC address (Media Access Control address)** is a **physical** address **permanently burned into the NIC** by the manufacturer. It is a 48-bit number shown as twelve hexadecimal digits (e.g. 00:1A:2B:3C:4D:5E), it is **unique** and **never changes**, and it is used to identify a device on the **local** network — switches use it to deliver each frame.
- In short: **IP is logical and can change and routes data across networks; MAC is physical, fixed to the hardware, and used within the local network.**

**Standards** — a **standard** is an **agreed set of rules that lets hardware and software from different manufacturers work together**. Wi-Fi (IEEE 802.11), Ethernet, ASCII and HTML are all standards. Without them a device from one maker could not reliably communicate with another's.

**Protocols** — a **protocol is a set of rules that governs how devices communicate**: how data is formatted, addressed, transmitted and acknowledged. Learn one line for each:
- **TCP/IP** — the suite that underpins the internet. **TCP (Transmission Control Protocol)** splits data into packets, checks they all arrive and reassembles them in order; **IP (Internet Protocol)** handles addressing and **routes** each packet to the right destination.
- **HTTP (Hypertext Transfer Protocol)** — requests and transfers **web pages** from a web server to a browser.
- **HTTPS (HTTP Secure)** — HTTP **with encryption** added, so data sent between browser and server (logins, banking) is protected.
- **FTP (File Transfer Protocol)** — **transfers files** (uploads/downloads) between computers over a network.
- **POP (Post Office Protocol)** — **retrieves email**, **downloading** it to one device and usually **deleting it from the server**.
- **IMAP (Internet Message Access Protocol)** — retrieves email but **keeps it stored on the server**, so it stays in sync across all your devices.
- **SMTP (Simple Mail Transfer Protocol)** — **sends** email and passes it between mail servers.

A quick anchor: **SMTP sends; POP and IMAP receive.**

**Layers** — related protocols are grouped into **layers**, each with one job. The **TCP/IP model has four layers**:
1. **Application layer** — where the software's protocols run (HTTP, HTTPS, FTP, SMTP, IMAP); it turns user data into a form ready to send and back again.
2. **Transport layer** — TCP splits the data into packets, numbers them for reassembly and adds error checking to make the delivery reliable.
3. **Internet (network) layer** — IP adds the source and destination **IP addresses** and routes the packets across networks; **routers** work here.
4. **Link (network access) layer** — the physical hardware, cabling and NIC that put the bits onto the wire or radio, using **MAC addresses** on the local network.

**Why layering is used**: it **breaks a hugely complex task into smaller self-contained parts**, so each layer can be designed and understood on its own; a layer can be **changed or upgraded without rewriting the others** (swap the cabling without touching HTTP); it lets **different manufacturers build compatible products** for each layer (standards); and it makes faults **easier to find and fix** by isolating them to one layer.

::: method
**Sending data down the four TCP/IP layers** — what happens to a web request as it leaves your computer:
1. **Application layer:** your browser creates the request using **HTTP** (or HTTPS if encrypted).
2. **Transport layer:** **TCP** splits the data into numbered **packets** and adds error-checking information so they can be reassembled correctly.
3. **Internet layer:** **IP** adds the **source and destination IP addresses** to each packet and works out the route.
4. **Link layer:** the **NIC** puts the packets onto the physical medium (cable or radio), addressed by **MAC address** to the next device.
5. At the receiving computer the packets travel **back up** the same four layers in reverse, where they are reassembled and handed to its application.

To score, put each protocol in its layer: **HTTP at application, TCP at transport, IP at internet, MAC/NIC at the link layer.**
:::

::: example Wired or wireless [4]
Give two advantages of a wired connection and two of a wireless connection. [4]

A wired connection is faster and more reliable because data travels along a dedicated cable with little interference, and it is more secure because an attacker would have to physically plug into the network. A wireless connection is portable, letting devices move around and connect from anywhere in range, and it is cheaper and easier to set up because no cabling has to be installed.
:::

::: example Why encrypt a wireless network [3]
Explain why data sent over a wireless network is encrypted. [3]

Wireless signals are broadcast through the air, so anyone within range can intercept them. Encryption scrambles the data into ciphertext using a key, so that even if it is intercepted it cannot be understood. Only the intended recipient, who holds the correct key, can decrypt it back into readable data, keeping the information confidential.
:::

::: example IP and MAC addresses [4]
State two differences between an IP address and a MAC address. [4]

An IP address is a logical address assigned to a device when it joins a network and it can change when the device connects to a different network. A MAC address is a physical address permanently assigned to the device's NIC by the manufacturer and it never changes. IP addresses are used to route data across networks, whereas MAC addresses identify devices on the local network.
:::

::: example Choosing an email protocol [4]
A user wants their email to appear identically on their phone and their laptop, staying in sync. Name the protocol they should use to receive mail and the one used to send it, and justify the receiving choice. [4]

To receive mail they should use IMAP, because IMAP keeps the messages stored on the mail server rather than downloading and deleting them, so both devices see the same synchronised mailbox. POP would download the mail to one device and remove it from the server, breaking the sync. To send mail, SMTP is used, as it transfers outgoing email between mail servers.
:::

::: example Why layer the protocols [3]
Explain two benefits of organising network protocols into layers. [3]

Layering breaks a complex communication task into smaller, self-contained parts, so each layer can be designed and understood on its own. It also means one layer can be changed or upgraded without affecting the others — for example the physical cabling can be replaced without altering how HTTP works — and it makes errors easier to locate because a fault can be isolated to a single layer.
:::

::: watch
- A **MAC address is fixed to the hardware; an IP address can change** with the network. Swapping these round is the classic dropped mark.
- **POP deletes mail from the server; IMAP keeps it there** — the single most confused pair. Learn which is which.
- **HTTPS is just HTTP plus encryption**, not an unrelated protocol.
- **SMTP sends, POP/IMAP receive** — do not use SMTP for collecting mail.
- Put each **protocol in its layer**: HTTP (application), TCP (transport), IP (internet), MAC/NIC (link).
- Encryption **does not prevent interception** — it makes the intercepted data unreadable without the key.
:::
