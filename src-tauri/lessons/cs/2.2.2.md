## What it is

Every value a program handles has a **data type** — what kind of thing it is and what you are allowed to do with it. J277 uses five:

- **Integer** — a whole number, positive or negative: 7, -3, 0.
- **Real** (also called float) — a number with a decimal point: 3.14, -0.5, 2.0.
- **Boolean** — one of only two values: `true` or `false`.
- **Character** — a single symbol in quotes: "A", "7", "?".
- **String** — a sequence of characters: "hello", "Grade 9", or "" (the empty string).

Choosing the **right type** matters. A house number you never do sums on can be a string; a price you add up must be a real; a "has the user paid?" flag is a Boolean. The type also fixes how much memory a value needs and which operations make sense — you can add two integers, but "adding" two Booleans is meaningless.

**Casting** (or type conversion) changes a value from one type to another. The Reference Language uses:
- `int(x)` — convert to an integer.
- `float(x)` — convert to a real.
- `str(x)` — convert to a string.
- `bool(x)` — convert to a Boolean (for example `bool(0)` is `false`).

You cast because data does not always arrive as the type you need. The single most important rule in this topic: **`input(...)` always returns a string.** If a user types 25, the program receives the string "25", not the number 25. Do arithmetic on it and you get a wrong answer or an error, so you must cast it first with `int(...)` or `float(...)`. Going the other way, to join a number onto text with `+` you first convert the number with `str(...)`.

::: method
Work out and fix the data type:
1. **Name the type** of each value — integer, real, Boolean, character or string.
2. Remember that **`input(...)` gives you a string**, whatever the user typed.
3. Decide the type the **operation** needs — adding and comparing size need a number; a true/false test needs a Boolean.
4. **Cast** the value to that type: `int(...)` for a whole number, `float(...)` for a decimal, `bool(...)` for true/false.
5. To **join a number to text** with `+` for output, convert it back with `str(...)`.
6. Check the cast is **safe** — `int("12.5")` or `int("cat")` has no sensible whole number and will fail, so validate first.
:::

::: example Why input must be cast
This looks right but is wrong.

1. `age = input("Enter your age: ")`
2. `print(age + 1)`

`input` returns a **string**, so `age` holds "16", not 16, and "16" + 1 tries to add a number to text — an error. Cast on the way in:

1. `age = int(input("Enter your age: "))`
2. `print(age + 1)`

Now `age` holds the integer 16 and the program prints 17.
:::

::: example Casting to a real for a calculation
Split a bill equally between friends.

1. `total = float(input("Enter the bill: "))`
2. `people = int(input("How many people? "))`
3. `each = total / people`
4. `print("Each pays " + str(each))`

The bill can have pennies, so it is cast with `float(...)`; the number of people is whole, so `int(...)`. The final value is converted with `str(...)` to join it onto the message.
:::

::: example Using str() to build output
A score is joined onto a message.

1. `score = 42`
2. `print("You scored " + str(score) + " points")`

`score` is an integer. To join it to the strings around it with `+`, it must first be converted with `str(...)`. Without the cast the program cannot add a number to a string and stops with an error.
:::

::: example Choosing the right data type
Pick the best data type for each value. [4]

- A phone number such as "07700..." — **string**, because it can start with 0 and is never calculated with.
- A temperature of 36.6 — **real**, because it has a decimal part.
- The number of pupils in a class — **integer**, a whole count.
- Whether a box is ticked — **Boolean**, either true or false.

Choosing the wrong type, such as an integer for a phone number, would drop the leading zero.
:::

::: example Working with a Boolean flag
A game tracks whether the player is still alive with a Boolean.

1. `alive = true`
2. `lives = int(input("How many lives? "))`
3. `if lives == 0 then`
4. `    alive = false`
5. `endif`
6. `print("Player alive: " + str(alive))`

`alive` holds only `true` or `false`, so it is a **Boolean** — perfect for a yes/no flag. `str(alive)` converts it to text so it can be printed.
:::

::: q
What data type does `input(...)` always return?
---
A string, whatever the user actually typed.
:::

::: q
Give the five data types used in J277.
---
Integer, real (float), Boolean, character and string.
:::

::: q
Why must the result of `input(...)` be cast before you do arithmetic on it?
---
Because it is a string, and arithmetic on a string gives a wrong result or an error; it must first be converted to a number with `int(...)` or `float(...)`.
:::

::: q
What is the difference between an integer and a real?
---
An integer is a whole number; a real has a decimal (fractional) part, such as 3.14.
:::

::: q
Which cast turns the number 42 into text so it can be joined to a string?
---
`str(42)`, which produces the string "42".
:::

::: q
Why is a phone number best stored as a string rather than an integer?
---
A phone number can begin with 0 and is never used in calculations; storing it as an integer would drop the leading zero.
:::

::: q
What type has only two possible values, and what are they?
---
A Boolean, which is either true or false.
:::

::: q
A character and a string both use quotes — what is the difference?
---
A character is exactly one symbol, such as "A"; a string is any sequence of characters, such as "Apple" or the empty string "".
:::

::: watch
- **`input(...)` always returns a string.** Forgetting to cast it before arithmetic is the classic Paper 2 error — convert with `int(...)` or `float(...)` first.
- To **join a number to text** with `+`, wrap the number in `str(...)`, or the program errors.
- **Integer or real?** Whole numbers are integers; anything with a decimal point is a real, even 2.0.
- Choose a type from **what you do with the value**, not how it looks — a phone number is a string because you never calculate with it.
- `int("12.5")` and `int("cat")` have no whole-number value and will fail — validate before you cast.
- A Boolean holds only **true or false** — use it for flags rather than the words "true" and "false" as text.
:::
