## What it is

Computers can only store and process data in **binary** — patterns of **1s and 0s**. This is because a computer is built from millions of tiny electronic **switches (transistors)** that each have only **two states**: on or off, high or low voltage. Those two states are written as **1** and **0**, so **every kind of data — numbers, text, images, sound and instructions — must be converted into binary** before the computer can work with it.

**The units of storage**, smallest to largest:
- **Bit** — a single binary digit, **0 or 1**. The smallest unit of data.
- **Nibble** — **4 bits**.
- **Byte** — **8 bits**. The basic unit; a single character is often stored in one byte.
- **Kilobyte (KB)** — **1,000 bytes**.
- **Megabyte (MB)** — **1,000 KB**.
- **Gigabyte (GB)** — **1,000 MB**.
- **Terabyte (TB)** — **1,000 GB**.
- **Petabyte (PB)** — **1,000 TB**.

**OCR uses 1,000, not 1,024.** Each step up the ladder — KB, MB, GB, TB, PB — multiplies by **1,000**. So a terabyte is $1000 \times 1000 \times 1000 \times 1000 = 10^{12}$ bytes. Do **not** use 1,024: on this specification that makes every capacity calculation wrong.

**Two relationships are fixed** (and are **not** 1,000): **8 bits = 1 byte** and **4 bits = 1 nibble**. The times-1,000 rule applies only to the kilo/mega/giga prefixes.

**Converting between units**
- To go **up** a unit (e.g. bytes to KB), **divide by 1,000**.
- To go **down** a unit (e.g. KB to bytes), **multiply by 1,000**.

**Calculating a file size** — a reliable routine:
1. Work out the size in **bits** first (figures such as colour depth and sound bit depth are given in bits).
2. **Divide by 8** to convert bits to **bytes**.
3. **Divide by 1,000** for each step up to KB, MB and so on.

Useful file-size formulas:
- **Text:** number of characters times bits per character (bits).
- **Image:** width times height times colour depth (bits), where colour depth is the number of bits per pixel.
- **Sound:** sample rate times duration times bit depth (bits).

**Capacity a set of files needs**
- **Total needed** = size of one file times the number of files.
- **How many files fit** = capacity divided by file size.
- Always **convert everything to the same unit first**, then divide.

::: terms
- **Bit**: a single binary digit, 0 or 1 — the smallest unit of data.
- **Nibble**: a group of 4 bits — half a byte.
- **Byte**: a group of 8 bits, enough to store one ASCII character.
- **Kilobyte (KB)**: a unit of 1,000 bytes.
- **Megabyte (MB)**: a unit of 1,000 kilobytes.
- **Gigabyte (GB)**: a unit of 1,000 megabytes.
- **Terabyte (TB)**: a unit of 1,000 gigabytes.
- **Petabyte (PB)**: a unit of 1,000 terabytes.
- **Binary**: a number system using only 0 and 1, which computers use because their circuits have two states, on and off.
:::

::: method
Working with units and capacity:
1. **Learn the ladder:** bit, nibble (4 bits), byte (8 bits), KB, MB, GB, TB, PB, each **prefix times 1,000** on OCR.
2. **For a file size,** find the total in **bits** first, then **divide by 8** to get bytes.
3. **Convert up** by dividing by 1,000 per step (divide by 1,000 for KB, by 1,000,000 for MB).
4. **"How many fit"** = capacity divided by file size, in the **same unit**.
5. **Show every line of working with its unit** — the method marks are there even if the final number slips. Use **1,000**, never 1,024.
:::

::: example Ordering the units
Put these units in order from smallest to largest: megabyte, bit, gigabyte, byte, kilobyte. [1]

bit, byte, kilobyte, megabyte, gigabyte.
:::

::: example A text file
A text file stores 2,000 characters, each using 1 byte. Give its size in bytes and in kilobytes. [2]

Size in bytes = 2,000 times 1 = 2,000 bytes. Converting up one unit, 2,000 divided by 1,000 = 2 KB.
:::

::: example An image file
An image is 200 pixels wide and 150 pixels high with a colour depth of 4 bits per pixel. Calculate its size in bytes. [3]

Size in bits = 200 times 150 times 4 = 120,000 bits. Converting to bytes, 120,000 divided by 8 = 15,000 bytes.
:::

::: example How many photos fit
A memory card has 2 GB of free space. Each photo is 4 MB. How many photos can it hold? [2]

Convert to the same unit: 2 GB = 2 times 1,000 = 2,000 MB. Number of photos = 2,000 divided by 4 = 500 photos.
:::

::: example Why binary
Explain why data must be converted into binary before a computer can process it. [2]

A computer is built from electronic switches that can only be in one of two states, on or off. These two states are represented as 1 and 0, so all data must be in binary for the computer to store and process it using those switches.
:::

::: q
Convert 5,000,000 bytes into megabytes.
---
5 MB (5,000,000 divided by 1,000, then by 1,000).
:::

::: q
A file is 250 KB. How many copies fit in 1 MB of space on OCR?
---
4 copies (1,000 divided by 250).
:::

::: q
An image has 8,000 pixels at a colour depth of 8 bits. What is its size in bytes?
---
8,000 times 8 = 64,000 bits; divided by 8 = 8,000 bytes.
:::

::: q
To convert from bytes up to kilobytes, do you multiply or divide, and by what?
---
Divide by 1,000.
:::

::: watch
- **OCR: 1 KB = 1,000 bytes**, and each step up the ladder is times 1,000. Using **1,024** makes the calculation wrong.
- But **8 bits = 1 byte** and **4 bits = 1 nibble** are fixed — **never** apply the 1,000 rule to bits.
- For a file size, convert to **bits first, then divide by 8** for bytes — figures like colour depth are given in bits.
- **Keep units consistent** before dividing for "how many fit"; convert to a common unit first.
- **Show each line of working with its unit** — method marks survive a slip in the final number.
- Going **up** a unit means **divide**; going **down** means **multiply**. Swapping these inverts the answer.
:::
