## What it is

**Computational thinking** is the way you think about a problem so that a computer — or a person following exact steps — can solve it. OCR splits it into three named techniques, and the exam expects you to name the right one and give an example.

- **Abstraction** — removing or hiding the detail that does not matter, so you can focus on what does. You keep the information the solution actually needs and throw the rest away.
- **Decomposition** — breaking one big, hard problem into smaller sub-problems that are each easier to understand and solve on their own.
- **Algorithmic thinking** — working out the clear, ordered sequence of steps (an algorithm) that solves the problem, including any decisions and repetition.

A quick way to hold them apart: **abstraction takes detail away**, **decomposition breaks the problem up**, and **algorithmic thinking puts the steps in order**.

**Abstraction** — a London Underground map is the classic example. It keeps what a traveller needs (which line, the order of the stations, where to change) and removes what they do not (real distances, the street layout, the bends in the track). When you write a program to model a car you might represent it with just a `speed` and a `position` and ignore its colour — colour is detail the simulation does not need.

**Decomposition** — you do not solve "make a quiz game" in one go. You split it: store the questions, ask a question, check the answer, keep the score, show the result. Each sub-problem is small enough to solve, and you can test each one on its own.

**Algorithmic thinking** — once a sub-problem is small, you work out the exact steps: what inputs you need, what to do with them, which decisions to make (`if` the answer is right...), what to repeat, and what to output.

::: method
Applying computational thinking to a problem:
1. **Decompose** the problem — break it into smaller sub-problems, and if any are still too big, break those down too.
2. Use **abstraction** on each sub-problem — decide which details actually matter, remove the rest, and choose how to represent the important information (what data or variables you need).
3. Use **algorithmic thinking** — write the ordered steps for each sub-problem: its inputs, the processing, any decisions and repetition, and its output.
4. Combine the sub-solutions into one algorithm that solves the whole problem.

In the exam, **name the technique and give a concrete example** — a bare one-word answer rarely earns full marks.
:::

::: example Abstraction: the Tube map
Explain what is meant by abstraction, using a map as an example. [3]

Abstraction means removing the details that are not needed so you can concentrate on the ones that are. A Tube map is an abstraction of the real rail network: it keeps the useful information — the lines, the order of the stations and where you can change — but removes detail such as the true distance between stations and the exact path of the track. This makes the map far easier to use for planning a journey, even though it is not geographically accurate.
:::

::: example Decomposition: a quiz game
Show how decomposition could be used to plan a simple quiz game. [4]

Break the whole problem into smaller sub-problems that can each be written and tested on their own:

| Sub-problem | What it does |
| --- | --- |
| Store questions | Hold each question with its correct answer |
| Ask a question | Show a question and read the player's answer |
| Check the answer | Compare the answer with the correct one |
| Keep the score | Add one each time the player is right |
| Show the result | Print the final score at the end |

Each part is now small enough to solve by itself, and together they solve the whole problem.
:::

::: example Abstraction or decomposition?
A student is writing a weather app. They (a) split it into "get the data", "work out the forecast" and "draw the screen", and (b) decide to store only temperature and rainfall, ignoring wind direction. Name the technique used in each. [2]

(a) is **decomposition** — the big problem has been broken into smaller sub-problems. (b) is **abstraction** — unnecessary detail (wind direction) has been removed so only the data that matters is kept. This is exactly the pair the exam likes to test: splitting the problem up is decomposition, leaving detail out is abstraction.
:::

::: example Algorithmic thinking: largest of three
Use algorithmic thinking to write the ordered steps that output the largest of three numbers. [4]

Work out the inputs, the decisions and the output, and put them in a definite order:

1. `input a`
2. `input b`
3. `input c`
4. `largest = a`
5. `if b > largest then`
6. `  largest = b`
7. `endif`
8. `if c > largest then`
9. `  largest = c`
10. `endif`
11. `print(largest)`

Each step is simple, they run in a set order, and following them always gives the right answer — that is what makes it an algorithm.
:::

::: example Abstraction: what data to store
A program keeps a record of library books. Suggest what it should store and what it can leave out, and name the technique. [3]

This is **abstraction** — you keep only the data the program needs and ignore the rest. Store the **title**, the **author**, a unique **ISBN** and whether the book is **on loan**; leave out details that do not affect borrowing, such as the cover picture, the exact shade of the cover or how the paper smells. Choosing the few pieces of data that matter, and dropping everything else, is abstraction applied to designing a program.
:::

::: q
State what abstraction means and give one example.
---
Abstraction is removing or hiding detail that is not needed so you can focus on what matters. Example: a Tube map keeps the lines and station order but removes real distances and the street layout.
:::

::: q
State what decomposition means and why it is useful.
---
Decomposition is breaking a problem into smaller sub-problems. It is useful because each smaller part is easier to understand, solve and test on its own, and different people can work on different parts at the same time.
:::

::: q
A game is broken down into "handle input", "update the score" and "draw the graphics". Which technique is this?
---
Decomposition — the problem has been split into smaller sub-problems.
:::

::: q
To model a runner in a race a programmer stores only their speed and position, ignoring hair colour and clothing. Which technique is this, and why?
---
Abstraction — unnecessary detail (hair colour and clothing) has been removed, keeping only the data the simulation needs (speed and position).
:::

::: q
Explain what algorithmic thinking is.
---
Algorithmic thinking is working out the clear, ordered sequence of steps that solves a problem, including the inputs needed, any decisions to make and anything that repeats, so the steps can be followed to give the right result every time.
:::

::: q
Give one benefit of decomposing a large programming problem before writing any code.
---
Any of: each sub-problem is easier to solve and test; the work can be shared between people; errors are easier to find because each part is small; a part can be reused elsewhere.
:::

::: q
Why is a Tube map called an abstraction rather than a mistake, even though its distances are wrong?
---
Because the wrong distances are detail that has been left out on purpose — they do not matter for planning a journey. Abstraction keeps only the useful information (lines, station order, changes), so leaving out the true distances makes the map more useful, not incorrect.
:::

::: q
Put these in the usual order for solving a problem and say what each does: algorithmic thinking, decomposition, abstraction.
---
Decomposition first — break the problem into sub-problems; then abstraction — remove unnecessary detail and decide what data to represent; then algorithmic thinking — write the ordered steps that solve each part.
:::

::: watch
- **Do not swap abstraction and decomposition.** Abstraction *removes detail*; decomposition *splits the problem into parts*. Describing one when the question asks for the other scores nothing.
- **Always give an example.** "Abstraction removes detail" is worth little on its own — add the Tube map, or ignoring a car's colour, to earn the mark.
- Abstraction is not "getting it wrong": the removed detail is left out **on purpose** because the solution does not need it.
- Decomposition is judged on **sensible sub-problems**, not just "splitting it up" — each part should be a real, solvable piece.
- Algorithmic thinking means a **clear, ordered sequence** — steps someone (or a computer) could follow to get the right answer every time.
:::
